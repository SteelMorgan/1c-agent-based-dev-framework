> Версия: 2.1
> Дата: 2026-03-01
> Автор: akimov.dssl
> Предыдущая версия: Codex subagent/SPEC.md (v1.0, 2026-02-26)

## 1. Назначение

Система расширяет рабочий процесс Claude Code, добавляя возможность получения **независимого ревью** от альтернативных LLM через их CLI-инструменты. Каждая модель вызывается через свой CLI: GPT — через Codex CLI, Gemini — через Gemini CLI.

### 1.1. Решаемая проблема

Claude Code работает только с моделями Anthropic. При проектировании сложных решений полезно получить **«второе мнение»** от моделей с другой архитектурой и обучающими данными. Это снижает риск ошибок, привносит разные точки зрения и повышает качество архитектурных решений.

### 1.2. Ключевые принципы

- **Claude Code остаётся ведущим агентом.** Внешние CLI — вспомогательные инструменты для ревью; они не пишут и не меняют код проекта.
- **Единый контекст.** Внешний CLI запускается в корне проекта и видит те же файлы, что и Claude Code.
- **Раздельные CLI.** Каждая модель управляется своим CLI (Codex CLI для GPT, Gemini CLI для Gemini). Переключение модели — переключение CLI.
- **Изоляция.** Внешний CLI работает в режиме `read-only` (sandbox — только чтение файлов).
- **Навыки как критерии.** Claude передаёт ревьюверу ссылки на навыки фреймворка, которые тот читает самостоятельно и использует как критерии проверки.
- **Прозрачность.** Прогресс работы доступен Claude Code через мониторинг фонового процесса.

## 2. Архитектура

### 2.1. Общая схема

```
┌──────────────────────────────────────────────────────────────┐
│  Claude Code (Opus/Sonnet) — оркестратор                     │
│                                                              │
│  Пользователь: /review-gpt   или   /review-gemini           │
│         │                              │                     │
│         ▼                              ▼                     │
│  ┌──────────────────┐    ┌──────────────────────┐            │
│  │ Bash (background) │    │ Bash (background)     │           │
│  │ codex exec        │    │ codex exec            │           │
│  │ -p cx_gpt-5_3-   │    │ -p ag_gemini-3_1-     │           │
│  │    codex-high     │    │    pro-high           │           │
│  │ --sandbox         │    │ --sandbox             │           │
│  │    read-only      │    │    read-only          │           │
│  └────────┬──────────┘    └────────┬──────────────┘           │
│           │                        │                         │
│           ▼                        ▼                         │
│  stdout + файл (-o)       stdout + файл                     │
│           │                        │                         │
│           ▼                        ▼                         │
│  Claude Code читает результат → синтезирует решение          │
└──────────────────────────────────────────────────────────────┘
```

### 2.2. Поток данных

```
1. Пользователь вызывает /review-gpt (или /review-gemini, /review-all)
2. Claude Code определяет:
   a. Тип ревью (код, спецификация, архитектура, план)
   b. Артефакт для ревью (текст плана, diff, файлы)
   c. Релевантные навыки фреймворка
3. Claude Code формирует структурированный промпт
4. Claude Code запускает codex exec в фоне через Bash (run_in_background)
5. Codex CLI выполняет агентный цикл:
   - читает указанные файлы навыков (SKILL.md)
   - читает файлы проекта по необходимости
   - анализирует артефакт по критериям навыков
   - формирует отзыв
6. Claude Code мониторит прогресс через TaskOutput
7. По завершении Claude Code читает чистый результат из файла (-o)
8. Claude Code представляет отзыв пользователю
9. При наличии критических замечаний — предлагает корректировку
```

### 2.3. Параллельный запуск

```
Claude Code (Opus)
    │
    ├── Bash(run_in_background: true)
    │       └── codex exec -p cx_gpt-5_3-codex-high ...
    │
    ├── Bash(run_in_background: true)
    │       └── codex exec -p ag_gemini-3_1-pro-high ...
    │
    └── Ожидает оба результата → синтез
```

## 3. Механика вызова Codex CLI

### 3.1. Команда

```bash
codex exec \
  -p cx_gpt-5_3-codex-high \
  --sandbox read-only \
  --ephemeral \
  -o /tmp/codex-review-<timestamp>.txt \
  "<prompt>"
```

### 3.2. Параметры

| Параметр | Значение | Назначение |
|----------|----------|------------|
| `-p cx_gpt-5_3-codex-high` | Профиль | Модель + провайдер из `~/.codex/config.toml` |
| `--sandbox read-only` | Режим песочницы | Codex может читать файлы, но не записывать |
| `--ephemeral` | Без персистенции | Не сохранять сессию на диск |
| `-o <файл>` | Файл результата | Последнее сообщение агента — чистый текст без хедеров |
| `<prompt>` | Промпт | Структурированный промпт от Claude Code |

### 3.3. Конфигурация

Codex CLI настроен через bootstrap (`~/.codex/config.toml`):
- Провайдер: `9R` (9Router, OpenAI-совместимый прокси)
- Base URL: `https://ai.gbig.holdings/v1`
- API Key: `OPENAI_API_KEY` (из `~/.codex/.env`)
- Профили: предопределены для каждой доступной модели

Эталонный конфиг **не хранится** в репозитории — генерируется `.devcontainer/codex-bootstrap.sh`.

### 3.4. Получение результата

Claude Code использует **два канала**:

| Канал | Что содержит | Когда использовать |
|-------|-------------|-------------------|
| stdout (TaskOutput) | Полный лог: хедер, thinking, exec, ответ | Мониторинг прогресса (дополнительный) |
| Файл `-o` | Только финальный ответ ревьювера (чистый текст) | **Основной** способ получения результата |

**Порядок:**
1. Запустить в background → получить task_id, запомнить путь к файлу `-o`
2. Периодически проверять файл `-o` через Read → если непустой, Codex завершился
3. `TaskOutput(block=false)` → дополнительно для отображения прогресса пользователю
4. Прочитать файл `-o` → чистый результат без шума

> **Важно:** `TaskOutput` может потерять задачу (вернуть "no task found").
> В этом случае **не ждать** — сразу проверять файл `-o`. Файл `-o`
> создаётся **атомарно при завершении** процесса Codex: он не существует
> пока Codex работает, и появляется только когда процесс полностью завершён.
> Если файл существует — Codex гарантированно отработал.

## 4. Структура пользовательского промпта

### 4.1. Принцип

Claude Code формирует промпт для ревьювера из трёх обязательных блоков:
- **Задача** — что проверяем и зачем
- **Артефакт** — конкретный объект проверки
- **Навыки** — ссылки на файлы SKILL.md, которые ревьювер читает и использует как критерии

### 4.2. Шаблон промпта

```markdown
# Задача
<описание: что именно нужно проверить и в каком контексте>

# Артефакт для ревью
Тип: <план | спецификация | код | архитектура | тесты>

<содержимое артефакта:
  - для плана/спецификации: текст целиком
  - для кода: diff или список файлов с путями
  - для архитектуры: описание + ключевые файлы>

# Навыки (критерии проверки)
Прочитай следующие файлы навыков и используй их как критерии при ревью:
- framework/skills/bsl-practices/coding-standards/SKILL.md
- framework/skills/bsl-practices/error-handling/SKILL.md
- <...другие навыки, зависящие от типа ревью>

# Контекст (опционально)
- Номер задачи: <если известен>
- Затронутые объекты: <если применимо>
- Дополнительные вопросы: <если есть>
```

### 4.3. Маппинг: тип ревью → навыки

| Тип ревью | Навыки для передачи |
|-----------|---------------------|
| Код BSL | `coding-standards`, `error-handling`, `query-patterns`, `ssl-patterns`, `form-patterns` |
| Спецификация / план | `spec-standard` |
| Форма (UI) | `form-patterns`, `form-visual-requirements` |
| Архитектура | `ssl-patterns`, `query-patterns`, `coding-standards` |
| Тесты | `coding-standards`, `error-handling` |

Пути навыков относительно корня проекта:
```
framework/skills/bsl-practices/<name>/SKILL.md
framework/skills/spec-writing/<name>/SKILL.md
framework/skills/tool-usage/<name>/SKILL.md
```

Claude Code выбирает навыки исходя из типа артефакта. При необходимости можно передать несколько групп (например, ревью кода с формой — навыки кода + навыки формы).

### 4.4. Формат ответа

Формат ответа **не задаётся** явно в промпте — остаётся на усмотрение модели-ревьювера. Модель самостоятельно решает, как структурировать отзыв, исходя из прочитанных навыков и содержания артефакта.

## 5. Компоненты

### 5.1. Структура файлов

```
framework/skills/tool-usage/
└── codex-review/
    ├── SKILL.md                          — навык для Claude Code (GPT через Codex CLI)
    └── references/
        └── prompt-template.md            — шаблон промпта (§4.2)

framework/skills/tool-usage/
└── gemini-review/
    ├── SKILL.md                          — навык для Claude Code (Gemini через Gemini CLI)
    └── references/
        └── prompt-template.md            — шаблон промпта (идентичен codex-review)

.claude/commands/
├── review-gpt.md                         — slash-команда /review-gpt
├── review-gemini.md                      — slash-команда /review-gemini
└── review-all.md                         — slash-команда /review-all (параллельный запуск)

docs/
└── SPEC-codex-review.md                  — данная спецификация
```

### 5.2. Навык `codex-review` (SKILL.md)

**Назначение:** Учит Claude Code ставить задачи ревью внешним CLI-агентам, контролировать выполнение и собирать результат.

**Содержимое:**
- Триггеры: когда использовать (пользователь просит ревью, сложная архитектура, /review-*)
- Механика: как вызвать `codex exec`, какие параметры передать
- Формирование промпта: как собрать Задачу + Артефакт + Навыки
- Маппинг навыков по типу ревью
- Мониторинг и получение результата
- Обработка ошибок

### 5.3. Slash-команды

#### `/review-gpt`

1. Claude определяет тип ревью и артефакт
2. Выбирает навыки по маппингу (§4.3)
3. Формирует промпт по шаблону (§4.2)
4. Запускает `codex exec` в background
5. Мониторит прогресс, сообщает пользователю
6. Читает результат из файла `-o`
7. Представляет отзыв пользователю

#### `/review-gemini`

1. Claude определяет тип ревью и артефакт
2. Выбирает навыки по маппингу (§4.3)
3. Формирует промпт по шаблону (§4.2)
4. Записывает промпт во временный файл
5. Запускает `gemini --yolo --output-format text -m ag-pro-high -p - <` в background
6. Мониторит прогресс, сообщает пользователю
7. Читает результат из файла перенаправления
8. Представляет отзыв пользователю

#### `/review-all`

Запускает `/review-gpt` и `/review-gemini` **параллельно** (два Bash с `run_in_background: true`), затем синтезирует общий отзыв: Консенсус + уникальные замечания каждой модели.

## 7. Ограничения и риски

### 7.1. Известные ограничения

| Ограничение | Описание | Митигация |
|-------------|----------|-----------|
| Раздельные CLI | Каждая модель — отдельный CLI | Унифицированный навык скрывает различия |
| Codex не знает `.claude/rules` | Правила Claude Code недоступны Codex | Навыки фреймворка передаются через промпт |
| Таймаут | Codex может не уложиться в отведённое время | `timeout` команды; при превышении — частичный результат |
| Sandbox read-only | Codex может только читать файлы | Это намеренное ограничение для безопасности |
| Расход токенов | Дополнительный расход на второго агента | Использовать только для значимых артефактов |
| Длина промпта | Артефакт + навыки могут быть большими | Codex сам управляет контекстом при чтении файлов; передавать ссылки, а не содержимое |
| Gemini CLI | Ещё не настроен | Заглушка в /review-gemini → **реализовано в v2.1** |

### 7.2. Безопасность

- **Никогда** не передавать в промпт: пароли, API-ключи, токены, персональные данные.
- Codex CLI работает **локально** — файлы не покидают машину; только текст запросов уходит в API.
- Прокси-сервер использует **HTTPS**.
- API-ключ хранится **только** в `~/.codex/.env`, не в файлах проекта.
- Sandbox `read-only` запрещает Codex модифицировать файлы.
