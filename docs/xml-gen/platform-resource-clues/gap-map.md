## Implementation Priority

1. **PredefinedData**: existing writer/editor support makes this the shortest path from validation-only to full oracle coverage.
2. **Flowchart stub correction**: observed corpus uses `GraphicalSchema`/`xcf/scheme`, while current stub emits `Flowchart`/`8.3/flowchart`.
3. **Picture payload preservation**: high sample count and binary payload risk; start with lossless preservation, not synthesis.
4. **ExchangePlanContent**: small corpus and clear platform identifiers; add content-item DSL after reading real samples.
5. **AppearanceTemplate and Help template body**: treat as template body subdomains, independent from wrapper registration.
6. **AccumulationRegisterAggregates**: only one corpus sample; begin with read/validate/decompile before introducing write DSL.
7. **Form bodies**: largest body class; expand incrementally by feature buckets while preserving the existing wrapper registration oracle.
