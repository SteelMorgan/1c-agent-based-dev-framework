# Критический анализ референсных репозиториев

Анализ внешних источников, использованных при проектировании фреймворка 1C Agent-Based Dev. Цель — обосновать выбор практик, стандартов и архитектурных решений.

---

## 1. comol/cursor_rules_1c

**Описание:** Правила и навыки для работы с 1С в Cursor.

### Что ценно

- **ИТС best practices** — использование практик, рекомендованных на ИТС
- **Знание антипаттернов** — описание типичных ошибок и нежелательных приёмов в 1С

### Что не ценно

- **Привязка к платным MCP-серверам** — значительная часть материалов ориентирована на vibecoding1c.ru (платный сервис)
- **Заимствованный контент** — большая часть содержимого заимствована из Nikolay-Shirokov
- **Самопродвижение без доказательств** — утверждения о преимуществах собственных решений не подкреплены примерами или метриками

### Решение

**Взять:** только знания, основанные на ИТС, и общие best practices.  
**Переписать** под наш стек open-source MCP-серверов, без привязки к платным сервисам.

---

## 2. AndreevED/1c-ai-feature-dev-workflow

**Описание:** Workflow разработки фич для 1С с использованием AI.

### Что ценно

- **Структура фаз** — понятное разделение на этапы: analyze → plan → implement → review
- **Выделенная фаза review** — отдельный этап проверки перед завершением фичи
- **Идея упорядоченного процесса** — последовательность шагов вместо хаотичных изменений

### Что не ценно

- **Минимальные стандарты кодирования** — ~30 строк, недостаточно для консистентной разработки
- **Слабая документация по MCP** — мало информации о доступных инструментах и их использовании
- **Избыточный simplifier agent** — дублирует функции reviewer, усложняет пайплайн без явной выгоды

### Решение

**Взять:** концепцию фаз workflow (analyze → plan → implement → review).  
**Расширить:** значительно развить стандарты кодирования и документацию MCP.

---

## 3. rmartynenko/workflow-dev-1c-claude-code

**Описание:** Workflow разработки 1С на базе Claude Code.

### Что ценно

- **Наиболее полные BSL coding standards** — детальные правила оформления и структуры кода
- **Хорошая структура MCP-документации** — логичное описание инструментов и их применения в workflow

### Что не ценно

- **Перегруженность Memory Bank** — избыточное использование для типовых задач
- **Энтерпрайз-оверхед** — много трекеров, чеклистов, репортов, усложняющих простые сценарии
- **AI-generated boilerplate** — большое количество шаблонного текста, мало практической пользы

### Решение

**Взять:** стандарты кодирования BSL как базу. **Переписать**, а не копировать — адаптировать под наш стек и упростить.  
**Игнорировать:** Memory Bank полностью — не включать в архитектуру фреймворка.

---

## 4. Nikolay-Shirokov/cc-1c-skills

**Описание:** Skills для Claude Code при работе с 1С.

### Что ценно

- **Оригинальный JSON DSL для генерации XML** — Form.xml, EPF/ERF
- **Креативное решение проблемы метаданных 1С** — DSL как способ работы с XML-структурами без ручного редактирования
- **Практическая применимость** — упрощает генерацию и модификацию XML в 1С-проектах

### Что не ценно

- **Зависимость от Windows** — реализация на PowerShell, не работает на Linux/macOS
- **Ограниченность** — в основном EPF/ERF, нет расширения на другие типы метаданных

### Решение

**Взять:** концепцию DSL для генерации XML.  
**Сделать кросс-платформенным:** Windows — PowerShell, Linux — Python/bash.  
**Расширить:** рассмотреть применение под другие типы метаданных.

## 5. Anthropic Agentic Systems Best Practices

**Описание:** Рекомендации Anthropic по построению агентных систем.

### Что ценно

- **Evaluator-Optimizer pattern** — паттерн кросс-ревью: один агент оценивает, другой оптимизирует
- **Принцип «simplicity first»** — приоритет простоты над сложностью
- **ACI tool design** — общие принципы проектирования инструментов для AI
- **Model tiering** — разумное использование разных моделей для разных задач (дорогие — для сложных, дешёвые — для рутинных)

### Что не ценно

- Общие принципы без конкретики под 1С — требуют адаптации

### Решение

**Взять:** как основное архитектурное влияние — Evaluator-Optimizer, simplicity first, tiering моделей. Адаптировать под контекст 1С и BSL.

## Итоговые принципы фреймворка

На основе анализа источников сформулированы следующие принципы:

1. **Open-source first** — без привязки к платным MCP-сервисам.
2. **Фазовый workflow** — analyze → plan → implement → review.
3. **Строгие BSL-стандарты** — на базе rmartynenko, переработанные и упрощённые.
4. **Evaluator-Optimizer** — кросс-ревью вместо самопроверки.
5. **Simplicity first** — минимум Memory Bank, трекеров и boilerplate.
6. **Кросс-платформенный DSL** — для XML-метаданных (Windows + Linux).
