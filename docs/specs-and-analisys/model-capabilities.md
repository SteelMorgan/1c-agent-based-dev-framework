## Детальный анализ по моделям

### Economy Tier

Модели этого tier-а оптимизированы для массовых, высокочастотных операций с минимальной стоимостью за токен. Идеальны для задач, не требующих глубокого рассуждения: навигация по коду, простые правки, проверки форматирования, начальная классификация задач.

#### Grok Code Fast 1 (xAI)

**Общие сведения**

| Параметр | Значение |
|---|---|
| Провайдер | xAI |
| Дата релиза | 26 августа 2025 |
| Архитектура | Mixture-of-Experts (MoE), 314B параметров |
| Контекст | 256K токенов |
| Цена input | $0.20 / 1M токенов |
| Цена output | $1.50 / 1M токенов |
| Цена cached | $0.02 / 1M токенов |
| Скорость | ~260 tok/s output |
| Медианная задержка (TTFT) | 5.70s |

**Бенчмарки**

| Бенчмарк | Результат |
|---|---|
| SWE-bench Verified | 70.8% |
| Практические задачи (16x Engineer) | 7.64/10 |
| TypeScript type narrowing | 8/10 |

**Ключевые сильные стороны**

- Экстремально низкая стоимость входных токенов ($0.20/1M) — одна из самых дешёвых моделей на рынке
- Высокая скорость генерации (~260 tok/s), подходит для потоковой работы
- Хорошие результаты в TypeScript: 8/10 на задачах с условными и mapped типами
- Лаконичные исправления багов — генерирует компактные решения (12 строк против 50 у Opus)
- Объясняет своё reasoning при генерации кода
- Поддержка tool use и агентных workflow

**Известные ограничения**

- Слабые знания CSS (1/10 на Tailwind CSS v3 — использует устаревшие подходы на основе floats)
- Высокая verbosity: генерирует ~65M токенов при оценке (в 4× больше среднего)
- Output-ценообразование ($1.50/1M) сравнительно высокое для Economy-модели
- Проблемы с cross-browser отладкой и production-окружением
- Ограниченные данные о работе с языками за пределами TypeScript/Python
- **Нет данных о работе с 1C BSL**

**Назначение в фреймворке**

- `explorer` — навигация по кодовой базе, поиск модулей и зависимостей
- Массовый анализ файлов (парсинг, классификация)
- Генерация простых шаблонов кода
- Предварительная фильтрация задач перед передачей старшим моделям

- Быстрые правки и мелкие рефакторинги

```
│  Рефакторинг отдельных модулей │  Mid                │
│  Агентная работа с терминалом  │  Mid                │
│  Анализ больших конфигураций   │  Mid (Gemini 3 Pro) │
│  Сложная бизнес-логика         │  High               │
│  Multi-file рефакторинг        │  High               │
│  Длительная автономная работа  │  High               │
│  Архитектурные решения         │  Premium            │
│  Code review                   │  Premium            │
│  Security audit                │  Premium            │
│  Финальная валидация           │  Premium            │
└─────────────────────────────────────────────────────┘
```

### Ключевые правила маршрутизации

1. **Правило ревьюера**: Tier ревьюера >= Tier автора кода  
   - Код, написанный Economy-моделью, ревьюирует Mid+ модель  
   - Код, написанный Mid-моделью, ревьюирует High+ модель  
   - Код, написанный High-моделью, ревьюирует Premium модель  
   - Код, написанный Premium-моделью, ревьюирует другая Premium модель (cross-model review)

2. **Правило explorer-а**: Роль `explorer` (навигация, поиск, классификация) всегда выполняется моделью Economy tier  
   - Не тратить дорогие токены на задачи, не требующие глубокого reasoning  
   - Grok Code Fast 1 оптимален для массового сканирования (низкая цена input: $0.20/1M)

3. **Правило эскалации**: Если Economy/Mid модель не справляется за N попыток — автоматическая эскалация на следующий tier  
   - Рекомендуемый N = 2 для Economy, N = 3 для Mid

4. **Правило кэширования**: При повторных обращениях к одному контексту — использовать модели с поддержкой prompt caching  
   - Anthropic: до 90% экономии на cached reads  
   - OpenAI: до 90% экономии на cached input  
   - Это делает Haiku 4.5 и Sonnet 4.5 особенно выгодными при итеративной работе

5. **Правило длинного контекста**: Для задач с контекстом >200K токенов — предпочитать Gemini 3 Pro (1M контекст без удвоения цены до 200K) или GPT 5.2/5.3 (400K без ступенчатого увеличения цены)  
   - Anthropic модели удваивают цену при >200K

6. **Правило cross-provider**: Для критических ревью использовать модели разных провайдеров  
   - Пример: код написан Claude Sonnet 4.5 → ревью GPT 5.2 (или наоборот)  
   - Разные модели имеют разные «слепые пятна» — cross-review повышает качество

## Риски и ограничения

### Актуальность данных

- **Цены меняются**: Провайдеры регулярно обновляют ценообразование. Данный документ актуален на 11.02.2026 и требует обновления не реже раза в квартал
- **Модели обновляются**: Мажорные версии (Opus 4.6 → 4.7, GPT 5.2 → 5.3) могут кардинально изменить расстановку сил
- **Доступность API**: GPT 5.3 Codex на момент написания не имеет открытого API-доступа — доступен через Codex app и ChatGPT

### BSL-специфика

- **Ни одна модель не обучалась специально на 1C BSL** — производительность на BSL-задачах может существенно отличаться от бенчмарков на Python/TypeScript/Java
- Бенчмарки (SWE-bench, Terminal-Bench) ориентированы на мейнстримные языки
- Необходимо провести собственное тестирование каждой модели на типичных BSL-задачах фреймворка
- Русскоязычные идентификаторы BSL (Процедура, Функция, КонецПроцедуры) могут влиять на качество генерации

### Бенчмарки

- Бенчмарки показывают «потолок» возможностей — реальная производительность в production-окружении, как правило, ниже
- GDPval — собственный бенчмарк OpenAI, независимая верификация ограничена
- SWE-bench Pro (4 языка) объективнее SWE-bench Verified (только Python), но не включает BSL
- Различные scaffolding при тестировании затрудняют прямое сравнение

### Финансовые риски

- Premium-модели при неконтролируемом использовании могут генерировать значительные расходы  
  (пример: $20,000 за эксперимент Anthropic с 16 агентами Opus 4.6)
- Необходимы hard limits на бюджет per-task и per-session
- Кэширование и batch-processing — обязательные оптимизации для production-использования

### Технические риски

- Latency Grok Code Fast 1 (TTFT 5.70s) может быть неприемлема для интерактивных сценариев
- GPT 5.2 Pro может таймаутить на сложных задачах
- Контекстное окно >200K у Anthropic удваивает стоимость — нужна стратегия chunking
