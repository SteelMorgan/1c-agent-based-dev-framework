# LLM-Proxy: агрегация моделей и подписок для CLI-агентов

> **Disclaimer.** Документ носит исключительно информационный характер. Использование прокси-сервисов **может нарушать** условия обслуживания (ToS) отдельных провайдеров и подписок. Перед использованием любого механизма, описанного ниже, **внимательно изучите ToS** каждого задействованного сервиса. За свои действия и их последствия отвечаете только вы сами.

---

## Что такое LLM-Proxy

LLM-Proxy — это локальный (или удалённый) прокси-сервер, который встаёт между вашим CLI-инструментом (Claude Code, Codex CLI, Gemini CLI и т.д.) и API провайдеров моделей. Он принимает запросы в формате одного API (например, OpenAI-совместимом), транслирует их в формат целевого провайдера и маршрутизирует ответ обратно.

Зачем это нужно:

1. **Агрегация подписок** — несколько аккаунтов и провайдеров в одной точке входа.
2. **Управление лимитами** — контроль расхода токенов, автоматическое переключение при исчерпании квот.
3. **Доступ к «чужим» моделям** — подключение CLI, заточенного под одну модель, к другой (Claude Code → GPT, Codex CLI → Gemini и т.д.).
4. **Локальные модели** — маршрутизация к self-hosted моделям через OpenAI-совместимый эндпоинт.

## Примеры open-source решений

### CLIProxyAPI

**Репозиторий:** [github.com/router-for-me/CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)

Go-сервер, предоставляющий OpenAI-, Gemini- и Claude-совместимые эндпоинты. Ключевые возможности:

- **OAuth-аутентификация** — вместо прямого API-ключа можно авторизоваться через OAuth-токены CLI-подписок.
- **Round-robin по аккаунтам** — балансировка нагрузки между несколькими аккаунтами одного провайдера для максимизации квот.
- **Streaming и function calling** — полноценная поддержка, включая мультимодальный ввод (текст + изображения).
- **Go SDK** — ядро можно встроить в собственные приложения.

Экосистема проекта включает 15+ производных инструментов: десктопные приложения, VSCode-расширения, menubar-утилиты.

### 9Router

**Репозиторий:** [github.com/decolua/9router](https://github.com/decolua/9router)

Интеллектуальный маршрутизатор с 3-уровневой архитектурой фоллбэка:

```
Подписка → Бюджетный провайдер → Бесплатный провайдер
```

Ключевые возможности:

- **Автоматический фоллбэк** — при исчерпании квоты бесшовное переключение на резервного провайдера.
- **Трансляция форматов** — OpenAI ↔ Claude ↔ Gemini, любой инструмент с поддержкой custom endpoint получает доступ ко всем провайдерам (покрывает 95% функций, но не всё. Работа с картинками или веб-поиском кривая.. Но это же OpenSource, а мы "агентные разработчики", хе-хе).
- **Real-time мониторинг** — дашборд с расходом токенов, оценкой стоимости, лимитами по провайдерам.
- **Combo-модели** — создание собственных «комбинаций» из нескольких провайдеров под одним именем модели.
- **Гибкий деплой** — localhost, VPS, Docker, Cloudflare Workers.

Провайдеры по тирам:
| Тир | Примеры |
|-----|---------|
| Подписка | Claude Code, OpenAI Codex, Gemini CLI, GitHub Copilot |
| Бюджет | GLM-4.7, MiniMax, Kimi K2 |
| Бесплатный | iFlow, Qwen, Kiro |

Сам 9Router бесплатен — вы платите только провайдерам напрямую.

## Подключение CLI к кастомным и локальным моделям

Главный сценарий использования прокси — **направить «родной» CLI к другой модели**. Например:

- Claude Code → GPT через OpenAI-совместимый эндпоинт прокси
- Codex CLI → Gemini через трансляцию формата
- Любой CLI → **ваша локальная модель** (self-hosted GPT-120B, LLaMA и т.д.) через OpenAI-совместимый API

### Про локальные модели

Если вы развернули мощную модель у себя (дома, на работе, в кластере), прокси позволяет подключить к ней любой CLI-агент. Однако здесь важен выбор агентной оболочки:

> **Чем нативнее модель и агентная оболочка — тем лучше.** Pretrain имеет значение.

Если ваша локальная модель — это GPT-совместимая архитектура, используйте **Codex CLI**. Если Claude — **Claude Code**. «Родные» CLI-оболочки лучше согласованы с протоколами взаимодействия, tool-calling, управлением контекста и форматами ответов своей модели¹.

## Готовые бутстрапы в 1c-ai-sandbox

В репозитории [SteelMorgan/1c-ai-sandbox-client-server](https://github.com/SteelMorgan/1c-ai-sandbox-client-server) уже встроены bootstrap-скрипты для популярных CLI:

| CLI | Обёртка | Что делает бутстрап |
|-----|---------|---------------------|
| **Claude Code** | `~/bin/claude-safe.sh` | Конфигурация из `.env` + секретов, маппинг моделей (`opus`, `sonnet`, `haiku`) на бэкенды через combo-конфигурации 9Router |
| **Codex CLI** | `~/bin/codex-safe.sh` | Генерация `~/.codex/config.toml` с профилями моделей, маппинг через `codex-model-map.json` и `codex-model-overrides.json` |
| **Gemini CLI** | через маппинг Codex | Для Gemini-моделей бутстрап скачивает системные промпты из официального репозитория Codex |

**Codex CLI** в отличие от своих "коллег" поддерживает подключение любых совместимых моделей.

Конфигурация управляется через переменные окружения:
- `OPENAI_BASE_URL` — адрес прокси/роутера
- `CODEX_MODEL` — модель по умолчанию
- `CODEX_MODELS` — список доступных моделей

## Преимущества и ограничения

### Что даёт прокси

- Единая точка входа для всех подписок и провайдеров
- Гибкое управление квотами и расходами
- Автоматический фоллбэк при достижении лимитов
- Возможность использовать self-hosted модели с любым CLI
- Мониторинг и аналитика потребления

### О чём помнить

- **ToS.** Использование прокси для перенаправления подписочных CLI через сторонние эндпоинты может нарушать условия обслуживания провайдеров. Изучайте ToS перед использованием.
- **Качество.** Кросс-модельная маршрутизация (Claude Code → GPT и наоборот) работает, но **не так хорошо**, как нативная пара «CLI + своя модель». Протоколы, tool-calling, контекстные окна и системные промпты оптимизированы под конкретную модель¹.
- **Латентность.** Дополнительный hop через прокси добавляет задержку.
- **Безопасность.** Прокси обрабатывает ваши токены и запросы — используйте только доверенные решения, предпочтительно self-hosted.
