# Компактизация: как не дать агенту «поглупеть» после компакта

> Результаты исследования «Как сделать, чтобы Claude не становился идиотом после Компакта». Про устойчивость правил и навыков к компакту, разницу между харнесами Claude CLI и Codex CLI, и практические настройки фреймворка.

## 1) Почему компакт — важная веха

При работе с набором правил и навыков **Компакт** становится критической точкой: он может вытеснить из контекста уже прочитанные правила и навыки. У каждого харнеса своя специфика подготовки саммари — это **многоступенчатый процесс**, а не простая отправка всего контекста в LLM с промтом «сожми это».

Если не понимать, что именно харнес сохраняет, а что выбрасывает, легко получить агента, который после компакта «забыл» про половину своих инструментов и политик.

---

## 2) Что происходит при компакте в Claude CLI

**Правила и `CLAUDE.md`:**

- Читаются в начале сессии в кеш, затем **каждый шаг** добавляются в контекст отдельным блоком.
- `CLAUDE.md` читается рекурсивно, с подтягиванием `@`-импортированных файлов (до 5 уровней вложения).
- Два разных механизма чтения, но итог один: **правила гарантированно присутствуют** в контексте на каждом ходу.

**Навыки:**

- Харнес формирует `skill_list` из названий и описаний навыков и в начале сессии подмешивает его в контекст.
- Этот список **может быть вытеснен компактом**.
- Механизмы харнеса восстанавливают до **5 последних навыков** или до **25 000 токенов** последних навыков.
- Если навыков у агента больше — часть `skill_list` компакт не переживёт.

---

## 3) Что в Codex CLI — забавная асимметрия

- **Навыки:** дела лучше — они добавляются к саммари после компакта свежим блоком.
- **Правила:** такой сущности, как `rules` в чистом виде, Codex CLI на уровне харнеса **не поддерживает**.

Получается зеркальная проблема: для Claude надо удерживать навыки, а для Codex — наоборот, обеспечивать наличие правил в контексте модели.

---

## 4) Ключевое открытие: два вида «уровней контекста»

Стоит различать **уровни контекста харнеса** и **уровни контекста API LLM**.

И тут открывается «Америка»: и `.claude/rules`, и `skill_list` попадают в LLM API на одном и том же уровне — **USER context**. А значит **принципиальной разницы между RULES и SKILL LIST нет**.

Правила получают больший приоритет лишь по двум причинам:

1. **Формулировка.** Правила пишутся в духе MUST: *Должен / Нужно / Обязан*. У навыков «рекомендуемая» мягкая формулировка (*Use for…*).
2. **Положение.** Правила всегда в начале контекста и гарантированно переживают компакт. `skill_list` плавно смещается «к середине», может быть потерян при компактах. На длинном треке шансы применения навыка постоянно снижаются.

**А что Codex?** У него `skill_list` (его аналог) всегда присутствует в контексте на фиксированном месте — как правила у Claude. Поэтому по аналогии **в Codex все навыки работают с силой «правила»**, и дальше всё зависит только от формулировки в шапке.

---

## 5) Про «силу» инструкции на уровне API

В Claude на уровне LLM API есть только **System** и **User** (и ниже — **assistant**). Поэтому Rules и прочий пользовательский контекст имеют **одну силу**.

Фиксированное положение в начале контекста даёт преимущество, **но не бесконечное**:

- С ростом контекста «начальные инструкции» и «свежий большой хвост» начинают конкурировать за фокус.
- Вес стартового блока постепенно растворяется в массе тела контекста.

В Codex дополнительный уровень **`developer`** позволяет держать эти данные в фокусе с приоритетом **выше**, чем у роли User. Поэтому, если проводить аналогию: правила для Codex — это те же навыки, но с формулировкой «Правила».

## 6) Практика для Claude

1. **Свой «фокус» в доп. инструкцию компакта** — ближе к codex-style. ([контекст-фокус](https://t.me/gbig_dev/177))
2. **Хук, реинжектящий `skill_list` после компакта** — чтобы агент/сабагент всегда знал о наличии навыков. Для этого фреймворка это ~5 000 токенов — терпимо.
3. **«Тонкие правила»**, описывающие триггер применения навыка. Формально это дублирование заголовка навыка, **но правило имеет больший вес**: не «можешь взять, если хочешь, для такой-то ситуации», а «**Если такая ситуация — обязательно возьми**».
4. **Профиль агента в системный промт.** Главного агента можно запустить с указанием профиля, который добавляется к системному промту и усиливает вес инструкции:
   ```bash
   claude --append-system-prompt "$(cat framework/subagents/orchestrator.md)"
   ```
   Удобно зашить в алиас вызова (в [песочнице](https://github.com/SteelMorgan/1c-ai-sandbox-client-server) под алиасом `сс` уже настроено).
5. **Автокомпакт пораньше.** Субъективное предпочтение — окно 400 000 (минус фиксированные пороги сработает в районе ~367 000 токенов). Подберите своё значение.
   ```jsonc
   // .claude/settings.json
   "env": {
     "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "400000"
   }
   ```

---

## 7) Практика для Codex

Достаточно **правильно формировать навыки**:

- Основное тело — тонкое.
- При необходимости — усиленная формулировка через **Триггер** или **Условие**.
- Остальные инструкции выносить в **референс**.

---

## 8) Роль RLM

**RLM** хорош как **меж-сессионная память** без задач «ритуалов компактизации». Поэтому проект рекомендуется подключать как **внешнюю базу знаний**, но **не как замену компактам**. Подробнее — [rlm.md](rlm.md).
