# Хуки агентских CLI

Хуки — внешние shell-скрипты, которые CLI вызывает на ключевых событиях сессии. Они нужны, чтобы детерминированно блокировать опасные действия, форматировать код после правок, логировать вызовы и принудительно дополнять контекст. **Память и системный промпт хуки не заменят** — они выполняются хостом, не моделью.

Ниже — справочный список событий по двум основным CLI: Claude Code (Anthropic) и Codex CLI (OpenAI).

## Общая модель

| | Claude Code | Codex CLI |
|---|-------------|-----------|
| Где конфигурируется | `~/.claude/settings.json` (user), `<project>/.claude/settings.json` (project), `<project>/.claude/settings.local.json` (private) | `~/.codex/hooks.json` или `[hooks]` в `~/.codex/config.toml`; `<repo>/.codex/hooks.json` / `config.toml` |
| Передача данных | JSON в stdin | JSON в stdin |
| Блокировка действия | `exit 2` (stderr → модели) или JSON `{"permissionDecision":"deny"}` / `{"decision":"block"}` | `exit 2` или JSON `decision:"block"` / `permissionDecision:"deny"` / `continue:false` |
| Селектор события | `matcher` по имени tool (regex) | `matcher` regex; пусто/`*` = все события |
| Управление через TUI | команды `/hooks`, перезагрузка через `/config` | команда `/hooks` |

Спецификация и формат полезной нагрузки в каждом CLI свои — список ниже даёт **только имена событий** и роль.

## 1. События, поддерживаемые ОБОИМИ CLI

| Событие | Когда срабатывает | Может блокировать? |
|---------|-------------------|---------------------|
| `SessionStart` | Старт сессии (новая или resume). Полезно для подгрузки контекста, прогрева кэша, проверки git-статуса. | Нет (наблюдатель) |
| `UserPromptSubmit` | Сразу после ввода пользовательского промпта, до отправки модели. Можно дополнить промпт текстом или отклонить. | **Да** |
| `PreToolUse` | Перед вызовом инструмента (Bash, файловые операции, MCP-tools). Главное место для policy-проверок. | **Да** |
| `PostToolUse` | После успешного завершения инструмента. Полезно для авто-форматирования, линтеров, логирования. | Условно — побочный эффект уже произошёл; можно остановить дальнейшее (`continue:false` в Codex, exit 2 как обратная связь модели в Claude) |
| `Stop` | Главный агент закончил отвечать на текущий ход. | В Claude — может, в Codex — только форсировать продолжение |

## 2. События, поддерживаемые ТОЛЬКО Claude Code

| Событие | Когда срабатывает | Может блокировать? |
|---------|-------------------|---------------------|
| `Notification` | Claude отправляет уведомление хосту (ожидание подтверждения, idle-сигналы). | Нет |
| `SubagentStop` | Подагент (`Agent` tool, например `Explore` или специализированный) закончил работу. | Да |
| `PreCompact` | Перед автоматической компактизацией контекста при подходе к лимиту. | Да (можно отложить) |
| `SessionEnd` | Сессия завершается (выход или закрытие окна). | Нет |

> Источник: документация Claude Code, раздел Hooks.

## 3. События, поддерживаемые ТОЛЬКО Codex CLI

| Событие | Когда срабатывает | Может блокировать? |
|---------|-------------------|---------------------|
| `PermissionRequest` | Codex запрашивает эскалацию прав (выход за песочницу, сетевой доступ, повышение). Любой хук с `decision.behavior:"deny"` блокирует запрос. | **Да** |

> Codex также имеет отдельный механизм `notify` в `config.toml` — это **не хук**, а внешняя программа-наблюдатель, которой передаются события `agent-turn-complete`, `approval-requested` и т.п. Тот же набор используется `tui.notifications`. Через `notify` нельзя ничего заблокировать.

## Какие хуки для каких задач во фреймворке

| Задача | Событие | Что делать в скрипте |
|--------|---------|----------------------|
| Запретить запуск 1cv8c напрямую (всё через `v8-runner`) | `PreToolUse` (matcher: `Bash`) | grep по `tool_input.command`; `exit 2` если найден `1cv8c` без `v8-runner` |
| Авто-`v8-runner syntax` после правки `.bsl` | `PostToolUse` (matcher: `Edit\|Write`) | проверить расширение; запустить syntax-check, при ошибке — `exit 2` для обратной связи модели |
| Не давать коммит без зелёных тестов | `PreToolUse` (matcher: `Bash`) | grep `git commit`; запустить `v8-runner test yaxunit module changed`, блокировать при провале |
| Подгрузить project-context.md в каждый prompt | `UserPromptSubmit` | вернуть JSON `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}` |
| Запретить любые сетевые скачивания | `PermissionRequest` (Codex) или `PreToolUse` (Claude) | проверить намерение; deny при network |
| Логировать все Bash-вызовы агента | `PreToolUse` + `PostToolUse` | append в `.claude/audit.log` (наблюдатель) |
| Перевести скиллы при изменении `framework/` | `PostToolUse` (matcher: `Write\|Edit`) | проверить путь; `python3 tools/sync-skill.py <file>` |

## Чего хуки НЕ умеют

- Не выполняются на стороне модели — они выполняются на машине хоста между шагами агента.
- Не заменяют системный промпт и не могут «дописать поведение» агента надолго — только повлиять на конкретный шаг.
- Не получают полный контекст диалога — только полезную нагрузку события (имя tool, входные параметры, transcript_path для чтения файла стенограммы).
- Не сохраняются автоматически между машинами — это часть `settings.json`/`config.toml`, нужны git/dotfiles, чтобы шарить.
