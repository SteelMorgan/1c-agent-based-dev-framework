# Аудит знания: framework/skills/bsl-practices/ssl-patterns/ (БСП 3.1.11)

Дата аудита: 2026-07-02.
Каталог: `framework/skills/bsl-practices/ssl-patterns/` (26 файлов, 10 160 строк: SKILL.md — 373, bsp-borrowings.md — 64, 24 файла bsp-3.1.11/ — 9 723).

Контекст: БСП (Библиотека стандартных подсистем 1С, борроу из `https://github.com/brake71/1c-ssl-skills`, commit `85783eec`, версия 3.1.11) — публичная, широко документированная библиотека 1С (ИТС, синтаксис-помощник, десятки книг/курсов, миллионы инсталляций). Ключевой вопрос: насколько содержимое этих справочников уже "в весах" современных LLM (в первую очередь моделей, тренированных с существенным русскоязычным/1С корпусом), и насколько велика добавочная ценность держать эти файлы в контексте агента.

Собственная таблица авторов (`bsp-borrowings.md`) уже даёт свою оценку "веса добавочного знания" (Очень высокий / Высокий / Средний / Низкий), но с ОБРАТНОЙ семантикой: у них "Очень высокий" = модель НЕ угадывает детали без референса (т.е. высокая ценность справочника). В этом отчёте `weights_likelihood` — семантика ЗАДАННАЯ В ЗАДАНИИ: высокая = вероятно уже в весах модели (низкая доп. ценность), низкая = вряд ли в весах (высокая доп. ценность). Это обратные шкалы — при чтении сверяйте направление.

**Важно про методологию `verdict_candidate` в этом отчёте.** Два основания различны и НЕ смешиваются:

1. **Редакторская ось** (`нужен как есть` / `сжать` / `удалить-архив`) — оценивается ТОЛЬКО по плотности/повторам/многословию текста самого файла, безотносительно к тому, знает ли модель содержимое. "Сжать" означает: в файле есть пустые слова, повторяющиеся объяснения, избыточные примеры — то же самое можно сказать короче.
2. **Weights-гипотеза** (`weights_likelihood`: низкая/средняя/высокая) — отдельная, непроверенная гипотеза для ПРИОРИТИЗАЦИИ последующих проб (probe_facts) в матрице "вопрос × модель". Она НЕ является основанием ни для сжатия, ни для удаления — разные модели (Sonnet/Haiku/etc.) могут знать API БСП с разной полнотой, и решение будет приниматься по факту прогона проб, а не по этой гипотезе.

Таким образом `verdict_candidate` ниже — чисто редакторское суждение; `weights_likelihood` идёт отдельной строкой и используется только чтобы решить, какие файлы тестировать в первую очередь.
