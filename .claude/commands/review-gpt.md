Получи независимое ревью от GPT по текущему плану, спецификации, коду или архитектуре.

Используй навык `codex-review` из `framework/skills/tool-usage/codex-review/SKILL.md`.

## Шаги

1. **Определи тип ревью** — что именно нужно проверить:
   - План реализации (из PlanMode или обсуждения)
   - Спецификация (файл .md)
   - Код BSL (изменённые файлы или модуль)
   - Архитектурное решение
   - Форма (UI)
   - Тесты

2. **Собери артефакт** — содержимое или пути к файлам для проверки.

3. **Выбери навыки** по типу артефакта (см. маппинг в SKILL.md):
   - Код → `coding-standards`, `error-handling`, `query-patterns`, `ssl-patterns`, `form-patterns`
   - Спецификация → `spec-standard`
   - Форма → `form-patterns`, `form-visual-requirements`
   - Архитектура → `ssl-patterns`, `query-patterns`, `coding-standards`
   - Тесты → `coding-standards`, `error-handling`

4. **Сформируй промпт** по шаблону из `framework/skills/tool-usage/codex-review/references/prompt-template.md`:
   - Блок «Задача» — что проверяем и зачем
   - Блок «Артефакт» — содержимое или пути
   - Блок «Навыки» — пути к SKILL.md файлам

5. **Запусти Codex CLI в фоне:**

   Сначала запиши промпт во временный файл, затем запусти Codex:
   ```
   REVIEW_TS=$(date +%s)

   cat <<'EOF' > /tmp/codex-prompt-${REVIEW_TS}.txt
   <сформированный промпт>
   EOF

   codex exec \
     -p cx_gpt-5_3-codex-high \
     --sandbox read-only \
     --ephemeral \
     -o /tmp/codex-review-${REVIEW_TS}.txt \
     - < /tmp/codex-prompt-${REVIEW_TS}.txt
   ```
   Используй Bash с `run_in_background: true`.
   Запомни путь к файлу результата (`/tmp/codex-review-${REVIEW_TS}.txt`).

6. **Мониторь прогресс и собирай результат:**

   **Основной способ** — проверяй файл результата `-o` через Read:
   - Если файл не найден → Codex ещё работает, сообщай статус пользователю
   - Если файл существует → Codex завершился (файл `-o` создаётся атомарно при завершении), читай результат

   **Дополнительный способ** — `TaskOutput(block=false)` для просмотра прогресса в stdout.

   > ⚠️ TaskOutput может потерять задачу ("no task found").
   > В этом случае НЕ жди — сразу проверяй файл `-o` через Read.
   > Файл `-o` не существует пока Codex работает и появляется только при завершении.

   Сообщай пользователю статус: «GPT читает файлы...», «GPT анализирует...»

7. **Представь результат** — прочитай файл `-o` и покажи отзыв пользователю.

8. **Если есть критические замечания** — предложи скорректировать артефакт.

## Важно

- Codex работает в sandbox read-only — он НЕ меняет файлы
- Не передавай в промпт секреты, пароли, ключи API
- Передавай **пути** к навыкам, а не их содержимое — Codex прочитает файлы сам
- Всегда записывай промпт во временный файл (heredoc) — не используй `echo`
- Основной канал результата — файл `-o`, не stdout
- Отзыв GPT — это мнение, а не приказ; финальное решение за тобой и пользователем
- Формат ответа ревьювера — на его усмотрение, не навязывай структуру
