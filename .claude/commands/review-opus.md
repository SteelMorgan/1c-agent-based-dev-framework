Получи независимое ревью от второго Opus по текущему плану, спецификации, коду или архитектуре.

Используй навык `opus-review` из `framework/skills/tool-usage/opus-review/SKILL.md`.

> Ревьювер — второй инстанс Opus с изолированным контекстом. Запускается через Task tool, читает файлы проекта самостоятельно, возвращает результат синхронно.

## Шаги

1. **Определи артефакт и тип ревью**:
   - Что ревьюируем: спецификация, код, архитектура, тесты, форма?
   - Где артефакт: файлы проекта, git diff?

2. **Выбери навыки** по типу артефакта:
   - Код BSL → `coding-standards`, `error-handling`, `query-patterns`, `ssl-patterns`, `form-patterns`
   - Спецификация / план → `spec-standard`
   - Форма (UI) → `form-patterns`, `form-visual-requirements`
   - Архитектура → `ssl-patterns`, `query-patterns`, `coding-standards`
   - Тесты → `coding-standards`, `error-handling`

3. **Собери промпт** по шаблону из `framework/skills/tool-usage/opus-review/references/prompt-template.md`:
   - Блок «Роль» — задаёт режим критика (обязательно!)
   - Блок «Задача» — что проверяем и зачем
   - Блок «Артефакт» — пути к файлам (не содержимое)
   - Блок «Навыки» — пути к SKILL.md
   - Блок «Формат ответа» — BLOCK/WARN/INFO + сводка
   - Блок «Контекст» — номер задачи, вопросы (опционально)

4. **Запусти субагент** через Task tool:

```
Task(
  subagent_type: "general-purpose",
  description: "Независимое ревью <тип> через Opus",
  prompt: "<сформированный промпт>"
)
```

5. **Представь результат** пользователю:
   - Показать отзыв ревьювера
   - BLOCK-замечания — настоятельно предложить исправить
   - Отзыв — это мнение, финальное решение за пользователем

## Важно

- Субагент **изолирован** — не знает историю текущей сессии, только промпт
- Пути к файлам — относительно корня проекта
- Не передавать содержимое файлов в промпт — субагент читает сам
- Результат возвращается синхронно — мониторинг не нужен
