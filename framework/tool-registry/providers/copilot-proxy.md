# Provider: copilot-proxy

**MCP Server:** [SteelMorgan/spring-mcp-1c-copilot](https://github.com/SteelMorgan/spring-mcp-1c-copilot)
**Версия:** 1.0.0
**Категория:** AI-ассистент
**Транспорт:** SSE (Server-Sent Events) / HTTP

## Описание

Прокси-сервер к API 1С:Напарник — AI-ассистент для вопросов по 1С, best practices, объяснение синтаксиса BSL и проверка качества кода. Оборачивает API 1С:Напарник в стандартный MCP-протокол.

## Предварительные требования

- Java 17+ / Docker
- Токен авторизации для API 1С:Напарник (Bearer token)
- Сетевой доступ к API 1С:Напарник

## Реализуемые Capability

### ask_ai_assistant

**Tool:** `ask_1c_ai`

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `question` | → | `question` | Прямое соответствие. Вопрос для AI-ассистента |
| `programming_language` | → | `programming_language` | Опциональный. Язык программирования |
| `create_new_session` | → | `create_new_session` | Опциональный. По умолчанию `false` |

**Маппинг результата:**

| Поле контракта | ← | Поле ответа tool | Примечание |
|----------------|---|------------------|------------|
| `answer` | ← | text content | Ответ AI-ассистента в текстовом формате |
| `references` | ← | (не предоставляется) | Ссылки на документацию могут быть встроены в текст ответа |

**Особенности и отклонения от контракта:**

- Ответ возвращается как единый текстовый блок, ссылки на документацию встроены в текст
- Сессия сохраняется между вызовами (диалоговый режим), если `create_new_session = false`
- Качество ответа зависит от API 1С:Напарник — сервер является прокси

**Пример вызова:**

```
Tool: ask_1c_ai
Параметры: {
  "question": "Как правильно обрабатывать ошибки в серверных процедурах БСП?",
  "create_new_session": true
}
```

### search_templates

**Tool:** `ask_1c_ai` (с формулировкой запроса как поиск шаблона)

**Роль:** 🔄 fallback — используется, если нет более специализированного провайдера.

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `query` | → | `question` | Запрос оборачивается в промпт: «Покажи пример кода 1С: {query}» |

**Особенности и отклонения от контракта:**

- Capability реализуется через тот же `ask_1c_ai`, но с формулировкой запроса как поиск шаблона/примера
- Ответ — текстовый, содержит код и пояснения, но не структурирован
- Качество зависит от точности формулировки запроса

**Пример вызова:**

```
Tool: ask_1c_ai
Параметры: {
  "question": "Покажи пример кода 1С для обхода табличной части документа с проверкой заполнения реквизитов"
}
```

### search_ssl_functions

**Tool:** `ask_1c_ai` (с формулировкой запроса о БСП)

**Роль:** 🔄 fallback — основной провайдер `lsp-bridge` (через `symbol_explore`). Используется, когда LSP недоступен или нужна документация/описание функций БСП.

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `query` | → | `question` | Запрос оборачивается в промпт: «Какие функции БСП (Библиотеки стандартных подсистем) подходят для: {query}? Укажи модуль, имя функции, параметры и пример использования.» |

**Особенности и отклонения от контракта:**

- Возвращает текстовое описание, а не навигационные данные (URI, range)
- Менее точный, чем LSP-поиск — основан на знаниях AI, а не на анализе кода
- Полезен для поиска по описанию задачи, когда точное имя функции неизвестно

**Пример вызова:**

```
Tool: ask_1c_ai
Параметры: {
  "question": "Какие функции БСП подходят для отправки email? Укажи модуль, имя, параметры и пример."
}
```

## Дополнительные tool-ы (без маппинга на capability)

| Tool | Описание | Параметры |
|------|----------|-----------|
| `explain_1c_syntax` | Объяснение конструкции синтаксиса BSL — операторов, ключевых слов, директив компиляции | `syntax_element` (обязательный), `context` (опциональный) |
| `check_1c_code` | Проверка качества кода 1С — синтаксис, логика, производительность. Не заменяет `check_syntax` (не использует EDT/Designer) | `code` (обязательный), `check_type` (опциональный: `syntax`, `logic`, `performance`) |

**Примечание:** `explain_1c_syntax` и `check_1c_code` не маппятся на стандартные capability, так как:
- `explain_1c_syntax` — учебная функция, не используется в рабочем workflow
- `check_1c_code` — AI-проверка качества, дополняет, но не заменяет формальную проверку `check_syntax`

## Ограничения

- Требует токен авторизации API 1С:Напарник — без токена сервер недоступен
- Все ответы — через AI (не детерминированные), точность зависит от модели 1С:Напарник
- Не подходит для задач, требующих точных данных из кода проекта — используйте `lsp-bridge`
- Лимиты API 1С:Напарник на количество запросов
