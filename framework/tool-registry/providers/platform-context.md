# Provider: platform-context

**MCP Server:** [alkoleft/mcp-bsl-platform-context](https://github.com/alkoleft/mcp-bsl-platform-context)
**Версия:** актуальная (Kotlin, Spring AI MCP)
**Категория:** API платформы 1С
**Транспорт:** stdio

## Описание

Предоставляет доступ к справочной информации по API платформы 1С:Предприятие — поиск по типам, методам, свойствам, конструкторам. Использует интеллектуальный 4-уровневый поиск: точное → префиксное → частичное → fuzzy совпадение. Поддерживает составные запросы и русскоязычные алиасы.

## Предварительные требования

- Java 17+ (для запуска Spring Boot приложения)
- Файлы справки платформы 1С (*.hbk) — загружаются при старте

## Реализуемые Capability

### search_platform_api

**Tool:** `search`

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `query` | → | `query` | Прямое соответствие. Поддерживает русскоязычные термины, составные запросы (`"Таблица значений"` → `ТаблицаЗначений`) |
| `type` | → | `type` | `method`, `property`, `type` или `null` (все) |
| `limit` | → | `limit` | По умолчанию 10, максимум 50 |

**Маппинг результата:**

| Поле контракта | ← | Поле ответа tool | Примечание |
|----------------|---|------------------|------------|
| `results` | ← | Форматированный текст | Результат возвращается как отформатированный markdown-текст, не как структурированный JSON |
| `results[].name` | ← | Имя в результатах | Извлекается из форматированного текста |
| `results[].kind` | ← | Тип в результатах | `method` / `property` / `type` |

**Особенности и отклонения от контракта:**

- Результат возвращается как **форматированный markdown-текст**, а не структурированный JSON. LLM-агент разбирает текст самостоятельно
- Поддерживает 13 русскоязычных алиасов для интуитивного поиска (например, «функция», «тип», «свойство»)
- Кэширование через Spring Cache для повторных запросов

**Пример вызова:**

```
Tool: search
Параметры: {
  "query": "ТаблицаЗначений",
  "type": "type",
  "limit": 5
}
```

### get_type_info

Capability `get_type_info` реализуется через комбинацию из 4 tool-ов, в зависимости от параметра `detail`:

#### При `detail = overview`

**Tool:** `info`

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `type_name` | → | `name` | Точное имя элемента API |
| (неявно) | → | `type` | Всегда `"type"` для типов, `"method"` для методов, `"property"` для свойств |

**Пример вызова:**

```
Tool: info
Параметры: {
  "name": "ТаблицаЗначений",
  "type": "type"
}
```

#### При `detail = members`

**Tool:** `getMembers`

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `type_name` | → | `typeName` | Имя типа 1С |

**Пример вызова:**

```
Tool: getMembers
Параметры: {
  "typeName": "СправочникСсылка"
}
```

#### При `detail = constructors`

**Tool:** `getConstructors`

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `type_name` | → | `typeName` | Имя типа данных 1С (например, `Массив`, `Структура`, `ТаблицаЗначений`) |

**Пример вызова:**

```
Tool: getConstructors
Параметры: {
  "typeName": "ТаблицаЗначений"
}
```

#### При `detail = member`

**Tool:** `getMember`

**Маппинг параметров:**

| Параметр capability | → | Параметр tool | Примечание |
|---------------------|---|---------------|------------|
| `type_name` | → | `typeName` | Имя типа 1С |
| `member_name` | → | `memberName` | Имя конкретного метода или свойства |

**Пример вызова:**

```
Tool: getMember
Параметры: {
  "typeName": "ТаблицаЗначений",
  "memberName": "Найти"
}
```

**Особенности и отклонения от контракта:**

- Capability `get_type_info` реализуется через **4 разных tool-а** в зависимости от требуемой детализации
- Все результаты возвращаются как форматированный markdown-текст
- Для параметра `type` в `info` необходимо указать категорию элемента явно

---

## Дополнительные tool-ы (без маппинга на capability)

Нет — все 5 tool-ов маппятся на capability `search_platform_api` и `get_type_info`.

---

## Ограничения

- Требует файлы справки платформы 1С — без них данные недоступны
- Результаты в формате markdown-текста, а не структурированного JSON
- Только справочная информация по API платформы — не работает с метаданными конкретной конфигурации
