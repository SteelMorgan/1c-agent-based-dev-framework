# Role DSL

JSON DSL для генерации ролей 1С с правами доступа.

## Команда

```bash
java -jar xml-gen.jar role compile <input.json> <output.xml>
```

**Параметры:**
- `<input.json>` — JSON DSL файл
- `<output.xml>` — выходной Role.xml

## Структура DSL

### Минимальная роль

```json
{
  "name": "ПростаяРоль",
  "rights": {}
}
```

### Полная структура

```json
{
  "name": "ИмяРоли",
  "rights": {
    "Catalog.Номенклатура": ["Read", "Insert", "Update", "Delete"],
    "Document.РеализацияТоваров": ["Read", "Insert"],
    "Report.ОтчётПоПродажам": ["View"]
  }
}
```

## Права доступа (rights)

### Базовый синтаксис

```json
{
  "rights": {
    "ТипОбъекта.ИмяОбъекта": ["Право1", "Право2"]
  }
}
```

### Типы объектов

| Тип | Описание | Пример |
|-----|----------|--------|
| `Catalog` | Справочник | `Catalog.Номенклатура` |
| `Document` | Документ | `Document.РеализацияТоваров` |
| `Report` | Отчёт | `Report.ОтчётПоПродажам` |
| `DataProcessor` | Обработка | `DataProcessor.ЗагрузкаДанных` |
| `InformationRegister` | Регистр сведений | `InformationRegister.Цены` |
| `AccumulationRegister` | Регистр накопления | `AccumulationRegister.Продажи` |

### Права доступа

| Право | Описание | Применимо к |
|-------|----------|-------------|
| `Read` | Чтение | Все объекты |
| `Insert` | Добавление | Справочники, Документы |
| `Update` | Изменение | Справочники, Документы |
| `Delete` | Удаление | Справочники, Документы |
| `View` | Просмотр | Отчёты, Обработки |
| `Edit` | Редактирование | Отчёты, Обработки |
| `InteractiveInsert` | Интерактивное добавление | Справочники, Документы |
| `InteractiveDelete` | Интерактивное удаление | Справочники, Документы |
| `Posting` | Проведение | Документы |
| `UndoPosting` | Отмена проведения | Документы |

## Генерация XML

### Входной JSON

```json
{
  "name": "МенеджерПродаж",
  "rights": {
    "Catalog.Номенклатура": ["Read"],
    "Document.РеализацияТоваров": ["Read", "Insert", "Update", "Posting"]
  }
}
```

### Выходной XML

```xml
<?xml version="1.0" encoding="UTF-8"?>
<MetaDataObject xmlns="http://v8.1c.ru/8.3/MDClasses" ...>
  <Role uuid="...">
    <Properties>
      <Name>МенеджерПродаж</Name>
      <Synonym>
        <v8:item>
          <v8:lang>ru</v8:lang>
          <v8:content>Менеджер продаж</v8:content>
        </v8:item>
      </Synonym>
    </Properties>
    <Rights>
      <Right>
        <Name>Catalog.Номенклатура</Name>
        <Value>
          <Read>true</Read>
        </Value>
      </Right>
      <Right>
        <Name>Document.РеализацияТоваров</Name>
        <Value>
          <Read>true</Read>
          <Insert>true</Insert>
          <Update>true</Update>
          <Posting>true</Posting>
        </Value>
      </Right>
    </Rights>
  </Role>
</MetaDataObject>
```

## Использование в 1С

### Назначение роли пользователю

```bsl
Процедура НазначитьРоль(Пользователь, ИмяРоли)
    ПользовательИБ = ПользователиИнформационнойБазы.НайтиПоИмени(Пользователь.ИмяПользователяИБ);
    
    Если ПользовательИБ <> Неопределено Тогда
        Роли = Новый Массив;
        Для Каждого Роль Из ПользовательИБ.Роли Цикл
            Роли.Добавить(Роль);
        КонецЦикла;
        
        Роли.Добавить(Метаданные.Роли[ИмяРоли]);
        
        ПользовательИБ.Роли.Очистить();
        Для Каждого Роль Из Роли Цикл
            ПользовательИБ.Роли.Добавить(Роль);
        КонецЦикла;
        
        ПользовательИБ.Записать();
    КонецЕсли;
КонецПроцедуры
```

### Проверка прав доступа

```bsl
Функция ЕстьПравоЧтения(ИмяОбъекта)
    Возврат ПравоДоступа("Чтение", Метаданные.Справочники[ИмяОбъекта]);
КонецФункции

Функция ЕстьПравоИзменения(ИмяОбъекта)
    Возврат ПравоДоступа("Изменение", Метаданные.Справочники[ИмяОбъекта]);
КонецФункции
```

## Типичные роли

### Роль "Базовые права"

Минимальные права для работы в системе:

```json
{
  "name": "БазовыеПрава",
  "rights": {
    "Catalog.Пользователи": ["Read"],
    "InformationRegister.НастройкиПользователей": ["Read", "Update"]
  }
}
```

### Роль "Просмотр отчётов"

Только просмотр отчётов:

```json
{
  "name": "ПросмотрОтчётов",
  "rights": {
    "Report.ОтчётПоПродажам": ["View"],
    "Report.ОтчётПоЗакупкам": ["View"],
    "Report.ОстаткиТоваров": ["View"],
    "Report.ВзаиморасчётыСКонтрагентами": ["View"]
  }
}
```

### Роль "Работа с документами"

Создание и редактирование документов:

```json
{
  "name": "РаботаСДокументами",
  "rights": {

    "Catalog.Контрагенты": ["Read"],

    "Document.ПоступлениеТоваров": ["Read", "Insert", "Update", "Posting", "UndoPosting"]
  }

```

## Особенности

### Автоматическая генерация

1. **UUID** — генерируется автоматически для роли
2. **Synonym** — создаётся из имени роли
3. **Структура прав** — правильная иерархия XML

### Формат файла

- **UTF-8 с BOM** — Role.xml создаётся с UTF-8 BOM (EF BB BF)
- **Правильная структура** — соответствует формату 1С Designer

## Ограничения

### Текущие ограничения

1. **Только базовые права** — расширенные права не поддерживаются
2. **Нет RLS** — Row Level Security не поддерживается
3. **Нет ограничений по полям** — права на уровне полей не поддерживаются
4. **Нет прав на команды** — права на команды не поддерживаются

### Workaround

- **Расширенные права** — добавляй вручную в Role.xml
- **RLS** — настраивай вручную в 1С
- **Права на поля** — настраивай вручную в 1С

## Рекомендации по безопасности

### Принцип минимальных привилегий

Назначай только необходимые права:

```json
{
  "name": "Оператор",
  "rights": {
    "Document.РеализацияТоваров": ["Read", "Insert"],
    // НЕ давай Update и Delete без необходимости
    "Report.ОтчётПоПродажам": ["View"]
    // НЕ давай Edit без необходимости
  }
}
```

### Разделение ролей

Создавай отдельные роли для разных функций:

- **Чтение** — отдельная роль
- **Запись** — отдельная роль
- **Администрирование** — отдельная роль

### Тестирование прав

Всегда тестируй роли перед использованием:

1. Создай тестового пользователя
2. Назначь роль
3. Проверь доступ к объектам
4. Убедись, что нет лишних прав
