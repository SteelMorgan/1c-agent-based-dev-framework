# Поиск перед записью (Search Before Write)

## Назначение

Навык учит агента **всегда выполнять поиск перед написанием нового кода**. Это предотвращает дублирование, обеспечивает соответствие существующим паттернам проекта и максимально использует уже имеющиеся возможности конфигурации (БСП, метаданные, API платформы).

**Принцип:** Любая задача на написание кода — это прежде всего задача на поиск. Сначала ищем, потом пишем.

---

## Когда применять

| Триггер | Действие |
|---------|----------|
| Пользователь просит создать новую функцию или процедуру | Сначала поиск аналогичных реализаций через `navigate_symbol`, `search_ssl_functions` |
| Пользователь просит реализовать бизнес-логику | Поиск по метаданным (`search_metadata`) — есть ли нужные объекты |
| Пользователь использует API платформы | Поиск по API (`search_platform_api`, `get_type_info`) — корректность вызова |
| Пользователь просит написать запрос | Поиск существующих запросов в проекте (`navigate_symbol`) |
| Пользователь просит создать печатную форму | Поиск существующих печатных форм, проверка паттернов БСП |
| Любая задача на создание нового кода | Применить стратегию поиска (см. ниже) |

---

## Сценарии использования

### Сценарий 1: Создание новой функции

**Шаги:**

1. **Поиск по имени** — `navigate_symbol` (operation: `search`) с именем предполагаемой функции.
2. **Если не найдено** — `search_ssl_functions` на случай, если функция уже есть в БСП.
3. **Если в БСП нет** — `search_platform_api` для проверки встроенных возможностей платформы.
4. **Если всё ещё нет** — `ask_ai_assistant` для уточнения best practices (опционально).
5. **Только после этого** — написание кода.

**Пример:** Пользователь просит создать функцию получения остатков товаров.

```
1. navigate_symbol(query: "ПолучитьОстатки", operation: "search")
2. search_ssl_functions(query: "остатки товаров")
3. search_metadata(query: "ОстаткиТоваров")
4. search_metadata(query: "Регистр накопления остатки")
5. Если найдены регистры — проверить их модули через navigate_symbol
6. Писать код на основе найденных паттернов
```

### Сценарий 2: Реализация бизнес-логики

**Шаги:**

1. `search_metadata` — найти объекты метаданных (справочники, документы, регистры) по ключевым словам.
2. По найденным объектам — `navigate_symbol` для перехода к модулям и анализа существующего кода.
3. `search_platform_api` — если используются типы платформы (СправочникСсылка, ДокументОбъект и т.д.).
4. Писать код, опираясь на найденные паттерны.

### Сценарий 3: Создание печатной формы

**Шаги:**

1. `search_metadata` — найти существующие печатные формы в конфигурации.
2. `navigate_symbol` — найти реализации печатных форм (например, по имени «Печать» или «ПечатнаяФорма»).
3. `search_ssl_functions` — проверить API БСП для печатных форм.
4. `search_templates` — если доступен, поиск шаблонов печатных форм.
5. Реализовать по найденным образцам.

### Сценарий 4: Использование API платформы

**Шаги:**

1. `search_platform_api` — поиск по ключевым словам (например, «СтрНайти», «ТаблицаЗначений»).
2. `get_type_info` — детальная информация о типе (методы, свойства, сигнатуры).
3. Только после проверки — использование в коде.

## Стратегия поиска

| Приоритет | Инструмент | Характеристики |
|-----------|------------|----------------|
| 1 | LSP (`navigate_symbol`) | Быстро, точно, по проекту. Первый выбор. |
| 2 | `search_metadata` | Для объектов конфигурации. |
| 3 | `search_platform_api`, `get_type_info` | Для API платформы. |
| 4 | `search_ssl_functions` | Для БСП (если конфигурация содержит БСП). |
| 5 | `ask_ai_assistant` | Широкий поиск, но медленнее. Когда LSP и метаданные не дали результата. |

**Правило:** Сначала LSP — быстрый и точный. Затем AI-ассистент — для более широкого контекста и best practices.

## Связанные capability

| Capability | Категория | Назначение |
|------------|-----------|------------|
| `navigate_symbol` | Core | Поиск символов, переход к определению, поиск использований |
| `search_metadata` | Important | Поиск объектов метаданных |
| `search_platform_api` | Core | Поиск по API платформы 1С |
| `get_type_info` | Important | Детальная информация о типах платформы |
| `search_ssl_functions` | Optional | Поиск функций БСП |
| `search_templates` | Optional | Поиск шаблонов кода |
| `ask_ai_assistant` | Important | Вопросы к AI по best practices |

## Типичные ошибки и обходные пути

| Ошибка | Обходной путь |
|--------|---------------|
| Пропуск поиска и сразу написание кода | Жёсткое правило: при любой задаче на создание кода — первый шаг = поиск. |
| Поиск только по одному источнику | Использовать каскад: LSP → метаданные → API → БСП → AI. |
| `search_metadata` возвращает пусто | Проверить: конфигурация загружена? Использовать `dump_config` при необходимости. |
| `navigate_symbol` возвращает пусто | Уточнить имя (рус/лат, регистр). Использовать нечёткий поиск через `ask_ai_assistant`. |
| `search_ssl_functions` недоступен | Конфигурация без БСП — использовать `search_platform_api` и `navigate_symbol` по общим модулям. |
| Результаты поиска не релевантны | Сужение запроса: добавить контекст (тип объекта, подсистема). |
