# Накопленные практики — xml-generation

```
status: candidate
class: Неполная семантика ifAbsent у составного иерархического селектора
recipe: Для селектора с несколькими уровнями идентичности применять режим отсутствия на каждом уровне: отсутствующий родитель и отсутствующий конечный узел одинаково проходят через общий fail/noop-контракт; неоднозначность всегда остаётся ошибкой.
anti-recipe: Не объединять состояния «родитель отсутствует» и «родитель неоднозначен» одной проверкой exact-one до обработки ifAbsent.
why: Иначе noop работает только для отсутствующего листа, но падает на схеме без родителя, нарушая идемпотентность и единый контракт batch-операции.
steps: Разделить cardinality на zero/one/many; zero передать общей обработке отсутствия, one продолжить, many отклонить; покрыть strict, noop и mixed rollback.
source: Ревью атомарного XML-редактора с иерархическим selector preflight, 2026-07
```

```
status: candidate
class: Скрытый отступ перед XML declaration в byte-sensitive Java fixture
recipe: Для XML-fixture, где проверяются BOM, CRLF и точные byte spans, собирать declaration и корневой opening явными строками либо держать одинаковый incidental indent у каждой строки text block; до запуска mutation отдельно проверять parse исходного fixture и первый символ после BOM.
anti-recipe: Не смешивать в одном Java text block строки с обычным отступом исходника и строки, начинающиеся с literal tab от нулевой колонки: минимальный incidental indent станет нулевым, а пробелы перед `<?xml ...?>` сохранятся.
why: XML-парсер отклоняет declaration не в начале документа, поэтому regression падает до проверяемой операции и маскирует её фактическое поведение ложной инфраструктурной ошибкой.
steps: Декодировать fixture с учётом BOM; проверить первый символ `<`; выполнить baseline parse; затем только запускать редактор и byte-diff; для CRLF-фрагментов не применять глобальную замену LF после конкатенации уже сформированных CRLF-частей.
source: Regression атомарного lossless-редактора Designer XML, 2026-07
```

```
status: candidate
class: Ложная проверка однородности переводов строк в byte-lossless XML
recipe: Проверять CRLF только на структурных spans, которые редактор добавил или заменил, а неизменность остального документа доказывать byte-сравнением после обратной подстановки адресованного span.
anti-recipe: Не удалять CRLF глобально и не требовать отсутствия оставшегося LF во всём Designer XML: текстовые content-узлы могут канонически содержать bare LF.
why: Глобальная проверка смешивает структурные окончания строк с содержимым текстовых узлов и ложно бракует корректную lossless-операцию.
steps: Извлечь адресованный direct-узел; проверить его EOL отдельно; заменить его исходным span и сравнить весь документ byte-exact; отдельно проверить BOM и mode.
source: Regression atomic/lossless редактора смешанного Designer XML, 2026-07
```
