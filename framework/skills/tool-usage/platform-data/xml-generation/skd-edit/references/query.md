# Запрос набора данных

Операции: `set-query`, `patch-query`.

## set-query — полная замена текста запроса

Value — **полный текст запроса** или ссылка на файл `@path/to/query.sql`.

```bash
xml-gen skd edit Schema.xml set-query "ВЫБРАТЬ Ссылка, Наименование ИЗ Справочник.Номенклатура"
xml-gen skd edit Schema.xml set-query "@queries/sales.sql"
xml-gen skd edit Schema.xml set-query "@queries/sales.sql" --dataSet Продажи
```

Поведение:

- Полностью заменяет содержимое `<query>` указанного набора данных (`--dataSet`, default — первый).
- При значении вида `@path/to/file.sql` — читает текст из файла. Путь разрешается **относительно Schema.xml**, затем относительно текущей рабочей директории.
- **Не поддерживает batch** — запрос может содержать `;;` буквально, разделитель сломал бы текст.
- `<fields>`, `<dataSource>`, `<role>` и прочая обвязка набора **не меняются**. Если новый запрос возвращает другие колонки — поля нужно править отдельно (`add-field`/`modify-field`/`remove-field`).

Используй когда:

- Меняешь логику запроса целиком (переписал ВТ, поменял источник, добавил/убрал большие куски).
- Сгенерировал запрос внешним инструментом и хочешь подложить его как файл.

## patch-query — точечная замена в тексте запроса

Shorthand: `"старое => новое [@once]"`.

```bash
xml-gen skd edit Schema.xml patch-query "СубконтоДт1) В => СубконтоКт1) В"
xml-gen skd edit Schema.xml patch-query "КАК ВТ_СтароеИмя => КАК ВТ_НовоеИмя @once"
xml-gen skd edit Schema.xml patch-query "&СтарыйПарам => &НовыйПарам @once ;; &ОтЧего => &ОтПериода @once"
```

### Поведение по умолчанию

Заменяет **все вхождения** подстроки в `<query>` указанного набора (`--dataSet`).

### Флаг @once — assert «ровно одно вхождение»

С флагом `@once` операция:

1. Считает число вхождений подстроки.
2. Если **0** — ошибка «substring not found», файл не меняется.
3. Если **≥ 2** — ошибка «substring is ambiguous: N matches», файл не меняется.
4. Если **ровно 1** — заменяет, валидирует, пишет.

Используй `@once` всегда, когда:

- Меняешь идентификатор, который, по твоему предположению, уникален (имя ВТ, имя поля в SELECT, имя параметра).
- Хочешь зафиксировать инвариант для reviewer-а: «эта правка точечная, не задевает другие места».
- Боишься попасть в комментарий или однотипное имя в другой части запроса.

Без `@once` — массовая замена (например, переименование одного поля везде, где оно встречается).

### Многострочные подстроки

Поддерживаются. Переводы строк в `старое`/`новое` сравниваются **буквально**, включая отступы:

```bash
xml-gen skd edit Schema.xml patch-query "ГДЕ
    Дата >= &НачалоПериода => ГДЕ
    Дата >= &НачалоОтчетногоПериода @once"
```

При составлении многострочной подстроки убедись, что отступы в shell-аргументе совпадают с текстом запроса.

### Batch

Поддерживается через `;;`. Каждый патч применяется последовательно; ошибка в любом из них откатывает весь батч (операция атомарна на уровне файла).

## Контракт: когда что

| Ситуация | Операция |
|----------|----------|
| Запрос переписан на 80%+ | `set-query` |
| Замена 1–5 идентификаторов с известной уникальностью | `patch-query @once` (по одному на патч) |
| Массовое переименование (например, поле `Цена` → `ЦенаСУчётомСкидки` везде) | `patch-query` без `@once` |
| Большой кусок шаблона, который точно уникален | `patch-query @once` многострочный |
| Запрос лежит в `.sql`-файле и часто меняется | `set-query "@queries/...sql"` после генерации |

## Edge cases

| Случай | Поведение |
|--------|-----------|
| `patch-query "x => y"` и `x` встречается 5 раз — без `@once` | Все 5 заменены. Хорошо это или нет — ответственность вызывающего. |
| `patch-query "x => y @once"` и `x` встречается 0 раз | Error, файл не меняется. |
| `patch-query "x => y @once"` и `x` встречается 2+ раз | Error «ambiguous», файл не меняется. |
| `set-query "@queries/q.sql"`, файла нет | Error «query file not found». |
| `set-query` без `--dataSet` при нескольких наборах | Применяется к первому. Лучше указывать `--dataSet` явно. |
| Замена ломает XML well-formedness (например, добавила непарную `<`) | Error на этапе пост-валидации, файл не меняется. |

## Reviewer-инвариант

При code-review исходящих патчей запроса:

- Любой `patch-query` без `@once` должен сопровождаться обоснованием «здесь массовая замена нужна».
- В типичном случае точечной правки добавь `@once` — это дешёвая защита от ошибок на ровном месте.
- Длинные многострочные `patch-query` лучше заменить на `set-query "@queries/...sql"` с хранением запроса в файле.
