# Параметры СКД

Операции: `add-parameter`, `modify-parameter`, `remove-parameter`, `rename-parameter`, `reorder-parameters`.

## add-parameter — добавить параметр

Shorthand: `"Имя [Заголовок]: тип = значение [availableValue=список] [@флаги]"`.

```
"Период [Отчетный период]: StandardPeriod = LastMonth @autoDates"
"Организация: CatalogRef.Организации"
"ПС: CatalogRef.Контрагенты = Справочник.Контрагенты.ПустаяСсылка @hidden"
"Период: StandardPeriod = LastMonth @always"
"ПСчет: ChartOfAccountsRef.Хозрасчетный = ПланСчетов.Хозрасчетный.X @hidden @always"
"Округление: EnumRef.Округления = Окр1 availableValue=Перечисление.Округления.Окр1: руб., Перечисление.Округления.Окр1000: тыс."
```

Семантика:

- `Имя` — имя параметра. Обязательное.
- `[Заголовок]` — `<title>`. Опционально, скобки — часть синтаксиса.
- `тип` — `<valueType>`, форматы как в полях (см. [fields.md](fields.md)).
- `= значение` — `<value>`. Тип значения подбирается по объявленному типу параметра.
- `availableValue=v1[: p1], v2[: p2], …` — начальный список допустимых значений. Разделитель элементов — `,`; представление после `:`.

### Кавычки в availableValue

Если в значении или представлении встречается `,` или `:` — оборачивай в одинарные кавычки `'...'`:

```
"Округление: EnumRef.Округления = Окр1 availableValue=Окр1_00: 'руб., коп.', Окр1: руб."
```

### Флаги параметра

| Флаг | Семантика |
|------|-----------|
| `@hidden` | Параметр скрыт от пользовательских настроек. Типично — для констант запроса. |
| `@always` | Параметр всегда подставляется в запрос. Применяется отдельно или вместе с `@hidden` (для видимых обязательных параметров — типа отчётного периода). |
| `@autoDates` | Для `StandardPeriod` — генерирует пару скрытых параметров `ДатаНачала` / `ДатаОкончания`, связанных с основным периодом. |

Идемпотентность: `@hidden`/`@always` можно ставить повторно — поведение не меняется.

## modify-parameter — изменить существующий параметр

Shorthand: `"Имя [Заголовок] [ключ=значение]... [@флаги]"`. Находит параметр по имени, обновляет указанные свойства, остальные сохраняет.

```
"ПорядокОкругления use=Always"
"ПорядокОкругления [Округление сумм] denyIncompleteValues=true"
"ПериодОтчета [Отчетный период]"                                  # только title
"ПорядокОкругления availableValue=Перечисление.Округления.Окр1: руб., Перечисление.Округления.Окр1000: тыс."
"СчетПС value=ПланСчетов.Хозрасчетный.КассаПредприятия"
"Контрагент @hidden @always"
```

Доступные kv:

| KV | Семантика |
|----|-----------|
| `value=` | Заменяет `<value>` параметра (тип значения автоматически по типу параметра). |
| `availableValue=` | **Полная замена** списка допустимых значений (см. ниже). |
| `use=` | `Always` / `Auto`. |
| `denyIncompleteValues=` | `true` / `false`. |

### availableValue= в modify-parameter — destructive

`availableValue=` в `modify-parameter` **заменяет весь список** допустимых значений. Старые элементы удаляются. Это сознательное решение: список обычно меняется целиком.

Если нужно добавить одно значение к существующему списку — сначала вычитай файл, затем перечисли все элементы в новой строке `availableValue=...`.

### Только title

`modify-parameter "Имя [Новый заголовок]"` — единственная операция, обновляющая только title. Это валидно — можно вызывать без других kv-пар.

## remove-parameter — удалить параметр

Value — имя параметра.

```
"СтарыйПараметр"
"Парам1 ;; Парам2 ;; Парам3"
```

Удаляет параметр из `<parameters>`. Ссылки `&Имя` в текстах запросов и в выражениях других параметров **не чистятся** — это ответственность вызывающего (используй `patch-query @once` для зачистки запроса).

Несуществующий параметр — warning + skip.

## rename-parameter — переименовать параметр

Shorthand: `"OldName => NewName"`. Атомарная операция:

1. Меняет имя параметра в `<parameters>`.
2. Обновляет ссылки `&OldName` в выражениях значений других параметров — **только полные совпадения** (`&ПериодX` не задевается).
3. Обновляет записи в `dataParameters` всех вариантов настроек.

Текст запроса **не трогается**. Если параметр используется в запросе как `&OldName` — отдельно вызови `patch-query "&OldName => &NewName"` (опционально с `@once`).

```
"Период => ПериодОтчета"
```

Batch поддерживается, но осторожно: при цепочке `A => B ;; B => C` второй патч найдёт уже переименованный параметр.

## reorder-parameters — переставить параметры

Shorthand: `"Имя1, Имя2, Имя3"` — частичный список. Указанные параметры идут первыми в заданном порядке, остальные сохраняют исходный относительный порядок и идут в конце.

```
"ПериодОтчета, НачалоПериода, КонецПериода"
```

Параметр из списка, которого нет в схеме — warning + skip. Дубликаты в списке — ошибка. Полный список приводить не обязательно — только те, чей порядок важен.

## Edge cases

| Случай | Поведение |
|--------|-----------|
| `add-parameter` для существующего имени | Warning + skip. Используй `modify-parameter`. |
| `@autoDates` на параметре не `StandardPeriod` | Error. |
| `availableValue=` с одинарной кавычкой внутри значения | Экранируй удвоением: `''` внутри `'...'`. |
| `modify-parameter` без kv и без `[Title]` | Noop с warning. |
| `rename-parameter` целевого имени, которое уже занято | Error. |
| `value=` с типом, не совпадающим с типом параметра | Error (валидация типа значения). |
