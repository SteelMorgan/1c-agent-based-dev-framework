# `mxl info` — как читать вывод

Команда `xml-gen mxl info <Template.xml>` заменяет необходимость читать сотни строк XML. Возвращает компактную сводку: именованные области, параметры, расшифровки, наборы колонок, статический текст.

## Опции

| Опция | По умолч. | Назначение |
|-------|-----------|------------|
| `--format text\|json` | `text` | Формат вывода. `json` — для программной обработки |
| `--with-text` | off | Включить статический текст ячеек и шаблонные строки |
| `--max-params N` | 10 | Максимум параметров в списке на область |
| `--limit N` | 150 | Максимум строк вывода (защита от переполнения контекста) |
| `--offset N` | 0 | Пропустить первые N строк (пагинация при `--limit`) |

## Порядок областей

Области выводятся в порядке **позиции в документе** (по верхней строке), а не по алфавиту. Это соответствует естественному порядку вывода областей при формировании печатной формы — сверху вниз.

```
--- Named areas ---
  Заголовок          Rows         rows 1-4     (1 params)
  Поставщик          Rows         rows 5-6     (1 params)
  ШапкаТаблицы       Rows         rows 12-13   (0 params)
  Строка             Rows         rows 14-14   (8 params)
  Итого              Rows         rows 16-17   (1 params)
  ВысотаЭтикетки     Rows         rows 20-25
  ШиринаЭтикетки     Columns      cols 1-5
```

## Типы областей

| Тип | Что это | Как получать в BSL |
|-----|---------|-----|
| `Rows` | Горизонтальная область — диапазон строк (`rows N-M`). Самый частый случай — шапка, строка ТЧ, подвал | `Макет.ПолучитьОбласть("Имя")` |
| `Columns` | Вертикальная область — диапазон колонок (`cols N-M`). Используется для этикеток, ценников, где есть «ширина» как именованная сущность | `Макет.ПолучитьОбласть("Имя")` (только в паре с Rows через `\|`) |
| `Rectangle` | Прямоугольник: явные строки + колонки + собственный набор колонок (`columnsID`). Применяется в сложных макетах с переменной шириной | `Макет.ПолучитьОбласть("Имя")` |
| `Drawing` | Именованный рисунок: картинка, штрихкод, QR | Доступ через `Макет.Рисунки.Найти("Имя")` |

## Пересечения

Если в макете присутствуют одновременно области `Rows` и `Columns` (типичный паттерн — этикетки, ценники), info выводит **пары пересечений**, как их нужно запрашивать в BSL:

```
--- Intersections (use with GetArea) ---
  ВысотаЭтикетки|ШиринаЭтикетки
```

BSL:

```bsl
Этикетка = Макет.ПолучитьОбласть("ВысотаЭтикетки|ШиринаЭтикетки");
```

## Параметры по областям

```
--- Parameters by area ---
  Заголовок: ТекстЗаголовка
  Поставщик: ПредставлениеПоставщика
    detail: ПредставлениеПоставщика->Поставщик
  Строка: НомерСтроки, Товар, Количество, Цена, Сумма, ... (+3)
    detail: Товар->Номенклатура
  Итого: Всего
```

- Запись `detail: A->B` означает: ячейка с параметром `A` имеет расшифровку в параметр `B`. В BSL заполнить **оба**: `A` — то, что показывается, `B` — ссылка для проваливания.
- Если параметров больше `--max-params`, выводится `... (+N)`.

## Параметры из шаблонов (суффикс `[tpl]`)

Параметры, встроенные в шаблонный текст (`fillType=Template`, например `"Инв № [ИнвентарныйНомер]"`), помечаются суффиксом `[tpl]`:

```
  НумерацияЛистов: Номер [tpl], Дата [tpl], НомерЛиста [tpl]
```

В BSL они заполняются точно так же, как обычные параметры:

```bsl
Область.Параметры.Номер     = НомерДокумента;
Область.Параметры.Дата      = ДатаДокумента;
Область.Параметры.НомерЛиста = Лист;
```

Числовые подстановки вида `[5]`, `[6]` (используются в официальных формах как ссылки на сноски) **игнорируются** — это не параметры.

## Текстовое содержимое (`--with-text`)

Опция показывает статический текст и шаблонные строки. Полезно для понимания назначения колонок и поиска нужного параметра.

```
--- Text content ---
  ШапкаТаблицы:
    Text: "№", "Товар", "Ед. изм.", "Кол-во", "Цена", "Сумма"
  Строка:
    Templates: "Инв № [ИнвентарныйНомер]"
  Итого:
    Text: "Итого:"
```

| Метка | Что значит |
|-------|------------|
| `Text` | Статические надписи — `fillType=Text` |
| `Templates` | Текст с подстановками `[Имя]` — `fillType=Template` |

## Пагинация

При больших макетах:

```bash
xml-gen mxl info Template.xml --limit 150           # первые 150 строк
xml-gen mxl info Template.xml --offset 150 --limit 150  # следующие 150
```

## JSON-вывод

```bash
xml-gen mxl info Template.xml --format json
```

Структура:

```json
{
  "areas": [
    { "name": "Заголовок", "type": "Rows", "rows": [1, 4], "params": ["ТекстЗаголовка"] },
    { "name": "Строка", "type": "Rows", "rows": [14, 14],
      "params": ["НомерСтроки", "Товар", ...],
      "detail": { "Товар": "Номенклатура" } }
  ],
  "intersections": ["ВысотаЭтикетки|ШиринаЭтикетки"],
  "drawings": []
}
```

Используется агентами в пайплайнах reverse-engineering и при инвентаризации макетов конфигурации.

## Типовые сценарии использования

| Subagent | Зачем info |
|----------|-----------|
| `developer-code` | Перед заполнением макета в BSL — узнать имена параметров и detail |
| `debugger` | При непечатающейся форме — проверить, какие области реально есть и как они называются |
| `explorer` | Карта печатных форм по обработке (быстрый аудит) |
| `analyst` | Понимание, какие данные нужны для печати |
| `architect` | Инвентаризация шаблонов конфигурации |
