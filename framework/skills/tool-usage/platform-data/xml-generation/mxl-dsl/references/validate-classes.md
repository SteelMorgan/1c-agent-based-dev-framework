# `mxl validate` — классы ошибок

Команда `xml-gen mxl validate <Template.xml>` проверяет структурную корректность собранного макета — то, что 1С-платформа не простит при открытии.

## Опции

| Опция | По умолч. | Назначение |
|-------|-----------|------------|
| `--detailed` | off | Подробный вывод (включая успешные проверки) |
| `--max-errors N` | 20 | Остановиться после N ошибок |

## Классы ошибок

### 1. `bad-column-index`

Ячейка ссылается на индекс колонки, которого нет в макете.

**Причины:**
- `col` больше, чем `columns` в DSL
- После compile `span` уходит за правую границу макета
- В исходном XML — пропущенные `Column` в наборе колонок

**Как чинить (для compile-результата):** проверить `columns` и максимальный `col + span - 1` в DSL.

### 2. `bad-format-index`

Ячейка ссылается на формат (`<f>N</f>`), которого нет в палитре форматов макета.

**Причины:**
- Ручное редактирование XML, после которого палитра потеряла запись
- Слияние двух макетов
- В DSL: опечатка в `format` стиля (мы используем имена форматов, но в XML это индекс палитры — компилятор должен сложить палитру)

**Как чинить:** перекомпилировать из DSL — он построит палитру с нуля.

### 3. `bad-height`

Высота строки задана некорректно: отрицательная, нулевая для непустой строки, или ссылается на отсутствующий индекс высот.

**Причины:**
- В DSL: `height: 0` или `height: -5`
- В исходном XML — повреждённая палитра высот

### 4. `palette-refs` (ссылки на палитры)

Объединяет проверки целостности всех палитр макета:
- `font` → существует ли шрифт по индексу
- `border` → существует ли описание рамки
- `color` → существует ли цвет
- `style` → существует ли стиль

Каждая палитра пронумерована, ячейки ссылаются индексом. Если индекс выходит за размер палитры или указывает на пропуск — это ошибка `palette-refs`.

### 5. `area-ranges` (диапазоны именованных областей)

Именованная область задаётся диапазоном (`top..bottom` для Rows, `left..right` для Columns, `top..bottom, left..right` для Rectangle).

**Проверки:**
- `top <= bottom`, `left <= right`
- диапазон не выходит за границы макета (`bottom <= maxRow`, `right <= columns`)
- две одноимённые области не задают конфликтующие диапазоны
- Rectangle: `columnsID` существует в макете

### 6. `merge-ranges` (диапазоны объединений)

Объединённые ячейки (`<merged>`) задаются прямоугольником `top..bottom, left..right`.

**Проверки:**
- координаты валидны (см. выше)
- объединения не пересекаются
- одиночное объединение не вырождено (`1×1`)

### 7. Прочие структурные

Помимо классов выше, validate ловит:
- отсутствие обязательных атрибутов в `Cell`
- ссылки на несуществующие наборы колонок (`columnsID`)
- битые ссылки на рисунки (`Drawing` без бинарного содержимого)
- неправильный namespace XML

## Вывод

### Кратко (по умолчанию)

```
Template.xml — 3 errors
  [palette-refs]  row 14, col 9: font index 12 out of range (palette size 8)
  [bad-column-index]  area "Строка": cell col=11 exceeds columns=10
  [merge-ranges]  row 16: merge 16:8-16:11 exceeds columns=10
```

### Подробно (`--detailed`)

```
Template.xml — validating...
  [ok]  palette/fonts: 8 entries
  [ok]  palette/borders: 4 entries
  [ok]  palette/formats: 5 entries
  [err] palette-refs: row 14, col 9: font index 12 out of range
  ...
```

## Когда какой subagent зовёт validate

| Subagent | Сценарий |
|----------|----------|
| `reviewer` | Часть code review для печатных форм — обязательно после любых изменений макета |
| `tester` | Smoke-проверка перед прогоном тестов печати |
| `developer-code` | Сразу после `mxl compile` перед коммитом |
| `debugger` | При «макет не открывается» / «1С падает на ПолучитьМакет» — validate указывает на конкретные палитры |

## Типовая привязка ошибок к DSL

| Класс ошибки | Что искать в DSL |
|--------------|------------------|
| `bad-column-index` | `col`, `span`, `columns` |
| `bad-format-index` | `format` в стилях (опечатки в токенах `ЧДЦ=`/`ДФ=`) |
| `bad-height` | `height` в строках |
| `palette-refs` | имена в `font`, ссылки `style.font` |
| `area-ranges` | пересекающиеся `name`, пустые `rows` |
| `merge-ranges` | `span`/`rowspan` (выход за края, пересечения двух явных ячеек) |
