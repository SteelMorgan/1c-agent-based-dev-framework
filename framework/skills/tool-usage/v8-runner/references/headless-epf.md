# Headless-запуск внешней обработки

Запуск внешней обработки в пакетном режиме выполняется через:

```bash
v8-runner launch <thin|thick|ordinary> --execute "<путь к .epf>" --c "<sentinel>" --raw-key /DisableUnsafeActionProtection
```

Ключевой нюанс платформы: `/Execute<epf>` открывает форму обработки, но не вызывает экспортный метод модуля объекта. Обработка без формы через `/Execute` не выполнит бизнес-логику.

Канонический подход:

1. У обработки есть управляемая форма.
2. В `ПриОткрытии` форма распознаёт пакетный режим по `ПараметрЗапуска()`.
3. Форма вызывает серверный метод, который выполняет работу.
4. Серверный метод пишет внешний протокол или иной наблюдаемый результат.
5. Форма завершает сеанс через `ЗавершитьРаботуСистемы(Ложь)`.

`--raw-key /DisableUnsafeActionProtection` нужен, чтобы первое открытие внешней обработки не зависло на предупреждении безопасности.

Верификация: жди завершения процесса 1С или появления файла-протокола, затем проверяй поведение: дельту данных, протокол, ЖР. Exit code без поведенческого результата не доказывает выполнение логики.

Альтернатива без `/Execute`: из уже подключённой серверной сессии создать обработку через `ВнешниеОбработки.Создать(<путь>, Ложь)` и вызвать экспортный метод. Это требует канала выполнения кода на сервере; `/Execute` самодостаточен из CLI.
