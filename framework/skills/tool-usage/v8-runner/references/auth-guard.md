# Auth Guard — безопасный доступ к ИБ

Применяй эти правила **до** любой операции v8-runner, которая обращается к информационной базе (build, init, syntax, test, dump, launch). Одинаково применимо к файловым и серверным ИБ.

## Жёсткие стопы по лицензии

Если вывод любой команды содержит хотя бы один из паттернов ниже — немедленно останови все операции и попроси пользователя устранить проблему лицензирования в окружении. Не пытайся чинить, обходить или перезапускать:

**Русские паттерны:**
- `лиценз` (любое слово, содержащее корень)
- `Не обнаружена лицензия`
- `Лицензия не найдена`
- `программная лицензия`

**Латинские паттерны:**
- `license` / `License` / `LICENSE`
- `HASP`
- `nethasp`
- `LM` (только в контексте сообщений платформы о лицензировании)
- `License not found`
- `No license`

**Правило:** при совпадении любого паттерна — hard stop с сообщением пользователю. Не делай повторных попыток, не предлагай альтернативных credentials, не меняй параметры запуска.

## Правило двух кандидатов

Если пользователь не задал login/password явно (ни в аргументах команды, ни в `v8project.local.yaml`, ни в переменных окружения):

1. Попробуй пользователя **`Администратор`** с пустым паролем.
2. Если не подошло (ошибка авторизации, не лицензии) — попробуй **`Admin`** с пустым паролем.
3. Если не подошло — **стоп**, спроси пользователя, под каким пользователем подключаться.

Не перебирай другие имена. Не создавай пользователей. Не сбрасывай пароль.

## Трёхпутевая классификация ошибки

После попытки подключения классифицируй результат:

| Класс | Признак | Действие |
|-------|---------|----------|
| **license** | Любой паттерн из раздела «Жёсткие стопы» | Hard stop, сообщи пользователю |
| **auth** | Ошибка авторизации (неверный пользователь / пароль) | Следующий кандидат или вопрос пользователю |
| **path** | База недоступна, путь неверный, база не найдена | Стоп, сообщи конкретную ошибку, не пытайся чинить |

Не смешивай классы: ошибка пути — это не проблема credentials.

## Передача credentials

**Порядок приоритета (от высшего к низшему):**

1. Параметры CLI команды v8-runner (`--user`, `--password` или аналоги, если поддерживаются)
2. Переменные окружения (если текущая команда их поддерживает)
3. Поле `connection` в `v8project.local.yaml`

**Где хранить credentials:**

- Записывай логин/пароль **только** в `v8project.local.yaml` — файл машинно-локальный и не попадает в репозиторий.
- **Никогда** не записывай credentials в `v8project.yaml` — он версионируется в Git.
- Если всё же приходится временно добавить в `v8project.yaml`, предупреди пользователя явно и не делай это молча.

**Логи:**

- Никогда не печатай пароль в сообщениях, логах или итоговом ответе — даже частично.
- Маскируй пароль при воспроизведении команды пользователю: `--password ***`.

## Пример структуры v8project.local.yaml

```yaml
connection:
  user: Администратор
  password: ""        # пустая строка — явное указание пустого пароля
```

Для серверной ИБ аналогично: credentials в `v8project.local.yaml`, путь подключения в `v8project.yaml`.

## Что НЕ нужно делать

- Не передавай `--config v8project.local.yaml` как аргумент — файл подхватывается автоматически при наличии рядом с `v8project.yaml`.
- Не используй переменную `V8TR_CONFIG` — она не входит в нашу модель конфигурации.
- Не перезапускай неудачную операцию с теми же credentials более одного раза без смены кандидата или явного запроса пользователя.
