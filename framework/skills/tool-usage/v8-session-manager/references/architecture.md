# Архитектура слоёв

Запрос AI-агента до бизнес-логики внутри 1С проходит пять слоёв. Skill менеджера касается слоя L3; остальные — точки, в которых агент может оказаться при отладке или при разработке нового tool.

## Слои

| Слой | Имя | Где код | Ответственность |
|---|---|---|---|
| L0 | Внешняя транспортная компонент-аддин (`session_y8`) | C++/Rust addin для 1С, грузится в клиента | TCP/WS-сокет наружу: один процесс 1С ↔ один WS-канал. Подъём, переподключение, низкоуровневый кадр |
| L1 | DevKit BSL (адаптер addin ↔ BSL) | общий модуль/расширение в проекте | Обёртка над `session_y8`: чтение/запись фреймов, события, сериализация JSON-RPC |
| L2 | `client_mcp` (BSL) | расширение `exts/client_mcp/` | Реализация JSON-RPC поверх devkit: `session.register`, `tools/publish`, обработка `tools/call`, lifecycle. Не содержит доменных tools |
| L2.5 | Прикладные расширения (`test_client`, `VAExtension`, `yaxunit_runner`, …) | `exts/<extension>/` | Регистрируют MCP-tools через `client_mcp`. Здесь живёт бизнес-логика — описание форм, запуск тестов и т.п. |
| L3 | `v8-session-manager` (этот продукт) | `src/` Rust-бинарь | WS-сервер на `:4000/sessions` для клиентов; HTTP MCP на `:4001/mcp` для AI-агента; реестр сессий, FIFO, soft-reconnect, дедуп проксированных tools |
| L4 | AI-агент | Claude Code, IDE-плагин, … | Дёргает `tools/list`/`tools/call` через MCP HTTP, строит сценарии |

## Поток вызова

```
AI-агент (L4)
  └─ POST /mcp (tools/call <kind>__<tool>, args+session_id)
       ↓
     v8-session-manager (L3)
       └─ resolve по (kind, tool_name) → session_id (из аргументов или единственный кандидат)
       └─ enqueue в FIFO нужной сессии
            ↓
          WS :4000/sessions ──► 1С-клиент
                                  └─ client_mcp BSL (L2) принимает JSON-RPC
                                       └─ диспетчер расширения (L2.5) выполняет tool
                                       └─ результат ──► обратно тем же путём
```

## Что где живёт

- **Rust** (этот репозиторий): транспорт + реестр + MCP-сервер. Тестируется отдельно, версионируется отдельно.
- **BSL** (репозиторий проекта 1С): `client_mcp` + прикладные расширения. Здесь работает разработчик, добавляющий новые tools.
- **Транспорт** (`session_y8`): отдельный addin, версионируется отдельно. На стороне 1С загружается через `client_mcp`.

## Что меняется в каком репозитории

| Изменение | Репо | Skill |
|---|---|---|
| Новый MCP-tool в `test_client` / `VAExtension` / др. | проект 1С | этот skill (`extending-tools.md`) + skill соответствующего расширения |
| Добавить параметр в `v8project.yaml`, поднять менеджер | проект 1С (конфиг) | этот skill (`bootstrap.md`) |
| Запуск 1С-клиента с подключением к менеджеру | проект 1С | `v8-runner` skill (опции `--mcp-transport=ws --manager-url=...`) |
| Изменить транспорт `session_y8`, реестр менеджера, протокол | upstream-репо менеджера / addin | вне скоупа: согласовать отдельной задачей |
