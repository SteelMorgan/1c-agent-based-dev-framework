# Работа с метаданными (Metadata Discovery)

## Назначение

Навык учит агента **работать с метаданными конфигурации 1С** — находить объекты (справочники, документы, регистры, обработки), понимать их структуру и связи. Метаданные — основа любой разработки в 1С: код всегда опирается на существующие объекты конфигурации.

**Принцип:** Перед работой с бизнес-логикой — исследовать метаданные. Не создавать объекты «наугад», если пользователь не попросил явно.

---

## Когда применять

| Триггер | Действие |
|---------|----------|
| Задача связана с конкретным объектом (справочник, документ) | `search_metadata` — проверить существование, структуру |
| Нужно найти «все документы, связанные с Номенклатурой» | `search_metadata` по паттерну + анализ реквизитов |
| Проверка наличия регистра (например, ОстаткиТоваров) | `search_metadata` с фильтром по типу |
| Пользователь просит добавить реквизит | Сначала `search_metadata` — изучить объект, реквизиты, табличные части |
| Анализ зависимостей между объектами | `search_metadata` + `navigate_symbol` для переходов к модулям |
| Создание нового объекта метаданных | См. протокол «агент ↔ пользователь» — требуется участие пользователя |

---

## Сценарии использования

### Сценарий 1: Поиск объекта по имени

**Шаги:**

1. `search_metadata` с `query: "Номенклатура"`.
2. Анализ `objects` — полное имя (`full_name`), тип (`type`), атрибуты.
3. При необходимости уточнить тип: `object_type: "Справочник"` или `"Документ"`.

**Пример:** Проверить существование регистра «ОстаткиТоваров».

```
search_metadata(query: "ОстаткиТоваров", object_type: "РегистрНакопления")
```

### Сценарий 2: Поиск объектов по паттерну

**Шаги:**

1. `search_metadata` с широким запросом (например, «Товар», «Остатки»).
2. Отфильтровать по `type` и `attributes` в результатах.
3. Для детального анализа — `navigate_symbol` по имени объекта для перехода к модулям.

**Пример:** Найти все документы, связанные с номенклатурой.

```
1. search_metadata(query: "Номенклатура")
2. search_metadata(query: "Документ", object_type: "Документ")
3. Анализ objects[].attributes — реквизиты типа СправочникСсылка.Номенклатура
```

### Сценарий 3: Поиск объекта → анализ кода

**Шаги:**

1. `search_metadata` — найти объект (например, `Справочник.Контрагенты`).
2. `navigate_symbol` — найти модуль объекта, процедуры, функции.
3. `get_call_graph` — понять цепочки вызовов (опционально).
4. На основе анализа — предложить решение или написать код.

### Сценарий 4: Создание нового объекта — протокол с пользователем

**Важно:** Создание объектов метаданных (новый справочник, документ, регистр) **не выполняется автоматически** агентом. Это требует действий в Конфигураторе или EDT.

**Шаги:**

1. `search_metadata` — убедиться, что объект не существует.
2. Агент формирует описание: что создать, какие реквизиты, табличные части.
3. Агент сообщает пользователю: «Создайте объект X в Конфигураторе со следующими реквизитами: …».
4. Пользователь создаёт объект вручную.
5. После создания — `search_metadata` для проверки, затем работа с модулями.

## Понимание структуры метаданных

| Элемент | Описание |
|---------|----------|
| `full_name` | Полное имя: `Справочник.Номенклатура`, `Документ.РеализацияТоваровУслуг` |
| `type` | Тип объекта: Справочник, Документ, РегистрСведений, РегистрНакопления, Обработка и т.д. |
| `attributes` | Реквизиты объекта (при детальном поиске) |
| `tabular_sections` | Табличные части (при детальном поиске) |

**Иерархия:** Справочники могут иметь иерархию. Документы — периодичность, проведение. Регистры — вид, измерение, ресурсы.

---

## Связанные capability

| Capability | Категория | Назначение |
|------------|-----------|------------|
| `search_metadata` | Important | Поиск объектов метаданных по запросу |
| `navigate_symbol` | Core | Переход к модулям, процедурам найденных объектов |
| `get_call_graph` | Important | Анализ цепочек вызовов в модулях |
| `dump_config` | Optional | Выгрузка конфигурации (может требоваться для search_metadata) |

---

## Типичные ошибки и обходные пути

| Ошибка | Обходной путь |
|--------|---------------|
| `search_metadata` возвращает пусто | Конфигурация не загружена — выполнить `dump_config`; проверить корректность запроса (регистр, язык). |
| Поиск по общему слову даёт много результатов | Сузить запрос; использовать `object_type` для фильтрации. |
| Нужно создать объект — агент пытается сделать это сам | Следовать протоколу: агент описывает, пользователь создаёт в Конфигураторе/EDT. |
| `search_metadata` недоступен | Capability зависит от провайдера; запасной вариант — `navigate_symbol` по именам объектов, если известны. |
| Неясно, как объекты связаны | Комбинировать с `navigate_symbol` и `get_call_graph` — анализ кода покажет связи. |
