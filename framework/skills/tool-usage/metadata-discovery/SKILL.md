# Работа с метаданными (Metadata Discovery)

## Назначение

Навык учит агента **работать с метаданными конфигурации 1С** — находить объекты (справочники, документы, регистры, обработки), понимать их структуру и связи. Метаданные — основа любой разработки в 1С: код всегда опирается на существующие объекты конфигурации.

**Принцип:** Перед работой с бизнес-логикой — исследовать метаданные. Не создавать объекты «наугад», если пользователь не попросил явно.

---

## Когда применять

| Триггер | Действие |
|---------|----------|
| Задача связана с конкретным объектом (справочник, документ) | `list_metadata_objects` — проверить существование; `get_metadata_structure` — структуру |
| Нужно найти «все документы, связанные с Номенклатурой» | `list_metadata_objects` по metaType + nameMask + анализ реквизитов через `get_metadata_structure` |
| Проверка наличия регистра (например, ОстаткиТоваров) | `list_metadata_objects` с metaType: "РегистрНакопления", nameMask |
| Пользователь просит добавить реквизит | Сначала `get_metadata_structure` — изучить объект, реквизиты, табличные части |
| Перед построением запроса — не уверен в именах таблиц/полей | `get_metadata_structure` — получить измерения, ресурсы, реквизиты |
| Анализ зависимостей между объектами | `list_metadata_objects` + `navigate_symbol` для переходов к модулям |
| Создание нового объекта метаданных | См. протокол «агент ↔ пользователь» — требуется участие пользователя |

---

## Сценарии использования

### Сценарий 1: Поиск объекта по имени

**Шаги:**

1. `list_metadata_objects` с `metaType: "Справочник"`, `nameMask: "Номенклатура"` (или `"*Номенклатура*"` для нечёткого поиска).
2. Анализ результатов — полное имя, тип.
3. При необходимости уточнить тип: `metaType: "Документ"`, `"РегистрНакопления"` и т.д.

**Пример:** Проверить существование регистра «ОстаткиТоваров».

```
list_metadata_objects(metaType: "РегистрНакопления", nameMask: "ОстаткиТоваров", maxItems: 10)
```

### Сценарий 2: Поиск объектов по паттерну

**Шаги:**

1. `list_metadata_objects` с metaType и nameMask (например, metaType: "Документ", nameMask: "*Номенклатура*").
2. Отфильтровать результаты по необходимости.
3. Для детального анализа — `get_metadata_structure` по найденному объекту.
4. Для перехода к коду — `navigate_symbol` по имени объекта.

**Пример:** Найти все документы, связанные с номенклатурой.

```
1. list_metadata_objects(metaType: "Справочник", nameMask: "Номенклатура")
2. list_metadata_objects(metaType: "Документ", nameMask: "*", maxItems: 50)
3. get_metadata_structure(metaType: "Документ", name: "РеализацияТоваровУслуг") — проверить реквизиты типа СправочникСсылка.Номенклатура
```

### Сценарий 3: Получение структуры перед запросом

**Шаги:**

1. `list_metadata_objects` — найти объект (если имя неизвестно).
2. `get_metadata_structure` — получить реквизиты, табличные части, измерения, ресурсы.
3. Строить запрос, опираясь на точные имена полей.

**Пример:** Написать запрос к регистру остатков.

```
1. list_metadata_objects(metaType: "РегистрНакопления", nameMask: "Остатки*")
2. get_metadata_structure(metaType: "РегистрНакопления", name: "ОстаткиТоваров")
3. Использовать измерения, ресурсы из структуры в тексте запроса
```

### Сценарий 4: Поиск объекта → анализ кода

**Шаги:**

1. `list_metadata_objects` — найти объект (например, Справочник.Контрагенты).
2. `navigate_symbol` — найти модуль объекта, процедуры, функции.
3. `get_call_graph` — понять цепочки вызовов (опционально).
4. На основе анализа — предложить решение или написать код.

### Сценарий 5: Создание нового объекта — протокол с пользователем

**Важно:** Создание объектов метаданных (новый справочник, документ, регистр) **не выполняется автоматически** агентом. Это требует действий в Конфигураторе или EDT.

**Шаги:**

1. `list_metadata_objects` — убедиться, что объект не существует.
2. Агент формирует описание: что создать, какие реквизиты, табличные части.
3. Агент сообщает пользователю: «Создайте объект X в Конфигураторе со следующими реквизитами: …».
4. Пользователь создаёт объект вручную.
5. После создания — `list_metadata_objects` и `get_metadata_structure` для проверки, затем работа с модулями.

## Параметры инструментов

| Tool | Параметры | Назначение |
|------|-----------|------------|
| `list_metadata_objects` | metaType, nameMask, maxItems | Поиск объектов по типу и маске имени. Вызывай перед `execute_query`, если не знаешь точное имя объекта. |
| `get_metadata_structure` | metaType, name | Структура объекта: реквизиты, табличные части, измерения, ресурсы. Обязательно перед построением запроса, если не уверен в именах полей. |

---

## Понимание структуры метаданных

| Элемент | Описание |
|---------|----------|
| full_name | Полное имя: `Справочник.Номенклатура`, `Документ.РеализацияТоваровУслуг` |
| type | Тип объекта: Справочник, Документ, РегистрСведений, РегистрНакопления, Обработка и т.д. |
| attributes | Реквизиты объекта (из `get_metadata_structure`) |
| tabular_sections | Табличные части (из `get_metadata_structure`) |
| dimensions, resources | Измерения и ресурсы регистров (из `get_metadata_structure`) |

**Иерархия:** Справочники могут иметь иерархию. Документы — периодичность, проведение. Регистры — вид, измерение, ресурсы.

## Capabilities

| Capability | Назначение |
|------------|------------|
| `list_metadata_objects` | Поиск объектов метаданных по типу и маске имени |
| `get_metadata_structure` | Получение структуры объекта (реквизиты, табличные части, измерения, ресурсы) |
| `navigate_symbol` | Переход к модулям, процедурам найденных объектов |
| `get_call_graph` | Анализ цепочек вызовов в модулях |
| `dump_config` | Выгрузка конфигурации (может выполняться по требовани пользователя) |

---

## Типичные ошибки и обходные пути

| Ошибка | Обходной путь |
|--------|---------------|
| Поиск по общему слову даёт много результатов | Сузить nameMask; использовать metaType для фильтрации; уменьшить maxItems. |
| Нужно создать объект — агент пытается сделать это сам | Следовать протоколу: агент описывает, пользователь создаёт в Конфигураторе/EDT. |
| Инструменты недоступны | Capability зависит от провайдера; запасной вариант — `navigate_symbol` по именам объектов, если известны. |
| Неясно, как объекты связаны | Комбинировать с `navigate_symbol` и `get_call_graph` — анализ кода покажет связи. |
