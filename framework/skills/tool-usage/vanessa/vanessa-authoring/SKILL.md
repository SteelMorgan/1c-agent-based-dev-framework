# Авторинг сценариев Vanessa Automation

## Когда применять

| Триггер | Действие |
|---------|----------|
| Нужно написать новый `.feature` | Использовать этот навык как baseline authoring |
| Нужно доработать существующий сценарий | Сократить сценарий до одного поведения |
| Нужно выбрать следующий кейс для покрытия | Брать реальное требование проекта |

---

## Источник сценария

Политика источников сценариев — см. правило `vanessa-scenario-policy`.

---

## Базовый процесс

1. Определи источник требования (спецификация или существующий бизнес-кейс).
2. Найди похожие шаги в библиотеке Vanessa и сценариях проекта.
3. Сформулируй один короткий `smoke`-сценарий: открыть форму → одно действие → одно наблюдаемое последствие.
4. Если точного шага нет — пометь `unknown_step_candidate`, а не придумывай низкоуровневый BSL-шаг.
5. Отдели подготовку данных от основного поведения.
6. После написания — передай сценарий в `vanessa-run`.

---

## Ожидания в сценариях

Допустимо: состояние реквизита на форме, видимость/доступность команды, изменение значения в таблице, появление/отсутствие сообщения.

Недопустимо: внутренний вызов метода, техническая деталь, не наблюдаемая из UI.

---

## Расположение сценариев

Project-local сценарии:

```text
<project_root>/vanessa-tests/features
<project_root>/vanessa-tests/support
```

Shared templates: `tools/runtime/vanessa/`. Сценарии проекта всегда project-local.

---

## Типичные ошибки

| Ошибка | Как избежать |
|--------|--------------|
| Выдуманный кейс | Всегда указывать источник требования |
| Слишком длинный сценарий | Делить на короткие smoke-сценарии |
| Придуманный шаг | Сначала искать существующий шаг в библиотеке |
| Подготовка данных смешана с проверкой | Выносить подготовку отдельно |
