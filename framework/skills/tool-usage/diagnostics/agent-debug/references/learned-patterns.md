# Learned Patterns — agent-debug

Проверенные приёмы и антиприёмы, накопленные из реальных задач.
`confirmed` — подтверждённое правило, `candidate` — требует повторного подтверждения.

---

```
status: candidate
область: отладка headless-прогона внешней обработки (.epf через 1cv8 ENTERPRISE /Execute), когда стандартные каналы наблюдаемости молчат или лгут
приём: Когда сервер-файл / клиент-файл / Сообщить-в-Out / журнал регистрации недоступны или
       врут — открыть форму ИНТЕРАКТИВНО на реальном экране (DISPLAY, xdotool+scrot), нажать
       нужный шаг/кнопку руками и прочитать модальную ошибку + стек из журнала регистрации.
       Прямое GUI-наблюдение — канал истины последней инстанции. Истину о данных в БД
       подтверждать read-only запросом, а НЕ кодом выхода/stdout прогона.
антиприём: НЕ принимать "EXIT=0 / пустой Out" за доказательство успеха headless-прогона.
           /Execute открывает ФОРМУ: при раннем выходе из ПриОткрытии (несовпадение параметра
           запуска) или зависании на GUI-диалоге процесс висит/выходит без следов, а нулевой
           результат трактуется как "успех". И НЕ строить диагноз на чужом непроверенном
           "корне" — перепроверять источник истины самому.
почему: у headless-прогона .epf под типовой конфигурацией разом отказывают несколько каналов:
        серверная запись файла идёт на ФС сервера приложений (другой хост — локально недостижимо);
        клиентская запись файла в безопасном режиме /Execute падает молча; вывод Сообщить в /Out
        не сбрасывается при зависании процесса; конвейер журнала регистрации может лагать/подвисать.
        Остаются реальный экран и прямой запрос к БД.
шаги: |
  1. Запустить форму интерактивно: ENTERPRISE /Execute<epf> БЕЗ ключа-триггера → форма открыта.
  2. Снять экран (scrot/import на нужном DISPLAY); найти/активировать окно (wmctrl/xwininfo/xdotool).
  3. Нажать кнопку шага (xdotool click) → снять экран → прочитать модальную ошибку.
  4. Снять стек из журнала регистрации (он содержит точную строку модуля), если конвейер жив.
  5. Истину по данным — read-only запросом к БД (дельта счётчиков до/после), не по коду выхода.
источник: backfill-обработка под типовой конфигурацией, многоканальный отказ наблюдаемости, 2026-06
```
