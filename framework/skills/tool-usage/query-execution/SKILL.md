# Выполнение запросов (Query Execution)

## Назначение

Навык учит агента **работать с запросами на языке запросов 1С** — проверять синтаксис без выполнения и получать данные из базы. Используется при анализе данных, диагностике, проверке заполнения.

**Принцип:** Перед выполнением — `validate_query`. Не уверен в именах таблиц/полей — `get_metadata_structure`.

**Справочник синтаксиса и примеры запросов:** [`references/query-syntax-cheatsheet.md`](references/query-syntax-cheatsheet.md)

---

## КРИТИЧНО: Проверка метаданных

**Никогда не угадывай имена объектов и полей.** Конфигурации 1С различаются — имена уникальны для каждой базы.

Перед построением запроса, если не уверен в точных именах:
1. `list_metadata_objects` — найти объект по metaType и nameMask
2. `get_metadata_structure` — получить реквизиты, табличные части, измерения, ресурсы

**Workflow:** метаданные → подтвердить имена → построить запрос → `validate_query` → `execute_query`

Запрос с неверным именем объекта или поля приведёт к ошибке. Один вызов за метаданными дешевле отладки провалившегося запроса.

---

## Когда применять

| Триггер | Действие |
|---------|----------|
| Нужно выполнить запрос к базе 1С | `validate_query` → `execute_query` |
| Пользователь просит проверить запрос | `validate_query` |
| Анализ данных, диагностика заполнения | `get_metadata_structure` (если не знаешь структуру) → `execute_query` |
| Итерационный анализ — модель анализирует результаты и делает доп. запросы | `execute_query` с уточнённым запросом |

---

## Сценарии использования

### Сценарий 1: Проверка и выполнение запроса

**Шаги:**

1. `validate_query` — проверить синтаксис без выполнения.
2. Если ошибок нет — `execute_query` для получения данных.
3. При ошибке валидации — исправить запрос, повторить.

### Сценарий 2: Запрос к неизвестной структуре

**Шаги:**

1. `list_metadata_objects` — найти объект (если имя неизвестно).
2. `get_metadata_structure` — получить имена таблиц, полей, измерений, ресурсов.
3. Построить запрос с корректными именами.
4. `validate_query` → `execute_query`.

### Сценарий 3: Ограничение выборки

При больших объёмах данных — использовать `ВЫБРАТЬ ПЕРВЫЕ N` или условия отбора, чтобы не перегружать ответ.

## Критические ограничения MCP

При выполнении запросов через `execute_query` (HTTP/MCP без параметров) значения задаются **явно в тексте запроса**. Параметры `&Имя` могут не поддерживаться.

### 1. Ограничивать выборку через ПЕРВЫЕ N

Для запросов, возвращающих строки данных, всегда ограничивай количество записей:

```sql
ВЫБРАТЬ ПЕРВЫЕ 100
    Документы.Номер,
    Документы.Дата
ИЗ
    Документ.РеализацияТоваровУслуг КАК Документы
```

**Исключения — `ПЕРВЫЕ N` не нужен и вреден:**

| Случай | Почему не нужен |
|--------|-----------------|
| Агрегатные запросы (`КОЛИЧЕСТВО`, `СУММА`, `МАКСИМУМ`) | Возвращают одну строку; `ПЕРВЫЕ 1` избыточен и может дать неверный результат при группировке |
| Проверка существования (`ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка ИЗ ... ГДЕ ...`) | `ПЕРВЫЕ 1` здесь уместен и уже ограничивает |
| `ОБЪЕДИНИТЬ ВСЕ` в подзапросах | Ограничение задаётся на внешнем уровне |

### 2. Параметры — если не поддерживаются

❌ **НЕПРАВИЛЬНО** (если `&Параметр` недоступен):
```sql
ГДЕ Товар = &Товар
```

✅ **ПРАВИЛЬНО** (сравнение через примитивные реквизиты):
```sql
ГДЕ Товар.Наименование = "iPhone 17 Pro Max"
ГДЕ Контрагент.ИНН = "7707083893"
```

### 3. Сравнение ссылочных полей — только через примитивы

`execute_query` через HTTP/MCP не поддерживает параметры `&Ссылка`, поэтому сравнивать ссылочные поля напрямую невозможно — используй примитивные реквизиты объекта.

❌ **НЕПРАВИЛЬНО** (сравнение ссылок напрямую):
```sql
ГДЕ Документ.Контрагент = Справочник.Контрагенты.Ссылка
```

✅ **ПРАВИЛЬНО** (сравнение через примитивные реквизиты):
```sql
ГДЕ Документ.Контрагент.Наименование = "ООО Ромашка"
ГДЕ Документ.Контрагент.Код = "000001"
ГДЕ Документ.Контрагент.ИНН = "7707083893"
```

> ⚠️ **Важно — риск неоднозначности.** Наименование и Код не гарантируют уникальность:
> - `Наименование` — может повторяться в разных папках или при дублях
> - `Код` — уникален внутри справочника, предпочтительнее
> - `ИНН`, `Артикул` и другие бизнес-идентификаторы — используй, если они уникальны в этой конфигурации
>
> Когда допустимо: диагностика, анализ данных, разовые запросы где дубли маловероятны.
> Когда недопустимо: критически важная выборка, где ложное совпадение по имени даст неверный результат — в этом случае уточни у пользователя точный идентификатор или используй `ПОДОБНО` с предупреждением о возможных дублях.

### 4. Работа с датами — функция ДАТАВРЕМЯ

```sql
ГДЕ Документы.Дата >= ДАТАВРЕМЯ(2026, 1, 1)
    И Документы.Дата < ДАТАВРЕМЯ(2026, 2, 1)
```

**Формат:** `ДАТАВРЕМЯ(Год, Месяц, День[, Час, Минута, Секунда])`

### 5. Строковые значения — двойные кавычки

```sql
ГДЕ Номенклатура.Наименование = "iPhone 17 Pro Max, 512 Гб"
ГДЕ Контрагент.ИНН = "7707083893"
```

## Capabilities

| Capability | Назначение |
|------------|------------|
| `validate_query` | Проверка синтаксиса запроса на языке запросов 1С без выполнения |
| `execute_query` | Выполнение запроса и получение данных из базы 1С |
| `get_metadata_structure` | Получение структуры объекта перед построением запроса (если не уверен в именах) |

## Типичные ошибки и обходные пути

| Ошибка | Обходной путь |
|--------|---------------|
| Ошибка в validate_query | Проверить имена таблиц/полей через `get_metadata_structure`. |
| «Параметр не найден» | `&Параметр` не поддерживается — использовать явные значения в тексте запроса. |
| Ошибка при сравнении ссылок | `&Ссылка` не поддерживается через MCP — сравнивать через `.Код` (предпочтительно), `.Наименование`, `.ИНН`. Код уникален; Наименование может давать дубли — учитывать при критичных запросах. |
| Слишком много данных / таймаут | Для выборки строк использовать `ПЕРВЫЕ N`; для агрегатов (`КОЛИЧЕСТВО`, `СУММА`) `ПЕРВЫЕ` не нужен. |
| NULL в вычислениях | Использовать `ЕСТЬNULL(Поле, ЗначениеПоУмолчанию)` при LEFT JOIN. |
| execute_query возвращает пусто | Проверить условия отбора, существование данных. |
| Не знаю точное имя объекта | `list_metadata_objects` перед построением запроса. |
| Медленный запрос с ИЛИ | Заменить на `В (...)` или разбить на `ОБЪЕДИНИТЬ ВСЕ`. |
| Медленный запрос к Регистратору | Использовать `ВЫРАЗИТЬ(Регистратор КАК Документ.Имя)` и `ССЫЛКА` в ГДЕ. |
