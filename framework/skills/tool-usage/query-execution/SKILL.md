# Выполнение запросов (Query Execution)

## Назначение

Навык учит агента **работать с запросами на языке запросов 1С** — проверять синтаксис без выполнения и получать данные из базы. Используется при анализе данных, диагностике, проверке заполнения.

**Принцип:** Перед выполнением — `validate_query`. Не уверен в именах таблиц/полей — `get_metadata_structure`.

---

## КРИТИЧНО: Проверка метаданных

**Никогда не угадывай имена объектов и полей.** Конфигурации 1С различаются — имена уникальны для каждой базы.

Перед построением запроса, если не уверен в точных именах:
1. `list_metadata_objects` — найти объект по metaType и nameMask
2. `get_metadata_structure` — получить реквизиты, табличные части, измерения, ресурсы

**Workflow:** метаданные → подтвердить имена → построить запрос → `validate_query` → `execute_query`

Запрос с неверным именем объекта или поля приведёт к ошибке. Один вызов за метаданными дешевле отладки провалившегося запроса.

---

## Когда применять

| Триггер | Действие |
|---------|----------|
| Нужно выполнить запрос к базе 1С | `validate_query` → `execute_query` |
| Пользователь просит проверить запрос | `validate_query` |
| Анализ данных, диагностика заполнения | `get_metadata_structure` (если не знаешь структуру) → `execute_query` |
| Итерационный анализ — модель анализирует результаты и делает доп. запросы | `execute_query` с уточнённым запросом |

---

## Сценарии использования

### Сценарий 1: Проверка и выполнение запроса

**Шаги:**

1. `validate_query` — проверить синтаксис без выполнения.
2. Если ошибок нет — `execute_query` для получения данных.
3. При ошибке валидации — исправить запрос, повторить.

### Сценарий 2: Запрос к неизвестной структуре

**Шаги:**

1. `list_metadata_objects` — найти объект (если имя неизвестно).
2. `get_metadata_structure` — получить имена таблиц, полей, измерений, ресурсов.
3. Построить запрос с корректными именами.
4. `validate_query` → `execute_query`.

### Сценарий 3: Ограничение выборки

При больших объёмах данных — использовать `ВЫБРАТЬ ПЕРВЫЕ N` или условия отбора, чтобы не перегружать ответ.

---

## Критические ограничения

При выполнении запросов через `execute_query` (HTTP/MCP без параметров) значения задаются **явно в тексте запроса**. Параметры `&Имя` могут не поддерживаться.

### 1. ОБЯЗАТЕЛЬНО использовать ПЕРВЫЕ N

Всегда ограничивай количество записей:

```sql
ВЫБРАТЬ ПЕРВЫЕ 100
    Документы.Номер,
    Документы.Дата
ИЗ
    Документ.РеализацияТоваровУслуг КАК Документы
```

### 2. Параметры — если не поддерживаются

❌ **НЕПРАВИЛЬНО** (если `&Параметр` недоступен):
```sql
ГДЕ Товар = &Товар
```

✅ **ПРАВИЛЬНО** (сравнение через примитивные реквизиты):
```sql
ГДЕ Товар.Наименование = "iPhone 17 Pro Max"
ГДЕ Контрагент.ИНН = "7707083893"
```

### 3. Сравнение ссылочных полей — только через примитивы

❌ **НЕПРАВИЛЬНО** (сравнение ссылок напрямую):
```sql
ГДЕ Документ.Контрагент = Справочник.Контрагенты.Ссылка
```

✅ **ПРАВИЛЬНО** (сравнение через Код, Наименование, ИНН):
```sql
ГДЕ Документ.Контрагент.Наименование = "ООО Ромашка"
ГДЕ Документ.Контрагент.Код = "000001"
```

### 4. Работа с датами — функция ДАТАВРЕМЯ

```sql
ГДЕ Документы.Дата >= ДАТАВРЕМЯ(2026, 1, 1) 
    И Документы.Дата < ДАТАВРЕМЯ(2026, 2, 1)
```

**Формат:** `ДАТАВРЕМЯ(Год, Месяц, День[, Час, Минута, Секунда])`

### 5. Строковые значения — двойные кавычки

```sql
ГДЕ Номенклатура.Наименование = "iPhone 17 Pro Max, 512 Гб"
ГДЕ Контрагент.ИНН = "7707083893"
```

## Справочник синтаксиса

### Базовая структура

```sql
ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ N]
    <Поля выборки>
ИЗ
    <Источники данных>
[ГДЕ <Условия отбора>]
[СГРУППИРОВАТЬ ПО <Поля группировки>]
[УПОРЯДОЧИТЬ ПО <Поля сортировки>]
```

**РАЗРЕШЕННЫЕ** — учитывать RLS (права доступа на уровне записей). Рекомендуется по умолчанию.

### Источники данных

| Тип объекта | Синтаксис |
|-------------|-----------|
| Справочник | `Справочник.ИмяСправочника` |
| Документ | `Документ.ИмяДокумента` |
| Табличная часть документа | `Документ.ИмяДокумента.ИмяТабличнойЧасти` |
| Регистр накопления (остатки) | `РегистрНакопления.ИмяРегистра.Остатки()` |
| Регистр накопления (обороты) | `РегистрНакопления.ИмяРегистра.Обороты()` |
| Регистр сведений | `РегистрСведений.ИмяРегистра` |
| Регистр сведений (срез последних) | `РегистрСведений.ИмяРегистра.СрезПоследних()` |
| Регистр бухгалтерии | `РегистрБухгалтерии.ИмяРегистра` |
| План счетов | `ПланСчетов.ИмяПлана` |

### Суффиксы ресурсов регистров

**Остатки:** `<ИмяРесурса>Остаток` (например: `КоличествоОстаток`)

**Обороты:** `<ИмяРесурса>Оборот`, `КоличествоПриход`, `КоличествоРасход`

**ОстаткиИОбороты:** `<ИмяРесурса>НачальныйОстаток`, `Приход`, `Расход`, `Оборот`, `КонечныйОстаток`

### Фильтрация в виртуальных таблицах

Условия лучше передавать в параметры виртуальной таблицы, а не в ГДЕ:

❌ **Неэффективно** (сначала получаются ВСЕ остатки, потом фильтрация):
```sql
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
ГДЕ Остатки.Склад.Наименование = "Основной склад"
```

✅ **Эффективно** (фильтрация при расчёте):
```sql
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(
    ,
    Склад.Наименование = "Основной склад"
) КАК Остатки
```

### Работа с NULL

При соединениях таблиц поля могут содержать NULL. Используй `ЕСТЬNULL()` для подстановки значения по умолчанию:

```sql
ВЫБРАТЬ ПЕРВЫЕ 100
    Товары.Наименование,
    ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
ИЗ
    Справочник.Номенклатура КАК Товары
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
    ПО Остатки.Номенклатура = Товары.Ссылка
```

**Проверка на NULL:** используй `ЕСТЬ NULL` / `НЕ ЕСТЬ NULL`, никогда не пиши `= NULL`:

```sql
ГДЕ Поле ЕСТЬ NULL
ГДЕ Поле НЕ ЕСТЬ NULL
```

### ВЫРАЗИТЬ для составных типов

Поля составного типа (например, `Регистратор` регистра — любой документ) при обращении через точку создают неявные JOIN ко **всем** возможным таблицам. Это сильно замедляет запрос.

**Сужать тип через ВЫРАЗИТЬ:**

```sql
-- ПЛОХО: JOIN ко всем типам Регистратора
ВЫБРАТЬ Регистратор.Номер ИЗ РегистрНакопления.ОстаткиТоваров

-- ХОРОШО: один JOIN
ВЫБРАТЬ ВЫРАЗИТЬ(Регистратор КАК Документ.РеализацияТоваровУслуг).Номер
ИЗ РегистрНакопления.ОстаткиТоваров
ГДЕ Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
```

### Операторы ГДЕ

| Оператор | Синтаксис 1С |
|----------|--------------|
| Равно / не равно | `=`, `<>` |
| Сравнение | `<`, `>`, `<=`, `>=` |
| Диапазон | `МЕЖДУ X И Y` (включительно) |
| В списке | `В (val1, val2, ...)` или `В (ВЫБРАТЬ ...)` |
| NULL | `ЕСТЬ NULL`, `НЕ ЕСТЬ NULL` (не `= NULL`) |
| Проверка типа ссылки | `ССЫЛКА Документ.ИмяДокумента` |
| Шаблон | `ПОДОБНО "шаблон"` — `%` любая строка, `_` один символ |
| Логика | `И`, `ИЛИ`, `НЕ` |

**ИЛИ ухудшает использование индексов.** По возможности заменяй на `В (...)` или разбивай на `ОБЪЕДИНИТЬ ВСЕ`.

### Предопределённые значения

```sql
ГДЕ ВидОперации = Значение(Перечисление.ВидыОпераций.Продажа)
ГДЕ Склад = Значение(Справочник.Склады.ОсновнойСклад)
```

## Примеры запросов

### Остатки товаров на складах

```sql
ВЫБРАТЬ ПЕРВЫЕ 100
    Остатки.Номенклатура.Наименование КАК Товар,
    Остатки.Склад.Наименование КАК Склад,
    Остатки.КоличествоОстаток КАК Количество
ИЗ
    РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
ГДЕ
    Остатки.КоличествоОстаток > 0
УПОРЯДОЧИТЬ ПО
    Товар
```

### Документы за период

```sql
ВЫБРАТЬ ПЕРВЫЕ 50
    Док.Номер,
    Док.Дата,
    Док.Контрагент.Наименование КАК Контрагент,
    Док.СуммаДокумента
ИЗ
    Документ.РеализацияТоваровУслуг КАК Док
ГДЕ
    Док.Дата >= ДАТАВРЕМЯ(2026, 1, 1)
    И Док.Дата < ДАТАВРЕМЯ(2026, 2, 1)
    И Док.Проведен = ИСТИНА
УПОРЯДОЧИТЬ ПО
    Док.Дата УБЫВ
```

### Актуальные цены (срез последних)

```sql
ВЫБРАТЬ ПЕРВЫЕ 100
    Цены.Номенклатура.Наименование КАК Товар,
    Цены.Номенклатура.Код КАК КодТовара,
    Цены.ТипЦен.Наименование КАК ТипЦены,
    Цены.Цена
ИЗ
    РегистрСведений.ЦеныНоменклатуры.СрезПоследних() КАК Цены
УПОРЯДОЧИТЬ ПО
    Товар
```

### Поиск по имени (нечёткий)

```sql
ВЫБРАТЬ ПЕРВЫЕ 50
    Ссылка,
    Наименование
ИЗ
    Справочник.Контрагенты
ГДЕ
    Наименование ПОДОБНО "%рога%"
```

### Проверка существования

```sql
ВЫБРАТЬ ПЕРВЫЕ 1
    Ссылка
ИЗ
    Справочник.Контрагенты
ГДЕ
    ИНН = "7707083893"
```

### Исключение помеченных на удаление

```sql
ГДЕ НЕ ПометкаУдаления
```

### Последние N документов

```sql
ВЫБРАТЬ ПЕРВЫЕ 10
    Ссылка,
    Дата,
    Номер,
    СуммаДокумента
ИЗ
    Документ.РеализацияТоваровУслуг
УПОРЯДОЧИТЬ ПО
    Дата УБЫВ
```

## Capabilities

| Capability | Назначение |
|------------|------------|
| `validate_query` | Проверка синтаксиса запроса на языке запросов 1С без выполнения |
| `execute_query` | Выполнение запроса и получение данных из базы 1С |
| `get_metadata_structure` | Получение структуры объекта перед построением запроса (если не уверен в именах) |

---

## Типичные ошибки и обходные пути

| Ошибка | Обходной путь |
|--------|---------------|
| Ошибка в validate_query | Проверить имена таблиц/полей через `get_metadata_structure`. |
| «Параметр не найден» | `&Параметр` не поддерживается — использовать явные значения в тексте запроса. |
| Ошибка при сравнении ссылок | Сравнивать через `.Код`, `.Наименование`, `.ИНН` и т.п., не через ссылку напрямую. |
| Слишком много данных / таймаут | Всегда использовать `ПЕРВЫЕ N`, начинать с малых значений (100, 50). |
| NULL в вычислениях | Использовать `ЕСТЬNULL(Поле, ЗначениеПоУмолчанию)` при LEFT JOIN. |
| execute_query возвращает пусто | Проверить условия отбора, существование данных. |
| Не знаю точное имя объекта | `list_metadata_objects` перед построением запроса. |
| Медленный запрос с ИЛИ | Заменить на `В (...)` или разбить на `ОБЪЕДИНИТЬ ВСЕ`. |
| Медленный запрос к Регистратору | Использовать `ВЫРАЗИТЬ(Регистратор КАК Документ.Имя)` и `ССЫЛКА` в ГДЕ. |
