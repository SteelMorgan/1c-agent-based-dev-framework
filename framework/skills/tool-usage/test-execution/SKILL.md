# Запуск и анализ тестов (Test Execution)

## Назначение

Навык учит агента **запускать тесты YaxUnit, анализировать результаты и связывать падения тестов с кодом**. Тесты — единственный надёжный способ убедиться, что код работает корректно после изменений.

**Принцип:** Написал код → запусти тесты. Тест упал → найди причину, исправь, перезапусти.

---

## Когда применять

| Триггер | Действие |
|---------|----------|
| После реализации функциональности | `run_tests` для проверки |
| Пользователь просит запустить тесты модуля X | `run_tests` с `scope: "X"` |
| TDD-подход: написал тест, реализую логику | Запуск после каждого этапа |
| После рефакторинга | Запуск всех тестов или затронутых модулей |
| Исправление бага | Написать/найти тест, исправить, перезапустить |
| Перед коммитом | Рекомендуется полный прогон тестов |

---

## Сценарии использования

### Сценарий 1: Стандартный прогон после изменений

**Шаги:**

1. Агент внёс изменения в модуль (например, `УправлениеСкладом`).
2. `build_project` — убедиться, что проект собирается без ошибок.
3. `run_tests` с `scope: "УправлениеСкладом"` — запуск тестов изменённого модуля.
4. При `success = true` — задача выполнена.
5. При `success = false` — анализ `errors`, исправление, повторный запуск.

### Сценарий 2: Анализ падения теста

**Шаги:**

1. `run_tests` возвращает `failed > 0`, `errors` содержит детали.
2. Читать `errors[].module`, `errors[].test`, `errors[].message`.
3. `navigate_symbol` — перейти к падающему тесту по имени (например, `ТестПолучитьОстатки`).
4. Проанализировать Assert и тестируемый код.
5. `navigate_symbol` — перейти к тестируемой процедуре/функции.
6. Исправить код или тест.
7. `run_tests` — перезапуск для проверки.

**Пример структуры ошибки:**

```
errors: [{ module: "УправлениеСкладом", test: "ТестПолучитьОстатки", message: "Ожидалось 10, получено 0" }]
```

### Сценарий 3: TDD-цикл

**Шаги:**

1. Написать тест для новой функции (ожидаем падение).
2. `run_tests` — подтвердить падение (`failed > 0`).
3. Реализовать минимальную логику для прохождения теста.
4. `run_tests` — ожидаем `success = true`.
5. При необходимости — рефакторинг, затем повторный запуск.

### Сценарий 4: Полный прогон перед коммитом

**Шаги:**

1. `build_project` — чистая сборка.
2. `run_tests` с `scope: "all"` — все тесты проекта.
3. При любых падениях — исправить перед коммитом.
4. `check_syntax` — финальная проверка (опционально, но рекомендуется).

## Интерпретация результатов

| Поле | Значение | Действие |
|------|----------|----------|
| `success` | `true` | Все тесты пройдены. |
| `success` | `false` | Есть падения — анализировать `errors`. |
| `total` | N | Всего тестов. |
| `passed` | N | Успешных. |
| `failed` | N | Провалившихся. |
| `errors` | `[{module, test, message}]` | Детали каждого падения. |
| `duration` | ms | Время выполнения. |

## MCP-инструменты

| Инструмент | MCP-сервер | Назначение |
|------------|------------|------------|
| `run_tests` | test-runner | Запуск тестов YaxUnit |
| `build_project` | test-runner | Сборка перед тестами (чистый билд) |
| `navigate_symbol` | lsp-bridge | Переход к падающему тесту и тестируемому коду |
| `check_syntax` | test-runner | Проверка синтаксиса перед/после изменений |

## Типичные ошибки и обходные пути

| Ошибка | Обходной путь |
|--------|---------------|
| Ошибка сборки перед тестами | Сначала `build_project`; при ошибках сборки — `check_syntax`, исправить компиляционные ошибки. |
| `run_tests` недоступен | Capability зависит от test-runner; зафиксировать причину пропуска, сообщить пользователю. |
| Модуль не найден | Проверить имя модуля (`scope`); убедиться, что тесты находятся в корректном sourceSet. |
| Тесты «падают» из-за данных ИБ | Тесты могут зависеть от тестовых данных; уточнить у пользователя настройки ИБ; при необходимости использовать отдельную тестовую ИБ. |
| Долгое выполнение всех тестов | Запускать тесты конкретного модуля (`scope: "ИмяМодуля"`) при итеративной разработке. |
| Падение не воспроизводится | Проверить порядок тестов, изоляцию; использовать `run_tests` с узким scope для воспроизведения. |
