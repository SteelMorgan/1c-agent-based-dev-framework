# Промпты волн консилиума и шаблон verdict.md (TD 4.1, 5, 3.5)

Промпты волн участников строит ядро `consilium.py` из шаблонов ниже. Модератор
(primary agent) владеет дайджестами, синтезом и вердиктом — их шаблоны в разделе
«Промпты модератора». Ядро контролирует формальные инварианты (digest-гейт, lint,
kill-защита).

## Общая инструкция структурированного хода (добавляется к каждому промпту участника)

````
В конце ответа ОБЯЗАТЕЛЬНО приложи fenced-блок структурированного хода:
```consilium-structured
{"elements": ["E1", "E2"], "new_findings": [{"id": "F-01", "text": "..."}],
 "position_changes": [{"element": "E1 | M#:E1", "action": "agree|disagree|refine|withdraw", "refs": [1]}],
 "borrowed": [{"element": "E3", "source_ref": 2}],
 "risk_checklist_responses": [{"item_id": "<id пункта>", "verdict": "hit|clear|na", "note": "<текст>"}]}
```
- elements: стабильные id элементов твоей текущей модели;
- position_changes: по пунктам; чужие элементы адресуются как <anon_id>:<element>;
- borrowed: только с разрешимым source_ref на запись-источника (антинакрутка);
- risk_checklist_responses (CONS-03): ответы на ВСЕ применимые к этому типу хода пункты
  риск-чеклиста твоей роли; verdict строго lowercase hit|clear|na; для hit и na note
  обязателен (непустой после trim, не "-", >=3 символов); для clear note не нужен.
````

## Блок роли домена (CONS-03 E-3, в промпты proposal/attack/response/redteam/confirmation)

Блок роли вставляется КОДОМ (`consilium.py::_build_prompt` + `_role_block`) во ВСЕ
шаблоны волн фаз A/B/D (в confirmation/redteam — роль фазы D по кросс-ротации) —
статический текст шаблонов ниже его не дублирует:

```
Твоя роль: <title>. Линза: <lens>
Риск-чеклист домена (ответь по КАЖДОМУ пункту в structured.risk_checklist_responses):
- [<item_id>] <текст пункта>
Evidence: <evidence_requirements домена>.
```

Промпты модератора (дайджест, синтез, вердикт) НЕ меняются.

## Фаза A — proposal (1 ход на участника, вслепую)

```
Архитектурный вопрос консилиума:
<question>

Твоя роль на фазу A: <role>.
Фаза A (дивергенция): выдвинь свою версию решения независимо и вслепую —
без оглядки на чужие позиции.
<structured instruction>
```

## Промпты модератора (дайджест, синтез, вердикт)

Эти тексты авторит модератор (primary agent), не ядро. Ниже — рабочие шаблоны;
формальные инварианты проверяет ядро fail-closed.

### Дайджест волны (фазы B и D, каждая волна после первой)

Дайджест — единственное, что участник получает о чужих ходах помимо анонимизированного
bundle (NFR-02). Требования, проверяемые ядром (`lint_digest`): без реальных id
участников (только anon_id вида `M1`, `M2`) и в пределах `context_budget` участника.
Требования по существу (не проверяются ядром, обязанность модератора):

```
Состояние полемики после <волны>:

Живые модели: <anon_id списком; замороженные unresponsive — с пометкой>.

По каждой живой модели (только anon_id, без авторства):
- <M#>: суть позиции в 2-3 предложениях; элементы, пережившие критику; элементы,
  снятые/опровергнутые; заимствования (с source_ref).

Ключевые развилки раунда:
- <по каким элементам позиции реально расходятся, а не пересказ всех атак>.

Открытые findings раунда: <F-идентификаторы и суть, без атрибуции>.
```

- Сжимайте, не пересказывайте: дайджест — карта полемики, а не конспект transcript.
- Не давайте оценок «сильная/слабая модель» — kill-критерий детерминирован, суждение
  модератора в выдачу участникам не входит (защита от якорения).
- Анонимизируйте автора, но сохраняйте адресуемость: участник должен понимать, какие
  атаки относятся к его модели, и уметь ссылаться на чужие элементы как `<M#>:<E#>`.

### Синтез фазы C (`--synthesis-file`)

```
# Синтез модератора

<итоговая модель: каждый элемент — с traceability на источник: seq:<n> записи
transcript, откуда взят элемент>

Обоснование выбора между расходящимися позициями: <почему взяты именно эти
элементы живых моделей, какие аргументы полемики перевесили>.

Не вошло в склейку: <элементы живых моделей, отвергнутые синтезом, с seq-ссылкой
и одной строкой причины — это сырьё minority report>.
```

- Traceability `seq:<n>` обязательна для каждого элемента (FR-05); ядро записывает
  синтез как ход модератора в transcript.
- Модератор склеивает из живых моделей и не вводит новых элементов «от себя» —
  собственное мнение оформляется только участием через свой адаптер (FR-05).

### Вердикт фазы E (`--decision-file`)

Собирается из синтеза фазы C + материалов transcript по шаблону verdict.md ниже;
ядро проверяет обязательные разделы fail-closed. Minority report ядро вставляет
дословно из transcript — модератору редактирование запрещено (FR-03b/FR-05).

## Формат синтеза модератора (CONS-02 OPT-3, обязателен)

Синтез (фаза C) — список маркированных элементов строго по шаблону
`- [E<n>] <текст> (refs: seq:<n>, seq:<m>)` + секция обоснования исключения вкладов:

```markdown
# Синтез

- [E1] разделение ядра и доменов (refs: seq:2, seq:5)
- [E3] транспорт через события (refs: seq:3)

## Обоснование исключения вкладов

Вклад <модель> не вошёл: <почему каждый невошедший живой вклад исключён>.
```

- ≥1 элемента; диапазоны `seq:2-4` запрещены (только перечисление через запятую);
  любая непустая строка вне шаблона элемента и вне секций (заголовок; секция
  обоснования исключения вкладов) — ядро отклоняет синтез fail-closed;
- условная фаза D: ядро пропускает ред-тим, только если все элементы трассируются
  к единственной живой активной модели-источнику (membership: id элемента ∈
  structured.elements referenced-записи); любая неопределённость (неразрешимый ref,
  ref на запись модератора, источник unresponsive/killed, ≥2 источника) → фаза D
  выполняется.

## Шаблон verdict.md (обязательные разделы, TD 3.5 — ядро проверяет fail-closed)

```markdown
# Вердикт консилиума <session_id>

Вопрос: <question>

## Решение
<синтез модератора с traceability: каждый элемент ссылается на seq:<n> модели-источника>

## Kill-log (FR-03c)
| участник | раунд | survived | borrowed_in | upheld_against | tie-break |

## Minority report (FR-03b/FR-05, дословно)
<дословные тексты несогласных и финальные заявления исключённых — ТОЛЬКО из transcript;
редактирование модератором запрещено, ядро вставляет тексты записей дословно>

## Флаг состава (FR-06)
<кворум выполнен/деградировал; предупреждение при однородности family>

## Инциденты (FR-11)
<unresponsive-участники, retry, таймауты>

## Стоимость (NFR-01)
<фактические вызовы адаптеров vs диапазон 16–25 default, потолок 31>

## Завершение фазы B
<стоп-условие: converged | round_limit | stalemate | invocation_ceiling>

## Фаза D
<выполнена | пропущена (CONS-02 OPT-3): причина — модель-источник, число элементов,
сэкономленные вызовы>

## Эскалация
<ESCALATE_TO_HUMAN при material-разногласии, иначе «нет»>

---
Advisory-only: вердикт не является acceptance/finalization gate (FR-13).
```
