# Плейбук модератора: human-critic режим (CONS-06, E12)

Режим включается при `convene --human-critic` (по умолчанию выключен). Человек
равноправно участвует ТОЛЬКО в атакующих волнах (attack фазы B, redteam фазы D):
он не выдвигает модели, не отвечает на критику, не входит в кворум, track-record
и kill-метрики. Для LLM-участников человек — обычный anon_id (`M#`) из общего
пространства `create_anon_map`; человеческое авторство не раскрывается нигде.

## Цикл одной атакующей волны

1. **Ядро встаёт в awaiting_human.** На pending волне attack (B) / redteam (D)
   `round <id>` без turn-файла НЕ запускает LLM-волну (антиякорение: человек
   ходит, не видя атак LLM текущей волны). Состояние видно в `status` и `watch`.
2. **Покажите человеку bundle дословно.** Источник для критики — анонимизированный
   bundle текущей атаки: после фазы A это `bundles/wave-*.bundle.md` (позиции),
   в фазе D — синтез модератора из transcript (запись `synthesis`). Bundle
   показывается человеку как есть, без ваших оценок и без подсказок, кто автор.
3. **Соберите критику в turn-файл** (см. схему ниже). Structured-блок
   заполняется МЕХАНИЧЕСКИ по словам человека; пробелы в его ответе закрывайте
   ВОПРОСАМИ к человеку («по какому элементу?», «disagree или refine?»),
   а не дописыванием от себя. Модератор не соавтор критики.
4. **Проставьте `human_approved: true`** — это подтверждение модератора, что
   текст дословно транскрибирует критику человека (audit-функция, а не
   удостоверение личности: ядро фиксирует аттестацию в transcript; явно ложная
   аттестация становится подотчётной).
5. **Подайте ход:** `round <id> --digest-file <digest> --human-turn-file <path>`.
   Ядро запишет ход первым и запустит LLM-волну — ход человека попадёт в bundle
   участников этой волны, на него отвечают наравне с атаками моделей.

## Схема turn-файла

```json
{
  "content": "<дословный текст критики человека>",
  "structured": {
    "elements": [],
    "new_findings": [{"id": "F-01", "text": "..."}],
    "position_changes": [{"element": "M2:E3", "action": "disagree", "refs": [9]}],
    "borrowed": [],
    "risk_checklist_responses": []
  },
  "refs": [9],
  "human_approved": true
}
```

- `content` — обязателен (непустой); критика адресует чужие элементы как
  `<anon_id>:<element>` (только anon_id, никогда реальные id).
- `structured` — объект; пустые разделы допустимы. Чеклист роли человек не
  заполняет (у него нет роли).
- `human_approved: true` — обязательная аттестация; без неё ядро отклоняет файл
  (fail-closed).
- В `content` и `structured` запрещены внутренние идентификаторы: реальные id
  участников и служебный id записи человека (`human-critic`) — lint отклоняет
  файл. Разрешены любые обычные слова (широкого маркерного словаря нет).
- `--human-keep-raw` — forensic-опция: сохранить исходный файл в каталоге
  сессии (`human/turn-<seq>.json`); по умолчанию raw-файл не копируется.

## Ожидание, кап и решения модератора

Ожидание human-хода останавливает wall-clock бюджет сессии
(`wall_clock.paused_sec`; `status` показывает `awaiting_human`,
`paused_total_sec`, `real_elapsed_sec`, `active_elapsed_sec`). По достижении
капа (`--human-wait-cap-sec`, default 1800) сессия переходит в
`awaiting_moderator_decision`: `round` отказывает, пока вы явно не подадите
одно из (каждое — system-запись в transcript):

- `--human-continue-wait` — новый ограниченный интервал ожидания;
- `--human-skip-wave` — человек пропускает ТОЛЬКО текущую волну (одноразово);
- `--human-withdraw --reason "..."` — режим сворачивается, сессия продолжается
  без человека до конца;
- `--human-turn-file` — ход всё-таки пришёл.

Молчаливого продолжения нет. Если человек сделал ≥1 ход в фазе B, фаза D
обязательна (предикат пропуска отменяется, причина фиксируется в transcript).

## Запреты

- **Не раскрывайте авторство.** В дайджестах, bundle и разговоре с участниками
  ход человека — ход anon_id. Запрещены: «человек сказал», «наш human-critic»,
  любые пометки происхождения вклада. Digest-lint отклоняет служебный id
  `human-critic`, но защита от стилистических намёков — на модераторе.
- **Не маркируйте human-вклады в дайджестах** (даже нейтрально: «пункт M4
  добавлен позже») — это деанонимизация по времени.
- **Не дописывайте критику от себя** — ваш конфликт интересов подотчётен через
  аттестацию, но не устранён; транскрибируйте дословно.

## Остаточные риски (декларируются, не закрываются)

- **Инъекция содержания (F-25):** текст human-хода попадает в контекст всех
  участников без семантической фильтрации; lint проверяет идентификаторы, не
  намерение. Ответственность за содержимое — на транскрибирующем модераторе:
  инструкции вида «игнорируй протокол» в turn-файл не переносите.
- **Семантическая деанонимизация не гарантируется:** стабильный anon_id защищает
  от прямого раскрытия, но число ходов, стиль и тайминги могут выдать человека.
- **Kill-метрики:** human-критика не засчитывается в upheld/metrics (политика 2,
  E4); влияние на kill — только через суверенный withdraw модели по её
  собственному решению.
