# Итеративное ревью через Codex CLI

## Когда применять

| Триггер | Действие |
|---------|----------|
| Запрос ревью | Запустить итеративное ревью через Codex CLI |
| «второе мнение» | Предложить `/review-gpt` или `/review-all` |
| Сложная архитектура, > 5 файлов | Рекомендовать ревью |
| Перед реализацией спецификации | Предложить ревью плана |

---

## Протокол итеративного ревью

Ревью — диалог между агентом (Claude) и ревьювером (Codex). Максимум **5 итераций**.

### Итерация 1 — первичный запрос

**Ревью артефакта:**

```
1. Задача — какая бизнес-цель стояла, контекст
2. Артефакт — пути к файлам
3. Правила — навыки и правила, которые должны были быть использованы при создании
```

**Второе мнение (произвольный вопрос):**

```
1. Артефакт — пути или текст
2. Вопрос — что именно оценить
3. Контекст — релевантные правила проекта (на усмотрение агента)
```

В начало промпта добавлять:
```
IMPORTANT: Do NOT create, modify, or delete any project files. You may only READ files for analysis. Your final text response will be captured automatically.
```

Отправить Codex в фоне, дождаться ответа.

### Итерация 2 — верификация и комментарии

1. **Прочитать ответ Codex**
2. **Присвоить каждому замечанию ID** (F-01, F-02, ...)
3. **Верифицировать** каждое замечание против реального кода/артефакта:

| Статус | Значение |
|--------|----------|
| `agree` | Подтверждено проверкой |
| `partial` | Частично верно, требует уточнения |
| `disagree` | Опровергнуто (указать файл:строка + факт) |
| `withdrawn` | Codex сам отозвал в следующей итерации |
| `out_of_scope` | Вне scope текущего ревью |

4. **Добавить свои замечания** (ID: C-01, C-02, ...) — то, что Codex пропустил
5. **Сформировать follow-up** (см. «Формат follow-up»)
6. **Сообщить пользователю прогресс:** `Раунд 2/5: N согласованы, M спорные`
7. **Отправить Codex**

### Итерации 3-5 — сближение

Тот же цикл верификации. Дополнительные правила:

- **Заморозка scope:** начиная с итерации 3, новые замечания допускаются только если уровень BLOCK/WARN и есть проверяемая улика
- **Стилистика не обсуждается:** замечания INFO/style принимаются к сведению без итераций
- **Прогресс пользователю** после каждой итерации

### Завершение

| Условие | Действие |
|---------|----------|
| **Консенсус** — все пункты `agree`/`withdrawn` | Завершить |
| **Тупик** — `unresolved` не изменились 2 цикла подряд | Завершить, показать обе позиции |
| **Лимит** — 5 итераций | Завершить с текущим состоянием |

### Финал — отчёт пользователю

```
Единое мнение: [согласованные замечания]
Расхождения: [позиция Claude vs позиция Codex] (если есть)
Итерации: N из 5
Рекомендация: [что делать]
```

## Формат follow-up промпта

```markdown
# Review Follow-up (Round N)

## Согласованные (закрыты)
- F-01: [краткое описание] → agree
- F-03: [краткое описание] → withdrawn

## Спорные (обсуждаем)

### F-02
Твоё замечание: [суть]
Мой статус: disagree
Мои аргументы: в <файл:строка> код делает <факт>, что соответствует спецификации <цитата>
Вопрос: пересмотри или приведи контраргумент с конкретной ссылкой на код

### F-04
Твоё замечание: [суть]
Мой статус: partial
Мои аргументы: [что верно, что нет]

## Мои дополнения
- C-01: [новое замечание + файл:строка + обоснование]

## Правила обсуждения
- Обсуждай только перечисленные ID
- Не возвращайся к закрытым пунктам
- Новые замечания — только BLOCK/WARN с уликой
- По каждому спорному: KEEP / REVISE / WITHDRAW + обоснование
```

## Формирование первичного промпта

Полный шаблон: [references/prompt-template.md](references/prompt-template.md).

**Блок 1 — Задача:** что проверяем и зачем (2-5 предложений).

**Блок 2 — Артефакт:** пути к файлам (ревьювер читает сам).

**Блок 3 — Правила:** пути к навыкам по типу артефакта:

| Тип | Навыки |
|-----|--------|
| Код BSL | `coding-standards`, `error-handling`, `query-patterns`, `ssl-patterns`, `form-patterns` |
| Спецификация | `spec-standard` |
| Форма (UI) | `form-patterns`, `form-visual-requirements` |
| Архитектура | `ssl-patterns`, `query-patterns`, `coding-standards` |
| Тесты | `coding-standards`, `error-handling` |

Пути: `framework/skills/bsl-practices/<name>/SKILL.md`

## Запуск Codex

### Определить режим

```bash
if [[ "${CUSTOM_CODEX_ENABLED:-0}" == "1" ]]; then
  echo "custom"
else
  echo "default"
fi
```

### Default

```bash
RESULT_FILE=$(mktemp /tmp/codex-review-XXXXXX.txt)
codex exec \
  -m gpt-5.4 \
  -c 'model_reasoning_effort="high"' \
  --dangerously-bypass-approvals-and-sandbox \
  --ephemeral \
  -o "$RESULT_FILE" \
  - < /tmp/codex-prompt.txt
```

### Custom

```bash
RESULT_FILE=$(mktemp /tmp/codex-review-XXXXXX.txt)
codex exec \
  -p cx_gpt-5_3-codex-high \
  --dangerously-bypass-approvals-and-sandbox \
  --ephemeral \
  -o "$RESULT_FILE" \
  - < /tmp/codex-prompt.txt
```

Запускать в фоне (`run_in_background: true`). Результат: `Read(RESULT_FILE)`.

## Обработка ошибок

| Ситуация | Действие |
|----------|----------|
| `Invalid JSON body` | Передать промпт через файл |
| Codex CLI не установлен | `npm install -g @openai/codex` |
| Auth failure | `codex login`; custom → проверить `config.toml` |
| Rate limit / 429 | Подождать 30-60 сек, повторить |
| Non-zero exit, файл не создан | Показать stderr; проверить cwd, пути, модель |
| Файл `-o` пуст | Взять последнее сообщение из `TaskOutput` |
