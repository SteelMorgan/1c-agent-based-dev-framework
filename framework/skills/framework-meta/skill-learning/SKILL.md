# Накопление знаний (Skill Learning) — процедура

> Тело вынесено из правила `skill-learning-policy`. Триггер «после цикла ≥2 итераций» остаётся в правиле; здесь — процедура ретроспективы, формат записи и критерий выбора уровня/файла.

> Агент учится на своих итерациях: что работает (приёмы) и что ломается (антиприёмы).
> Знания записываются в `references/learned-patterns.md` навыка-владельца.

## Два уровня знаний

| Уровень | Файл | Что хранит |
|---------|------|------------|
| Универсальный | `skill/references/learned-patterns.md` | Приёмы, работающие в любой конфигурации 1С |
| Проектный | `{project}/.context/learned-patterns.md` | Приёмы, привязанные к конкретной конфигурации / проекту |

**Критерий разделения:** если запись упоминает конкретный объект метаданных, имя формы, реквизит
или особенность конфигурации → проектный. Если описывает общий паттерн платформы/фреймворка → универсальный.

## Использование накопленных знаний

Триггер чтения («перед работой с навыком — прочитать его уроки») — в правиле `skill-learning-policy` (always-on). Здесь — раскладка по уровням:

- `references/learned-patterns.md` в каталоге навыка — универсальные приёмы;
- `{project}/.context/learned-patterns.md` — проектные приёмы.

Применяй `confirmed`-записи как дополнительные правила, `candidate` — как подсказки.

## Когда запускать

После завершения цикла работы, в котором было **≥2 итерации** (написал → ошибка → исправил → успех).
Если задача решена с первой попытки — ретроспектива не нужна.

## Процедура

1. **Восстановить цепочку итераций** — что сделал → что упало → как исправил → что прошло

2. **Для каждого нетривиального исправления** сформулировать запись:

```
status: candidate | confirmed
область: <свободная формулировка>
приём: <что делать — проверено успехом>
антиприём: <что НЕ делать — проверено падением>
почему: <что происходит при нарушении>
шаги: <конкретные шаги/код, если применимо>
источник: <задача, итерация>
```

Приём и антиприём — **одна запись**, две стороны одного открытия. Не дублировать.

3. **Отфильтровать** — исключить:
   - Опечатки и случайные синтаксические ошибки
   - Разовые сбои окружения

4. **Определить уровень и навык-владелец:**
   - Упоминает конкретный объект метаданных / конфигурацию → **проектный** → `{project}/.context/learned-patterns.md`
   - Общий паттерн платформы / фреймворка → **универсальный** → `references/learned-patterns.md` навыка-владельца
   - Навык-владелец: тот навык, к которому приём относится по содержанию.
     Путь к RU-версии: `.install-session.json` → `component_map` → `skill/{name}` → `ru_path`.

5. **Прочитать существующие записи** из целевого файла:
   - Аналогичный приём уже есть → не дублировать
   - Есть `candidate` с той же областью → повысить до `confirmed`

6. **Дописать** (append) запись в целевой файл.
   Если файла нет — создать. Не перезаписывать существующие записи.

## MUST

| Требование | Описание |
|------------|----------|
| Не менять тело навыка | Записи — только в `references/learned-patterns.md`, не в `SKILL.md` |
| Не дублировать | Перед записью прочитать существующие приёмы |
| Первый случай = candidate | Единичный случай получает `status: candidate` |
| Повторение = confirmed | При повторении аналогичной ситуации повысить до `confirmed` |
