# Макет из словесного описания

Преобразуй утвержденное описание табличного документа в согласуемый Excel-прототип без
Excel-свойств, которым не гарантирован эквивалент в MXL. Прототип задает представление, но
не доказывает корректность runtime-данных и не является готовым MXL-макетом.

## Когда применять

| Триггер | Действие |
|---|---|
| Источник истины — утвержденное словесное описание | Создать однолистовый `.xlsx` и спецификацию |
| Нужен визуальный прототип до реализации MXL | Использовать только закрытый whitelist |
| Прототип планируется передать в `layout-from-excel` | Выполнить предэкспортную проверку всех свойств |
| Найдено непереносимое Excel-свойство | Остановить маршрут и выполнить обязательную самокорректировку |

Не применяй этот навык к уже существующей Excel-книге как источнику истины: для нее сразу
используй `layout-from-excel`. Не применяй его вместо `layout-from-image`, если утвержденным
источником является изображение.

## Результат

Подготовь единый пакет согласования:

1. один `.xlsx` с ровно одним видимым листом;
2. `layout spec`: области, строки, колонки, объединения, ширины и высоты;
3. `border spec`: сегменты границ, стороны, стили и цвета;
4. `style spec`: заливки, шрифты, выравнивание, перенос и форматы;
5. `data-binding spec`: назначение статического текста и будущих runtime-параметров;
6. снимок структуры книги и чек-лист разрешенных/запрещенных свойств.

Явно пометь все значения-примеры как демонстрационные. Они показывают геометрию и формат,
но не заменяют data contract из `tabular-output-data-verification`.

Заполненный образец такой спецификации: `references/layout-spec-example.md`.

## Закрытый positive whitelist

Разрешай только перечисленные свойства. Любое отсутствующее свойство запрещено до отдельной
проверки и явного добавления вместе с MXL-эквивалентом.

| Разрешенное свойство Excel-прототипа | MXL-эквивалент |
|---|---|
| Один видимый лист | Один проектируемый табличный документ/макет |
| Обычные ячейки | Ячейки и области MXL |
| Статический текст и демонстрационные значения | Текст ячейки и параметры области |
| Строки и колонки | Сетка табличного документа |
| Объединения | Объединенные области ячеек |
| Явные ширины колонок и высоты строк | Ширины колонок и высоты строк MXL |
| Границы | Границы ячеек/областей MXL |
| Сплошные заливки | Цвет фона ячейки/области |
| Шрифт: семейство, размер, жирный, курсив, цвет | Оформление шрифта MXL |
| Горизонтальное и вертикальное выравнивание | Выравнивание ячейки/области MXL |
| Перенос текста | Перенос текста ячейки MXL |

### Разрешенные format code

Это закрытый перечень числовых и дата-временных отображений:

| Excel format code | Семантика | MXL-эквивалент |
|---|---|---|
| `0` | целое без разделителей | числовой параметр с `ЧДЦ=0` |
| `0.00` | число с двумя знаками | числовой параметр с `ЧДЦ=2` |
| `#,##0` | целое с группировкой тысяч | числовой параметр с `ЧГ=3,0;ЧДЦ=0` |
| `#,##0.00` | число с двумя знаками и группировкой | числовой параметр с `ЧГ=3,0;ЧДЦ=2` |
| `dd.mm.yyyy` | календарная дата | текстовый параметр, заранее форматированный как `dd.MM.yyyy` |
| `dd.mm.yyyy hh:mm` | дата и минуты | текстовый параметр, заранее форматированный как `dd.MM.yyyy HH:mm` |

Переноси дату и дату-время как подготовленный текст. Не обещай перенос Excel type/locale
semantics. Запрещай проценты, валютные символы, научную нотацию, дроби, пользовательские
маски и любой иной format code, пока доказанная проверка не добавит его в whitelist вместе
с точным MXL-эквивалентом.

## Безусловно запрещенные свойства

Не допускай в прототипе:

- несколько листов;
- формулы и бизнес-логику;
- сводные таблицы;
- макросы и VBA;
- внешние связи и запросы;
- Power Query и модель данных;
- фильтры и срезы;
- закрепление областей;
- заданную область печати;
- условное форматирование;
- диаграммы;
- изображения, фигуры и иные свободные графические объекты;
- защиту листа или книги;
- скрытые строки, колонки или листы;
- именованные диапазоны как носитель логики;
- Excel-таблицы и иные Excel-специфичные интерактивные возможности.

## Порядок работы

1. Зафиксируй утвержденное словесное описание как источник истины. Не достраивай молча
   отсутствующие визуальные или смысловые требования.
2. Разложи описание на `layout/border/style/data-binding` спецификацию.
3. Создай `.xlsx` с одним видимым листом, используя только закрытый whitelist. Для каждого
   свойства зафиксируй MXL-эквивалент в спецификации.
4. Пометь демонстрационные данные и отдели их от будущих runtime-источников.
5. Выполни структурную предэкспортную проверку книги: листы, ячейки, размеры, объединения,
   стили, format code и отсутствие всех запрещенных классов.
6. Получи утверждение прототипа и спецификации.
7. Пройди `tabular-output-data-verification`. Проверку данных можно вести параллельно с
   согласованием прототипа, но она обязана завершиться до runtime-компоновки или ручного вывода.
8. При необходимости структурного переноса передай утвержденный файл в `layout-from-excel`,
   затем реализуй визуальный слой через `mxl-layout-patterns`.
9. Передай реализованный макет последующему потребителю: `skd-report-patterns` вместе со
   `skd-custom-layout` либо `print-form-patterns`.

Сквозная последовательность:

```text
словесное описание
  -> layout-from-description
  -> утверждение прототипа и спецификации
  -> tabular-output-data-verification
  -> layout-from-excel (если нужен структурный перенос)
  -> mxl-layout-patterns
  -> skd-report-patterns + skd-custom-layout ИЛИ print-form-patterns
```

## Обязательная самокорректировка

Если при генерации или предэкспорте найдено уже использованное Excel-свойство без
переносимого MXL-эквивалента:

1. Немедленно останови `layout-from-excel`, генерацию MXL и любой другой зависимый маршрут.
2. Сначала обнови русскоязычный канонический источник этого навыка: добавь или усили запрет
   класса свойств и зафиксируй причину непереносимости. Если навык имеет языковые зеркала,
   синхронизируй их штатным механизмом до продолжения.
3. Замени свойство в прототипе доказанным MXL-эквивалентом из whitelist либо убери его.
4. Обнови `layout/border/style/data-binding` спецификацию.
5. Перегенерируй MXL-совместимый прототип и повтори полную структурную проверку.
6. Продолжай перенос только после нового `PASS`.

Никогда не принимай известную потерю Excel-only свойства как допустимый тихий downgrade.
Если эквивалент не доказан, свойство остается запрещенным.

## Правильно и неправильно

Правильно:

```text
Ячейка: демонстрационное число 1234.50
Excel format code: #,##0.00
MXL: числовой параметр с ЧГ=3,0;ЧДЦ=2
```

Неправильно:

```text
Ячейка: =SUM(B2:B10)
Назначение: вычислить итог внутри Excel-прототипа
```

Формула переносит бизнес-логику в Excel и не имеет места в MXL-совместимом прототипе.
Итог должен приходить из проверенного data contract, а прототип задает только его отображение.

## Чек-лист приемки

- [ ] Источник истины — утвержденное словесное описание.
- [ ] Книга сохранена как `.xlsx` и содержит ровно один видимый лист.
- [ ] Использованы только свойства закрытого whitelist.
- [ ] Каждый format code входит в таблицу из шести разрешенных вариантов.
- [ ] Каждое свойство имеет зафиксированный MXL-эквивалент.
- [ ] Все запрещенные классы проверены и отсутствуют.
- [ ] Демонстрационные значения явно отделены от runtime data-binding.
- [ ] Приложены снимок структуры и чек-лист свойств.
- [ ] При обнаружении непереносимого свойства выполнена самокорректировка и повторная проверка.
- [ ] `tabular-output-data-verification` завершен до runtime-вывода.
