# Пример `layout/border/style/data-binding` спецификации

Обобщённый образец того, как выглядит готовая спецификация печатной формы
документа с одной табличной частью. Имена областей и параметров — пример;
структура разделов повторяет реальный проверенный макет.

## Layout spec

Базовая сетка:

- страница: `A4-portrait`;
- колонок: `12`;
- таблица и блоки реквизитов сидят в одной общей сетке, чтобы границы не
  плыли между секциями.

Области:

1. `Заголовок`
   - две строки;
   - строка 1: заголовок документа на всю ширину;
   - строка 2: номер и дата документа без времени.
2. `Реквизиты`
   - заголовок секции и несколько строк данных;
   - компактные строки `label + value` по два поля в строке;
   - полноширинные строки для длинных значений (договор, источник),
     чтобы текст не обрезался.
3. `ШапкаТаблицы`
   - одна строка;
   - колонки: `№`, `Наименование`, `Количество`, `Курс, <валюта>`,
     `Сумма, <валюта>`;
   - код валюты подставляется в денежные заголовки из данных документа.
4. `Строка`
   - повторяемая строка;
   - одна область на одну запись табличной части.
5. `Итого`
   - одна строка с текстом итога, кодом валюты и суммой.
6. `Подписи`
   - заголовок секции;
   - роли подписантов;
   - отдельные незаполненные линии для собственноручных подписей;
   - ФИО под линиями как расшифровка.

## Border spec

- `Реквизиты`: у каждой label/value-ячейки замкнутый прямоугольный бордер
  `all`, приглушённый цвет; заголовок секции без рамки.
- `ШапкаТаблицы`: замкнутые границы `all`, более контрастный цвет.
- `Строка`: у каждой ячейки `all`, цвет чуть светлее шапки.
- `Итого`:
  - левый блок: `top,bottom,left`;
  - валюта: только `top,bottom`;
  - сумма: `all`.
- `Подписи`: у незаполненной строки только `bottom`; линии разделены
  свободными колонками и не сливаются между сторонами.

## Style spec

- заголовок: крупный bold, тёмно-синий текст, по центру;
- подзаголовок: мелкий серо-синий, по центру;
- label в реквизитах: мелкий bold на светлом фоне;
- шапка таблицы: bold на акцентном светлом фоне;
- строки таблицы: обычный мелкий шрифт;
- числовые колонки: вправо, точность по реквизиту документа
  (количество `ЧДЦ=8`, суммы `ЧДЦ=2`);
- итог: акцентный фон, жирный;
- подписи: без заливки, роли полужирным серым; нижняя граница только у
  линии подписи, ФИО под ней;
- высоты строк не ниже текста соответствующего шрифта;
- длинные значения реквизитов переносятся и не выходят за ячейки.

## Data-binding spec

`Заголовок`: `ЗаголовокДокумента`, `НомерДокумента`, `ДатаДокумента`.

`Реквизиты`: `Аккаунт`, `Договор`, `ТипПортфеля`, `ВалютаОценкиПортфеля`,
`ИсточникСоздания`, `ВнешнийID`.

`ШапкаТаблицы`: `ВалютаКурса`, `ВалютаСуммы`.

`Строка`: `НомерСтроки`, `Монета`, `Количество`, `КурсКВалютеОценки`,
`СуммаВВалютеОценки`.

`Итого`: `ВалютаИтога`, `ИтоговаяСумма`.

`Подписи`: `Управляющий`, `Клиент`, `Операционист`.

## Negative checks (проверено на реальном макете)

- печатная форма не использует СКД: нет `DataCompositionSchema`,
  `КомпоновщикМакетаКомпоновкиДанных`, `ПроцессорКомпоновкиДанных`;
- строки таблицы повторяются циклом по данным, а не фиксированной сеткой;
- блок подписей без общей рамки и боковых границ; нижняя граница только у
  трёх отдельных линий;
- дата без времени;
- длинные значения читаются полностью;
- код валюты присутствует в денежных заголовках.
