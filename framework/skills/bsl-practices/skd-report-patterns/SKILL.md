# СКД-отчеты

## Назначение

Используй этот навык для СКД как механизма данных и компоновки:

- наборы данных;
- связи наборов;
- поля;
- вычисляемые поля;
- ресурсы;
- параметры;
- настройки;
- варианты;
- отборы;
- сортировки;
- группировки;
- программное формирование результата.

Если отчет использует собственные области вкладки `Макеты`, дополнительно используй `skd-custom-layout`.

## Базовая цепочка

Типовая программная цепочка:

```bsl
Настройки = КомпоновщикНастроек.ПолучитьНастройки();
КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
МакетКомпоновки = КомпоновщикМакета.Выполнить(СхемаКомпоновкиДанных, Настройки, ДанныеРасшифровки);

ПроцессорКомпоновки = Новый ПроцессорКомпоновкиДанных;
ПроцессорКомпоновки.Инициализировать(МакетКомпоновки, ВнешниеНаборыДанных, ДанныеРасшифровки);

ПроцессорВывода = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
ПроцессорВывода.УстановитьДокумент(ДокументРезультат);
ПроцессорВывода.Вывести(ПроцессорКомпоновки);
```

Платформенный граф:

```text
СхемаКомпоновкиДанных
  -> ИсточникДоступныхНастроекКомпоновкиДанных
  -> КомпоновщикНастроекКомпоновкиДанных
      -> НастройкиКомпоновкиДанных
          -> КомпоновщикМакетаКомпоновкиДанных.Выполнить()
              -> МакетКомпоновкиДанных
                  -> ПроцессорКомпоновкиДанных.Инициализировать()
                      -> ЭлементРезультатаКомпоновкиДанных*
                          -> ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент
                              -> ТабличныйДокумент
```

`ДанныеРасшифровкиКомпоновкиДанных` передаются в построение макета, процессор компоновки и форму результата. Внешние наборы данных передаются в `ПроцессорКомпоновкиДанных.Инициализировать()`.

Для поэлементного вывода используй `НачатьВывод()`, цикл `ПроцессорКомпоновки.Следующий()`, `ВывестиЭлемент()` и `ЗакончитьВывод()`. Такой режим нужен, когда требуется вмешаться в элемент результата до вывода.

## Возможности СКД

Наборы данных:

- `DataSetQuery` получает данные запросом 1С. Используй, когда данные можно выразить запросом и нужны стандартные отборы, параметры и оптимизация платформы.
- `DataSetObject` описывает внешний набор. Данные передаются кодом через структуру внешних наборов при инициализации процессора компоновки.
- `DataSetUnion` объединяет несколько наборов с общей структурой полей в один логический поток.

Связи наборов данных применяй для master-detail, ограничения набора-приемника параметром и связывания query/object-наборов. Проверяй, что параметр связи реально используется в запросе приемника; для операции `В` должен быть разрешен список параметров.

Вычисляемые поля используй для легких производных значений, которые должны участвовать в настройках, отборах, сортировках или ресурсах. Тяжелые алгоритмы и обращения к данным выноси в запрос или подготовку внешнего набора.

Ресурсы отвечают за агрегирование. Не подменяй ресурсом исходное поле: исходное поле хранит детальные значения, ресурс задает итоговое выражение и группировки.

Если значение должно выводиться на уровне группировки или итога, не тяните в grouped-узел "сырое"
поле как будто оно уже агрегировано. Для такого уровня явно задавай ресурс или вычисляемое поле с
агрегатной функцией, иначе схема может формально собраться, но упасть на runtime-формировании из-за
некорректного использования поля в группировке.

Параметры делятся по назначению:

- параметры запроса;
- пользовательские параметры данных;
- параметры с доступным списком значений;
- скрытые служебные параметры;
- параметры функциональных опций;
- производные параметры периода.

`Авто` подходит для параметров, включаемых по фактическому использованию. `Всегда` нужен для обязательных параметров запроса или доступности полей.

Вариант настроек фиксирует прикладной сценарий вывода. Пользовательские настройки накладываются поверх варианта, фиксированные настройки применяются дополнительно через компоновщик.

Основные элементы структуры вывода: группировка, таблица, диаграмма, вложенный отчет и детальные записи. При собственных макетах элементы структуры связываются с областями через `groupTemplates`; при стандартном выводе области результата строит платформа.

## XML-карта

`СхемаКомпоновкиДанных` обычно находится в `Templates/<ИмяСКД>/Ext/Template.xml`.

Типовые XML-разделы:

- `<dataSet>` — наборы данных;
- `<dataSetLink>` — связи наборов;
- `<calculatedField>` — вычисляемые поля;
- `<totalField>` — ресурсы;
- `<parameter>` верхнего уровня — параметры схемы;
- `<settingsVariant>` и `dcsset:*` — варианты и настройки;
- `<template>` и `<groupTemplate>` — собственные области СКД-макета.

Для анализа XML используй `xml-gen skd info`, а не ручной разбор. Если runtime ломается при формально валидном XML, сравни структуру с минимальным штатно открывающимся эталоном и зафиксируй дефект генерации в процессе работы с xml-gen.

## Что проверять

- Набор данных существует и возвращает нужные поля.
- Поля, ресурсы и вычисляемые поля доступны в настройках.
- Параметры имеют корректные значения и типы.
- Структура варианта соответствует требуемому выводу.
- Отборы и сортировки описаны средствами СКД, если это часть отчета.
- Внешние object-наборы передаются под теми именами, которые ожидает схема.
- Runtime-результат получен на платформе, а не только сгенерирован XML.
- Если у внешнего отчета нет собственной пользовательской формы, runtime-проверка идет через
  стандартную форму отчета и штатную команду формирования.

## Инструменты

```bash
xml-gen skd info <Template.xml> --mode overview
xml-gen skd info <Template.xml> --mode fields
xml-gen skd info <Template.xml> --mode resources
xml-gen skd info <Template.xml> --mode params
xml-gen skd info <Template.xml> --mode variant --name <Вариант>
xml-gen validate --type skd <Template.xml>
```

Для создания схемы используй `skd-dsl`. Для точечных правок существующей схемы используй `skd-edit`.
