# Learned Patterns — query-patterns

Проверенные приёмы и антиприёмы, накопленные из реальных задач.
`confirmed` — подтверждённое правило, `candidate` — требует повторного подтверждения.

---

```
status: candidate
область: алиасы колонок в SELECT-строке запроса 1С
антиприём: НЕ давать полю в SELECT алиас, совпадающий с зарезервированным словом языка
           запросов (ЕСТЬ, ДАТА, ЗНАЧЕНИЕ и т.п.). Такой алиас ломает компиляцию запроса
           с ошибкой «Ожидается имя» — ПРИЧЁМ позиция ошибки указывает на сам алиас,
           а не на выражение поля перед ним, из-за чего диагностика по позиции курсора
           легко уводит в сторону (правят выражение, а не имя).
приём: при ошибке «Ожидается имя» в строке SELECT сначала проверить алиас поля (КАК Имя)
       на коллизию с зарезервированным словом языка запросов, и только потом —
       выражение самого поля. Чинить переименованием алиаса, а не заменой литерала
       или перестановкой выражения.
почему: парсер языка запросов резервирует служебные слова (в т.ч. используемые в
        конструкциях ЕСТЬ NULL, ДАТАВРЕМЯ и др.) и не позволяет использовать их как
        свободный идентификатор алиаса, даже когда по смыслу это обычное поле.
источник: реальная задача (2026-07), developer-code: `ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА КАК Есть`
          падал на ошибке «Ожидается имя» из-за алиаса `Есть` (коллизия с ЕСТЬ NULL);
          фикс — переименование алиаса в `ЕстьЗапись`.
```
