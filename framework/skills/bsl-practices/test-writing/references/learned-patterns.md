# Learned Patterns — test-writing

Проверенные приёмы и антиприёмы, накопленные из реальных задач.
`confirmed` — подтверждённое правило, `candidate` — требует повторного подтверждения.

---

```
status: confirmed
область: серверные YaxUnit-тесты с записью в БД
приём: Пишущий серверный набор всегда регистрируется с .ВТранзакции() сразу после
       ДобавитьТестовыйНабор(). Рантайм ищет настройку по иерархии Тест→Набор→Модуль.
       Перед каждым тестом YaxUnit открывает транзакцию, после — откатывает.
       Справочники — только через ЮТест.Данные(); документы через Документы.X.СоздатьДокумент()
       не трекаются — требуют явного teardown в .После("...").
антиприём_1: НЕ создавать объекты через прямые конструкторы (Справочники.X.СоздатьЭлемент,
             Документы.X.СоздатьДокумент) без teardown — объекты не трекаются YaxUnit,
             копятся в базе, прогоны теряют идемпотентность.
антиприём_2: НЕ применять .ВТранзакции() к наборам с негативными тестами проведения
             (ожидаемый Отказ = Истина): упавшая вложенная транзакция отравляет внешнюю —
             «В данной транзакции уже происходили ошибки!» при последующих чтениях.
             Такие наборы: .УдалениеТестовыхДанных() + .После("Очистка").
исключения: (а) негативные тесты проведения — см. антиприём_2;
            (б) прод-код с гвардом ТранзакцияАктивна() — двухфазные фиксации, реальные API;
            (в) клиентский контекст — ДобавитьКлиентскийТест.
            Каждое исключение требует комментария-обоснования у набора + .После("Очистка").
почему: Без изоляции тесты не воспроизводимы, база деградирует, прогоны дают нестабильные
        результаты в зависимости от порядка выполнения и предыдущих запусков.
шаги: |
  1. ДобавитьТестовыйНабор("Имя") — сразу .ВТранзакции() если набор пишет в БД
  2. Справочники: ЮТест.Данные().СоздатьЭлемент() / КонструкторОбъекта().Записать()
  3. Документы: ЮТест.Данные().СоздатьДокумент() — трекается; иначе .После("Очистка")
  4. Негативные тесты: .УдалениеТестовыхДанных() + .После("Очистка"), без .ВТранзакции()
  5. Перепроведение: ДокОбъект = Ссылка.ПолучитьОбъект() перед каждой сменой режима
источник: task-165 GBIG PAM, два гейта ревью (2026-06-05); повторно подтверждено на TASK-165.6
```

```
status: confirmed
область: серверные модули расширений (YaxUnit)
приём: В серверных модулях (Server=true) использовать ПредопределенноеЗначение("Справочник.ИмяСправочника.ИмяЭлемента")
       для получения ссылки на предопределённый элемент.
антиприём: НЕ использовать ПредопределённыйЭлемент() — это клиентская функция,
           недоступная в серверном контексте. Ошибка компиляции, расширение не загружается.
почему: 1С выдаёт ошибку компиляции "Процедура или функция с указанным именем не определена",
        расширение TESTS не загружается, тесты зависают без результата.
        ЖР показывает event_presentation="30" (ошибка компиляции), но без явного указания на причину.
шаги: |
  1. В серверных модулях (Server=true, ExternalConnection=true): ПредопределенноеЗначение("...")
  2. В клиентских модулях (Client=true): допустим ПредопределённыйЭлемент(), но ПредопределенноеЗначение тоже работает
  3. При массовом исправлении: grep -r "ПредопределённыйЭлемент" → replace_all → ПредопределенноеЗначение
источник: task-103 GBIG PAM, ошибка компиляции в 4 тестовых модулях (2026-03-24)
```
