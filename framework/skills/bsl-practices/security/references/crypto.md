# Криптография в 1С

Справочник по криптографическому API платформы и БСП: провайдеры, сертификаты, подпись CMS, ГОСТ, lifecycle закрытого ключа. Используется навыком `bsl-practices/security`.

---

## Архитектурная схема

1С не делает криптографию сама — она делегирует её **внешнему криптопровайдеру ОС**:

```
1С (МенеджерКриптографии)  ─►  Криптопровайдер (CryptoPro CSP / ViPNet CSP / OpenSSL)  ─►  ОС / контейнер ключей
```

Из этого следует:

- Провайдер должен быть **установлен и лицензирован на сервере 1С** (rphost), а не на клиенте.
- Закрытый ключ живёт в **контейнере провайдера** (реестр Windows, файловая система, токен/смарт-карта), а не внутри 1С.
- Учётная запись, под которой работает сервер 1С (`USR1CV8` / `usr1cv8` или доменная), должна иметь доступ к контейнеру.
- Версия провайдера, версия ГОСТ и тип контейнера фиксируются в документации развёртывания; в коде они **должны быть заданы явно**.

## API: `МенеджерКриптографии`

```bsl
МенеджерКриптографии = Новый МенеджерКриптографии(ИмяПровайдера, ТипПровайдера, ПутьКМодулюПровайдера = "");
```

- `ИмяПровайдера` — строка имени CSP, как его видит ОС:
  - CryptoPro CSP, ГОСТ Р 34.10-2012, 256 бит: `"Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider"`
  - CryptoPro CSP, ГОСТ Р 34.10-2012, 512 бит: `"Crypto-Pro GOST R 34.10-2012 Strong Cryptographic Service Provider"`
  - ViPNet CSP, ГОСТ Р 34.10-2012: `"Infotecs Cryptographic Service Provider"` (точное имя зависит от версии)
- `ТипПровайдера` — числовой код типа CSP. Для ГОСТ-2012 у CryptoPro — `80` (256) или `81` (512). Уточнять у провайдера, не подбирать.
- `ПутьКМодулюПровайдера` — для Linux: явный путь к `.so`. Обычно не нужен на Windows.

Stop rule: **никогда не вызывай `Новый МенеджерКриптографии()` без аргументов**. Дефолтный провайдер ОС может оказаться MS Crypto на одной машине и CryptoPro на другой — поведение перестанет быть воспроизводимым.

## Объекты

| Объект | Что моделирует |
|--------|----------------|
| `МенеджерКриптографии` | Подключённый CSP. Контекст для всех операций (подпись, шифрование, хеш). |
| `СертификатКриптографии` | X.509-сертификат (открытая часть). Создаётся из бинарных данных или берётся из хранилища. |
| `ХранилищеСертификатовКриптографии` | Системное хранилище ОС (`Личное`, `Доверенные корневые`, и т.д.). |
| `ПараметрыПодписиCMS` | Настройки CMS-подписи: тип (открепленная/прикреплённая), кодировка, время. |
| `ПараметрыШифрованияCMS` | Настройки CMS-шифрования. |
| `МенеджерСертификатовКриптографии` (БСП) | Высокоуровневая обёртка БСП «Электронная подпись». |

## Поиск сертификата

```bsl
МенеджерКриптографии = Новый МенеджерКриптографии(
    "Crypto-Pro GOST R 34.10-2012 Cryptographic Service Provider",
    80);

Хранилище = МенеджерКриптографии.ОткрытьХранилищеСертификатов(
    ТипХранилищаСертификатовКриптографии.ПерсональныеСертификаты);

ОтпечатокЦелевой = "0123456789ABCDEF0123456789ABCDEF01234567"; // 40 hex для SHA-1
Сертификат = Неопределено;
Для Каждого ЭлементХранилища Из Хранилище.ПолучитьВсе() Цикл
    Если ВРег(ЭлементХранилища.Сертификат.Отпечаток) = ВРег(ОтпечатокЦелевой) Тогда
        Сертификат = ЭлементХранилища.Сертификат;
        Прервать;
    КонецЕсли;
КонецЦикла;

Если Сертификат = Неопределено Тогда
    ВызватьИсключение НСтр("ru = 'Сертификат с заданным отпечатком не найден.'");
КонецЕсли;
```

Правила:

- **Поиск только по `Отпечатку`** (`Thumbprint`). Не по СН, не по «первому в хранилище», не по сроку действия.
- Отпечаток хранится в реквизите справочника учётных записей — это открытая информация.
- Проверь `Сертификат.ДействителенДо` и `Сертификат.ДействителенС` перед использованием.

## Подпись CMS

```bsl
Параметры = Новый ПараметрыПодписиCMS;
Параметры.ВключатьСертификаты = ВключениеСертификатовCMS.ПодписавшийСертификат;
Параметры.ТипПодписи = ТипПодписиCMS.СCMS;
Параметры.Откреплённая = Истина; // или Ложь — прикреплённая
Параметры.ВключатьВремяШтампа = Истина;

ДанныеПодписи = МенеджерКриптографии.ПодписатьCMS(
    ДвоичныеДанныеИсточника,
    Сертификат,
    Параметры);
```

Замечания:

- Открепленная подпись (`Откреплённая = Истина`) — внешний файл `.sig`/`.p7s`, источник остаётся неизменным. Чаще требуется в B2G-обменах.
- Прикреплённая — данные и подпись в одном CMS-контейнере.
- Метка времени (`ВключатьВремяШтампа`) требует TSA-сервиса; убедись, что URL TSA настроен в CSP.

## Версии ГОСТ

| Стандарт | Размер ключа | Статус | Когда использовать |
|----------|--------------|--------|-------------------|
| ГОСТ Р 34.10-2012, 256 бит | 256 | Действующий | По умолчанию для новых подписей |
| ГОСТ Р 34.10-2012, 512 бит | 512 | Действующий | Усиленные требования, КЭП квалифицированных АС |
| ГОСТ Р 34.10-2001 | 256 | Устаревший | **Только** проверка ранее сделанных подписей. Новых не выпускать. |
| ГОСТ Р 34.11-2012 (Stribog) | 256/512 | Действующий | Хеш-функция, идёт в паре с 34.10-2012 |

Stop rule: **не смешивай провайдер и версию ГОСТ**. Провайдер «GOST R 34.10-2012 Cryptographic Service Provider» обслуживает 256 бит; для 512 нужен «Strong»-вариант.

## БСП «Электронная подпись»

Если в конфигурации есть БСП, **предпочитай её модули** прямой работе с `МенеджерКриптографии`:

- `ЭлектроннаяПодпись.СоздатьПодпись()` / `ЭлектроннаяПодпись.ПроверитьПодпись()`
- `ЭлектроннаяПодписьСлужебный.МенеджерКриптографии()` — централизованное получение менеджера по настройкам.
- `ЭлектроннаяПодписьСлужебныйКлиент` — клиентская часть (диалоги выбора сертификата, ввод PIN).

Преимущества:

- Единая обработка ошибок провайдера, нормализованные коды.
- Готовый UI выбора сертификата и ввода PIN.
- Поддержка нескольких сертификатов и нескольких провайдеров без дублирования кода.
- Уже сделанные обходные пути для известных багов CSP.

Если БСП в проекте нет — оформи это как технический долг, не пиши свою «обёртку с нуля» в каждом модуле.

## Lifecycle закрытого ключа

| Этап | Где | Что критично |
|------|-----|--------------|
| Генерация | На рабочем месте владельца (HSM, токен, ноутбук с CSP) | Никогда не на сервере приложений 1С общего пользования |
| Хранение | Контейнер CSP (реестр Windows под пользователем, файл, токен) | Доступ имеет **только** учётка сервера 1С |
| Использование | `МенеджерКриптографии.ПодписатьCMS` | На сервере, никогда на клиенте через `НаКлиенте` |
| Резервная копия | Экспорт контейнера, шифрование, сейф | Не делается через 1С |
| Отзыв | Запрос в УЦ + удаление контейнера + удаление отпечатка из справочника | Журналируется отдельно |

Stop rules:

- **Закрытый ключ не существует внутри 1С как объект**. Если в коде встретилась `ДвоичныеДанные` с приватным ключом — это уязвимость.
- Закрытый ключ не передаётся через обмен данными, не выгружается в файл из 1С, не логируется.

## Антипаттерны

```bsl
// ПЛОХО: дефолтный провайдер.
МенеджерКриптографии = Новый МенеджерКриптографии();

// ПЛОХО: поиск сертификата «первый попавшийся».
Сертификат = Хранилище.ПолучитьВсе()[0].Сертификат;

// ПЛОХО: приватный ключ в виде строки в коде или в макете.
Перем PrivateKeyPEM Экспорт;
PrivateKeyPEM = "-----BEGIN PRIVATE KEY-----...";

// ПЛОХО: подпись на клиенте через НаКлиенте + передача результата на сервер.
// Корректно только если используется БСП с её клиентским UI выбора сертификата.

// ПЛОХО: логирование двоичных данных подписи целиком.
ЗаписьЖурналаРегистрации("ЭЦП", , , , "Подпись=" + Base64Строка(ДанныеПодписи));
```
