# Секреты и `БезопасноеХранилище`

Справочник по работе с секретами в 1С: куда класть, как читать, как ротировать, как маскировать в логах. Используется навыком `bsl-practices/security`.

---

## Что такое `БезопасноеХранилище`

Платформенный API для хранения чувствительных данных (пароли, токены, ключи API, refresh-токены) **отдельно от данных конфигурации**:

- Физически — отдельные таблицы в кластере, недоступные через запрос языка запросов.
- Доступ — только через привилегированный режим, по владельцу.
- Резервная копия секретов делается отдельной выгрузкой кластера — учитывай при миграции.

Доступно начиная с платформы 8.3.9. На более старых версиях — использовать БСП «Сохраняемые данные» как fallback (не рекомендуется для нового кода).

---

## API

```bsl
БезопасноеХранилище.УстановитьДанные(Владелец, Данные, Ключ = Неопределено)
БезопасноеХранилище.ПрочитатьДанные(Владелец, Ключ = Неопределено)
БезопасноеХранилище.УдалитьДанные(Владелец, Ключ = Неопределено)
```

- **Владелец** — ссылка объекта метаданных (обычно элемент справочника учётных записей). Никогда не строка-константа: при удалении объекта секрет автоматически зачищается.
- **Данные** — произвольное сериализуемое значение (строка, структура, соответствие). Для одного владельца можно класть несколько секретов с разными ключами.
- **Ключ** — строка, разделяющая секреты одного владельца (`"access_token"`, `"refresh_token"`, `"client_secret"`).

Все три метода — **серверные**, требуют **привилегированного режима** для обычного пользователя.

---

## Структура хранения: рекомендуемый шаблон

Под каждый тип внешнего сервиса заведи отдельный справочник учётных записей, например:

- `Справочник.УчётныеЗаписиВнешнихСервисов` — общий каталог подключений.
- Реквизиты: `URLСервиса`, `Логин` (открыто), `ИдентификаторКлиента` (открыто), `ТипАутентификации` (перечисление).
- Секреты: всё, что хранится только в `БезопасноеХранилище` по ключам:
  - `password`
  - `client_secret`
  - `access_token`
  - `refresh_token`
  - `api_key`
  - `certificate_thumbprint` (отпечаток — не секрет, но удобно хранить рядом)

Никогда **не** заводи реквизит `Пароль` или `Токен` в справочнике — это типовая утечка через выгрузку, отчёт, журнал регистрации, обмен.

## Запись секрета

```bsl
&НаСервере
Процедура СохранитьУчётныеДанныеНаСервере(СсылкаУчётнойЗаписи, ПарольПользователя)

    УстановитьПривилегированныйРежим(Истина);
    Попытка
        БезопасноеХранилище.УстановитьДанные(СсылкаУчётнойЗаписи, ПарольПользователя, "password");
    Исключение
        УстановитьПривилегированныйРежим(Ложь);
        ВызватьИсключение;
    КонецПопытки;
    УстановитьПривилегированныйРежим(Ложь);

КонецПроцедуры
```

Замечания:

- Параметр `ПарольПользователя` приходит **с клиента в момент настройки**. Сразу после `УстановитьДанные` обнуляй переменную (`ПарольПользователя = ""`).
- Не логируй сам пароль ни на каком шаге.
- Никогда не вызывай `УстановитьДанные` из клиентского контекста — `БезопасноеХранилище` доступен только на сервере.

## Чтение секрета

```bsl
&НаСервереБезКонтекста
Функция ПрочитатьПароль(СсылкаУчётнойЗаписи)

    УстановитьПривилегированныйРежим(Истина);
    Попытка
        Пароль = БезопасноеХранилище.ПрочитатьДанные(СсылкаУчётнойЗаписи, "password");
    Исключение
        УстановитьПривилегированныйРежим(Ложь);
        ВызватьИсключение;
    КонецПопытки;
    УстановитьПривилегированныйРежим(Ложь);

    Возврат Пароль; // Может быть Неопределено, если секрет не задан

КонецФункции
```

Stop rules:

- Привилегированный режим обязателен, иначе у обычного пользователя `ПрочитатьДанные` упадёт с ошибкой прав.
- `УстановитьПривилегированныйРежим(Ложь)` ставится **в той же области видимости** и обрабатывается через `Попытка/Исключение`, иначе при исключении режим утечёт за пределы вызова.
- Никогда не возвращай пароль клиенту. Возвращай результат бизнес-операции, выполненной на сервере с этим паролем.

## Lifecycle секрета

| Этап | Кто делает | Где | Что критично |
|------|------------|-----|--------------|
| Источник | Администратор интеграции | Форма настройки учётной записи | Поле ввода с маской, без `ОтправляемоеЗначение` в форме |
| Запись | Сервер | `БезопасноеХранилище.УстановитьДанные` | Привилегированный режим, обнуление переменной после |
| Чтение | Сервер | `БезопасноеХранилище.ПрочитатьДанные` | Привилегированный режим, точечно, без утечки на клиент |
| Использование | Сервер | `HTTPСоединение`, `МенеджерКриптографии` | Заголовок собирается на сервере, не возвращается клиенту |
| Ротация | Регламентное задание / админ вручную | См. ниже | Атомарная замена, без окна с пустым секретом |
| Отзыв | Удаление учётной записи | `БезопасноеХранилище.УдалитьДанные` | Автоматически при удалении владельца, но лучше явно |

## Ротация секретов

Сценарии:

1. **Регламентная ротация пароля внешнего сервиса** — обычно раз в N дней.
2. **OAuth refresh token** — refresh-токен меняется при каждом получении нового access-токена, его тоже надо перезаписывать.
3. **Компрометация** — внеплановая ротация по инциденту.

Рекомендации:

- Новое значение пишется **поверх** старого (`УстановитьДанные` с тем же ключом). Окна с пустым секретом не должно быть.
- Для OAuth refresh — операция `получили новый access + новый refresh → УстановитьДанные оба ключа` в одном `Попытка/Исключение`; если запись refresh упала — старый access откатывать не надо, но в логе пометить рассинхронизацию.
- Запись ротации в журнал регистрации: владелец, ключ (`access_token`), `success/fail`, **без значения**.

## Маскирование в логах

Что попадает в логи (журнал регистрации, `Сообщить`, ответ агента) **только в маскированном виде**:

- Пароли — никогда, даже в маске; вообще не упоминать значение.
- Токены (`access_token`, `refresh_token`, `api_key`) — последние 4 символа, остальное `***`.
- Полный заголовок `Authorization` — никогда; логируется только тип схемы (`Bearer`, `Basic`).
- Тело HTTP-запроса/ответа — только после санитизации (поля `password`, `token`, `secret`, `authorization` заменяются на `***`).
- Сертификаты — отпечаток (это открытая информация), а не PEM/CER целиком.

Шаблон утилиты маскирования:

```bsl
Функция ЗамаскироватьСекрет(Значение)
    Если ТипЗнч(Значение) <> Тип("Строка") ИЛИ ПустаяСтрока(Значение) Тогда
        Возврат "***";
    КонецЕсли;
    Если СтрДлина(Значение) <= 4 Тогда
        Возврат "***";
    КонецЕсли;
    Возврат "***" + Прав(Значение, 4);
КонецФункции
```

## Антипаттерны

```bsl
// ПЛОХО: пароль в реквизите справочника.
УчётнаяЗапись.Пароль = ПарольПользователя;
УчётнаяЗапись.Записать();

// ПЛОХО: пароль в константе.
Константы.ПарольИнтеграции.Установить(ПарольПользователя);

// ПЛОХО: привилегированный режим на всю функцию.
Функция ВыполнитьБизнесОперацию(Параметры) Экспорт
    УстановитьПривилегированныйРежим(Истина); // охватывает всю логику, не только секрет
    // ... 200 строк бизнес-логики ...
КонецФункции

// ПЛОХО: возврат пароля на клиент.
&НаСервереБезКонтекста
Функция ПолучитьПароль(УчётнаяЗапись) Экспорт // вызывается с клиента
    УстановитьПривилегированныйРежим(Истина);
    Возврат БезопасноеХранилище.ПрочитатьДанные(УчётнаяЗапись, "password");
КонецФункции

// ПЛОХО: пароль в журнале регистрации.
ЗаписьЖурналаРегистрации("Интеграция", , , , "Логин=" + Логин + ", пароль=" + Пароль);
```
