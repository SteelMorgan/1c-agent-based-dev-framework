# Секреты и безопасное хранилище

Справочник по работе с секретами в 1С: куда класть, как читать, как ротировать, как маскировать в логах. Используется навыком `bsl-practices/security`.

---

## Что такое безопасное хранилище

Хранение чувствительных данных (пароли, токены, ключи API, refresh-токены) **отдельно от данных конфигурации** — регистр сведений `БезопасноеХранилищеДанных`. Это **не общий модуль**: прямой доступ к регистру запрещён, работа с ним идёт только через обёртки общего модуля `ОбщегоНазначения` (запись — под привилегированным режимом внутри этих обёрток):

- Физически — отдельные записи регистра, изолированные от прикладных данных.
- Доступ снаружи обёрток — только через привилегированный режим, по владельцу.
- Резервная копия секретов делается вместе с базой — учитывай при миграции/переносе данных.

## API

```bsl
ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище(Владелец, Данные, Ключ = "Пароль")
ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(Владелец, Ключи = "Пароль", ОбщиеДанные = Неопределено)
ОбщегоНазначения.ПрочитатьДанныеВладельцевИзБезопасногоХранилища(Владельцы, Ключи = "Пароль", ОбщиеДанные = Неопределено)
ОбщегоНазначения.УдалитьДанныеИзБезопасногоХранилища(Владелец, Ключи = Неопределено)
```

- **Владелец** — ссылка объекта метаданных (обычно элемент справочника учётных записей) либо уникальная строка (до 128 символов). Ссылка предпочтительна: при удалении объекта-владельца секрет нужно зачищать явно в `ПередУдалением`, автоматической каскадной чистки нет.
- **Данные** — произвольное сериализуемое значение (строка, структура, соответствие) для `Ключ`, либо структура целиком, если `Ключ = Неопределено`.
- **Ключи/Ключ** — строка, разделяющая секреты одного владельца (`"access_token"`, `"refresh_token"`, `"client_secret"`); для чтения может быть списком через запятую (`"Логин,Пароль"`) — тогда возвращается структура, при одном ключе — само значение.

Все методы — **серверные**, требуют **привилегированного режима** для обычного пользователя; сами обёртки привилегированный режим не устанавливают — это обязан делать вызывающий код.

## Структура хранения: рекомендуемый шаблон

Под каждый тип внешнего сервиса заведи отдельный справочник учётных записей, например:

- `Справочник.УчётныеЗаписиВнешнихСервисов` — общий каталог подключений.
- Реквизиты: `URLСервиса`, `Логин` (открыто), `ИдентификаторКлиента` (открыто), `ТипАутентификации` (перечисление).
- Секреты: всё, что хранится только в регистре `БезопасноеХранилищеДанных` (через `ОбщегоНазначения.*ДанныеВБезопасноеХранилище*`) по ключам:
  - `password`
  - `client_secret`
  - `access_token`
  - `refresh_token`
  - `api_key`
  - `certificate_thumbprint` (отпечаток — не секрет, но удобно хранить рядом)

Никогда **не** заводи реквизит `Пароль` или `Токен` в справочнике — это типовая утечка через выгрузку, отчёт, журнал регистрации, обмен.

## Запись секрета

```bsl
&НаСервере
Процедура СохранитьУчётныеДанныеНаСервере(СсылкаУчётнойЗаписи, ПарольПользователя)

    УстановитьПривилегированныйРежим(Истина);
    Попытка
        ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище(СсылкаУчётнойЗаписи, ПарольПользователя, "password");
    Исключение
        УстановитьПривилегированныйРежим(Ложь);
        ВызватьИсключение;
    КонецПопытки;
    УстановитьПривилегированныйРежим(Ложь);

КонецПроцедуры
```

Замечания:

- Параметр `ПарольПользователя` приходит **с клиента в момент настройки**. Сразу после `ЗаписатьДанныеВБезопасноеХранилище` обнуляй переменную (`ПарольПользователя = ""`).
- Не логируй сам пароль ни на каком шаге.
- Никогда не вызывай `ЗаписатьДанныеВБезопасноеХранилище` из клиентского контекста — регистр `БезопасноеХранилищеДанных` доступен только на сервере.

## Чтение секрета

```bsl
&НаСервереБезКонтекста
Функция ПрочитатьПароль(СсылкаУчётнойЗаписи)

    УстановитьПривилегированныйРежим(Истина);
    Попытка
        Пароль = ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(СсылкаУчётнойЗаписи, "password");
    Исключение
        УстановитьПривилегированныйРежим(Ложь);
        ВызватьИсключение;
    КонецПопытки;
    УстановитьПривилегированныйРежим(Ложь);

    Возврат Пароль; // Может быть Неопределено, если секрет не задан

КонецФункции
```

Stop rules:

- Привилегированный режим обязателен, иначе у обычного пользователя `ПрочитатьДанныеИзБезопасногоХранилища` упадёт с ошибкой прав.
- `УстановитьПривилегированныйРежим(Ложь)` ставится **в той же области видимости** и обрабатывается через `Попытка/Исключение`, иначе при исключении режим утечёт за пределы вызова.
- Никогда не возвращай пароль клиенту. Возвращай результат бизнес-операции, выполненной на сервере с этим паролем.

## Lifecycle секрета

| Этап | Кто делает | Где | Что критично |
|------|------------|-----|--------------|
| Источник | Администратор интеграции | Форма настройки учётной записи | Поле ввода с маской, без `ОтправляемоеЗначение` в форме |
| Запись | Сервер | `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище` | Привилегированный режим, обнуление переменной после |
| Чтение | Сервер | `ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища` | Привилегированный режим, точечно, без утечки на клиент |
| Использование | Сервер | `HTTPСоединение`, `МенеджерКриптографии` | Заголовок собирается на сервере, не возвращается клиенту |
| Ротация | Регламентное задание / админ вручную | См. ниже | Атомарная замена, без окна с пустым секретом |
| Отзыв | Удаление учётной записи (в `ПередУдалением`) | `ОбщегоНазначения.УдалитьДанныеИзБезопасногоХранилища` | Явный вызов — каскадной чистки при удалении владельца нет |

## Ротация секретов

Сценарии:

1. **Регламентная ротация пароля внешнего сервиса** — обычно раз в N дней.
2. **OAuth refresh token** — refresh-токен меняется при каждом получении нового access-токена, его тоже надо перезаписывать.
3. **Компрометация** — внеплановая ротация по инциденту.

Рекомендации:

- Новое значение пишется **поверх** старого (`ЗаписатьДанныеВБезопасноеХранилище` с тем же ключом). Окна с пустым секретом не должно быть.
- Для OAuth refresh — операция `получили новый access + новый refresh → ЗаписатьДанныеВБезопасноеХранилище оба ключа` в одном `Попытка/Исключение`; если запись refresh упала — старый access откатывать не надо, но в логе пометить рассинхронизацию.
- Запись ротации в журнал регистрации: владелец, ключ (`access_token`), `success/fail`, **без значения**.

## Маскирование в логах

Что попадает в логи (журнал регистрации, `Сообщить`, ответ агента) **только в маскированном виде**:

- Пароли — никогда, даже в маске; вообще не упоминать значение.
- Токены (`access_token`, `refresh_token`, `api_key`) — последние 4 символа, остальное `***`.
- Полный заголовок `Authorization` — никогда; логируется только тип схемы (`Bearer`, `Basic`).
- Тело HTTP-запроса/ответа — только после санитизации (поля `password`, `token`, `secret`, `authorization` заменяются на `***`).
- Сертификаты — отпечаток (это открытая информация), а не PEM/CER целиком.

Шаблон утилиты маскирования:

```bsl
Функция ЗамаскироватьСекрет(Значение)
    Если ТипЗнч(Значение) <> Тип("Строка") ИЛИ ПустаяСтрока(Значение) Тогда
        Возврат "***";
    КонецЕсли;
    Если СтрДлина(Значение) <= 4 Тогда
        Возврат "***";
    КонецЕсли;
    Возврат "***" + Прав(Значение, 4);
КонецФункции
```

## Антипаттерны

```bsl
// ПЛОХО: пароль в реквизите справочника.
УчётнаяЗапись.Пароль = ПарольПользователя;
УчётнаяЗапись.Записать();

// ПЛОХО: пароль в константе.
Константы.ПарольИнтеграции.Установить(ПарольПользователя);

// ПЛОХО: привилегированный режим на всю функцию.
Функция ВыполнитьБизнесОперацию(Параметры) Экспорт
    УстановитьПривилегированныйРежим(Истина); // охватывает всю логику, не только секрет
    // ... 200 строк бизнес-логики ...
КонецФункции

// ПЛОХО: возврат пароля на клиент.
&НаСервереБезКонтекста
Функция ПолучитьПароль(УчётнаяЗапись) Экспорт // вызывается с клиента
    УстановитьПривилегированныйРежим(Истина);
    Возврат ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(УчётнаяЗапись, "password");
КонецФункции

// ПЛОХО: пароль в журнале регистрации.
ЗаписьЖурналаРегистрации("Интеграция", , , , "Логин=" + Логин + ", пароль=" + Пароль);
```
