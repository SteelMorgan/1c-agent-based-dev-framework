# Аутентификация и внешние API

Справочник по схемам аутентификации, которые встречаются в коде 1С: OpenID/OIDC, OAuth 2.0, basic/token, клиентский TLS-сертификат. Используется навыком `bsl-practices/security`.

---

## Карта схем

| Схема | Где применяется | Где хранится секрет | Где собирается заголовок |
|-------|-----------------|---------------------|--------------------------|
| OpenID / OpenID Connect | Аутентификация пользователей в платформе и БСП | Платформа / БСП «ИнтернетПользователи» | Платформа |
| OAuth 2.0 (client credentials) | Сервер 1С → внешний API без участия пользователя | `БезопасноеХранилище` | Сервер 1С |
| OAuth 2.0 (authorization code) | Внешний API от имени пользователя | `БезопасноеХранилище` + refresh | Сервер 1С |
| Basic auth | Legacy-сервисы, внутренние API | `БезопасноеХранилище` | Сервер 1С |
| API token / API key | Простые REST-API | `БезопасноеХранилище` | Сервер 1С |
| Клиентский TLS-сертификат (mTLS) | B2G, банки, защищённые интеграции | Контейнер CSP ОС | TLS-стек, заголовок не нужен |

---

## OpenID / OpenID Connect

Платформа поддерживает OpenID как способ аутентификации пользователей информационной базы:

- Параметры подключения — в свойствах информационной базы (через конфигуратор/администрирование).
- Дополнительно в БСП есть подсистема «ИнтернетПользователи» и связанные модули для авторизации в опубликованных HTTP-сервисах.
- Идентификация пользователя — по `email`/`sub` из ID-токена, маппится на пользователя ИБ.

Замечания:

- OIDC discovery (`/.well-known/openid-configuration`) — проверь, что URL стабилен и доступен с сервера 1С.
- Время на сервере 1С должно быть синхронизировано (NTP); расхождение > 5 минут ломает проверку токенов.
- Журналируй `sub`/`email`, но **не** ID-токен и не access-токен целиком.

## OAuth 2.0 поверх `HTTPСоединение`

### Получение access-токена (client credentials)

```bsl
Функция ПолучитьAccessТокен(УчётнаяЗапись)

    УстановитьПривилегированныйРежим(Истина);
    Попытка
        ClientId = БезопасноеХранилище.ПрочитатьДанные(УчётнаяЗапись, "client_id");
        ClientSecret = БезопасноеХранилище.ПрочитатьДанные(УчётнаяЗапись, "client_secret");
    Исключение
        УстановитьПривилегированныйРежим(Ложь);
        ВызватьИсключение;
    КонецПопытки;
    УстановитьПривилегированныйРежим(Ложь);

    Тело = "grant_type=client_credentials"
        + "&client_id=" + ClientId
        + "&client_secret=" + ClientSecret;

    Запрос = Новый HTTPЗапрос("/oauth2/token");
    Запрос.Заголовки.Вставить("Content-Type", "application/x-www-form-urlencoded");
    Запрос.УстановитьТелоИзСтроки(Тело, КодировкаТекста.UTF8);

    Соединение = Новый HTTPСоединение(УчётнаяЗапись.Хост, 443, , , , 30, Новый ЗащищённоеСоединениеOpenSSL);
    Ответ = Соединение.ОтправитьДляОбработки(Запрос);

    Если Ответ.КодСостояния = 200 Тогда
        Возврат РазобратьТокен(Ответ.ПолучитьТелоКакСтроку());
    ИначеЕсли Ответ.КодСостояния = 401 ИЛИ Ответ.КодСостояния = 400 Тогда
        ВызватьИсключение НСтр("ru = 'Ошибка аутентификации во внешнем сервисе.'");
    Иначе
        ВызватьИсключение НСтр("ru = 'Сервис аутентификации временно недоступен.'");
    КонецЕсли;

КонецФункции
```

Замечания:

- Переменные `ClientId` и `ClientSecret` живут только в этой функции; не возвращай их наружу.
- Тело запроса с `client_secret` **не** логируется.
- Полученный `access_token` пишется в `БезопасноеХранилище` с тем же владельцем, ключ `"access_token"`, и `expires_at` — в реквизит справочника (это открытая информация).

### Refresh token

- При истечении access-токена сделать `POST /oauth2/token` с `grant_type=refresh_token` и `refresh_token` из `БезопасноеХранилище`.
- Многие провайдеры **обновляют refresh-токен** при каждом запросе — обязательно перезаписывай его в `БезопасноеХранилище`.
- Если refresh-токен отозван (`400 invalid_grant`) — это **не** retry, а ошибка конфигурации/реавторизации.

## Basic / API-token

```bsl
УстановитьПривилегированныйРежим(Истина);
Попытка
    Логин = БезопасноеХранилище.ПрочитатьДанные(УчётнаяЗапись, "login");
    Пароль = БезопасноеХранилище.ПрочитатьДанные(УчётнаяЗапись, "password");
Исключение
    УстановитьПривилегированныйРежим(Ложь);
    ВызватьИсключение;
КонецПопытки;
УстановитьПривилегированныйРежим(Ложь);

Учётка = Base64Строка(ПолучитьДвоичныеДанныеИзСтроки(Логин + ":" + Пароль));
Запрос.Заголовки.Вставить("Authorization", "Basic " + Учётка);
```

Stop rules:

- Заголовок `Authorization` собирается **только на сервере** и **не возвращается** клиенту.
- `Пароль` обнуляется (`Пароль = ""`) сразу после сборки заголовка.
- Запрос целиком не логируется; для диагностики — только URL, метод, код ответа, время.

## Клиентский TLS-сертификат (mTLS)

Платформа предоставляет три варианта объектов «сертификат клиента» для `HTTPСоединение`:

| Объект | Когда применять | Где живёт ключ |
|--------|-----------------|----------------|
| `СертификатКлиентаФайл` | Сертификат + ключ в PFX-файле на сервере 1С | Файл, защищённый паролем |
| `СертификатКлиентаWindows` | Сертификат в Windows-хранилище под учёткой rphost | Реестр Windows |
| `СертификатКлиентаOpenSSL` | Linux-сервер, ключ в PEM-файле | Файл |

Пример:

```bsl
СертификатКлиента = Новый СертификатКлиентаФайл(
    ПутьКPFX,                          // путь на сервере 1С, не на клиенте
    ПрочитатьПарольКонтейнераИзБХ());  // пароль контейнера из БезопасноеХранилище

ЗащищённоеСоединение = Новый ЗащищённоеСоединениеOpenSSL(СертификатКлиента, Неопределено);

Соединение = Новый HTTPСоединение(Хост, 443, , , , 30, ЗащищённоеСоединение);
```

Замечания:

- Путь к PFX/PEM — на сервере 1С, доступ имеет только учётка rphost (`USR1CV8`).
- Пароль контейнера PFX — в `БезопасноеХранилище`.
- На Linux-сервере используется OpenSSL — `СертификатКлиентаWindows` работать не будет.
- TLS-версия и набор шифров определяются ОС/OpenSSL; если внешний сервис требует TLS 1.2+ — это вопрос конфигурации сервера, а не кода 1С.

## Error semantics

Аутентификационные ошибки **обязаны** отличаться от валидационных и бизнес-ошибок. Минимальный набор:

| Код | Семантика | Реакция |
|-----|-----------|---------|
| `missing credentials` | Секрет не задан в `БезопасноеХранилище` | Ошибка конфигурации, эскалация администратору, **не retry** |
| `expired token` | Access-токен истёк, refresh есть | Автоматический refresh + повтор операции |
| `invalid refresh` | Refresh отозван/невалиден | Эскалация: требуется повторная авторизация владельца |
| `invalid certificate` | Сертификат истёк, не найден, неверный пароль PFX | Ошибка конфигурации, **не retry** |
| `provider unavailable` | OIDC/OAuth/API недоступен (5xx, таймаут, network) | Retry с backoff (3 попытки, 2/4/8 секунд), потом — ошибка |
| `denied rights` | 403 от внешнего API | Бизнес-ошибка прав, эскалация, **не retry** |
| `tenant mismatch` | `aud`/`tenant_id` в токене не совпадает с ожидаемым | Ошибка конфигурации, **не retry** |
| `remote auth failure` | 401 после успешного логина (странный кейс) | Сбросить кэш токена, попытаться обновить, потом эскалация |

Stop rule: **`401` от внешнего API нельзя превращать в «не удалось выполнить операцию»**. Это отдельный класс ошибки с отдельной обработкой.

## Маскирование заголовков

При журналировании HTTP-обмена санитизируй заголовки:

```bsl
Функция ЗаголовкиДляЛога(Заголовки)
    Копия = Новый Соответствие;
    ЧувствительныеИмена = "authorization,x-api-key,cookie,set-cookie,proxy-authorization";
    Для Каждого КЗ Из Заголовки Цикл
        Если СтрНайти(ЧувствительныеИмена, НРег(КЗ.Ключ)) > 0 Тогда
            Копия.Вставить(КЗ.Ключ, "***");
        Иначе
            Копия.Вставить(КЗ.Ключ, КЗ.Значение);
        КонецЕсли;
    КонецЦикла;
    Возврат Копия;
КонецФункции
```

## Антипаттерны

```bsl
// ПЛОХО: пароль и логин в параметрах НаКлиенте → НаСервере.
&НаКлиенте
Процедура Подключиться(Команда)
    ПодключитьсяНаСервере(Объект.Логин, ПарольИзПоляФормы);
КонецПроцедуры
// Правильно: на сервер передаётся ссылка учётной записи; секрет читается на сервере.

// ПЛОХО: 401 трактуется как «временно недоступно».
Если Ответ.КодСостояния <> 200 Тогда
    // retry через минуту — на 401 это бесполезный цикл
КонецЕсли;

// ПЛОХО: логирование полного заголовка Authorization.
ЗаписьЖурналаРегистрации("API", , , , "Authorization=" + Запрос.Заголовки["Authorization"]);

// ПЛОХО: путь к PFX в реквизите формы или передаётся с клиента.
// Корректно: путь — серверная константа/реквизит ИБ, файл лежит на сервере 1С.
```
