# Антипаттерны BSL (1С)

## Назначение

Этот навык учит агента распознавать и избегать типичные антипаттерны при разработке на BSL. Каждый антипаттерн описан по формуле: **что плохо → почему плохо → как правильно → пример кода**. Антипаттерны — это не теоретические «плохие практики», а реальные ошибки, встречающиеся в продуктивных системах и приводящие к деградации производительности, потере данных и трудноуловимым багам.

**Источники:**
- [Стандарты ИТС: «Типичные ошибки и методы оптимизации»](https://its.1c.ru/db/v8std)
- [Стандарты ИТС: «Ограничения на использование запросов»](https://its.1c.ru/db/v8std)
- Методические рекомендации ЦКТП по оптимизации
- Стандарты БСП (Библиотека стандартных подсистем)

## Антипаттерн 1: Запросы в циклах

### Что плохо
Выполнение запроса к базе данных внутри цикла обработки коллекции.

### Почему плохо
Каждое выполнение запроса — сетевой round-trip к СУБД. При N итерациях:
- N × латентность сети (обычно 2-10 мс)
- N × время компиляции плана (если не кэширован)
- N × время выполнения запроса

Для 1000 элементов при латентности 5 мс = **5 секунд** только на ожидание, не считая самого выполнения. Один запрос с `В(&Массив)` выполнится за 50 мс.

**Сложность:** O(N) вызовов СУБД → O(1) вызов.

### Как правильно
Собрать все ключи в массив/таблицу значений, выполнить один запрос с условием `В(&Массив)` или через временную таблицу, обработать результат в цикле.

### Пример

```bsl
// ❌ ПЛОХО: запрос в цикле
Для Каждого СтрокаТоваров Из Документ.Товары Цикл
    Запрос = Новый Запрос("ВЫБРАТЬ Н.ЕдиницаИзмерения ИЗ Справочник.Номенклатура КАК Н ГДЕ Н.Ссылка = &Ссылка");
    Запрос.УстановитьПараметр("Ссылка", СтрокаТоваров.Номенклатура);
    Результат = Запрос.Выполнить(); // Запрос на КАЖДОЙ итерации!
КонецЦикла;

// ✅ ПРАВИЛЬНО: один запрос для всех
МассивНоменклатуры = Документ.Товары.ВыгрузитьКолонку("Номенклатура");

Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ Н.Ссылка, Н.ЕдиницаИзмерения
|ИЗ Справочник.Номенклатура КАК Н
|ГДЕ Н.Ссылка В (&МассивНоменклатуры)";
Запрос.УстановитьПараметр("МассивНоменклатуры", МассивНоменклатуры);
Результат = Запрос.Выполнить(); // Один запрос!
```

**Подробнее:** [query-patterns.md](query-patterns.md), правило 1.

## Антипаттерн 2: Точечная нотация через ссылки (неявные JOIN)

### Что плохо
Обращение к реквизитам через цепочку ссылок: `СправочникСсылка.Владелец.Наименование`, `Документ.Контрагент.ГоловнойКонтрагент.Наименование`.

### Почему плохо
Каждая «точка» через ссылочное поле — это **неявный LEFT JOIN** в запросе к СУБД. Платформа 1С при каждом обращении через точку выполняет отдельное чтение из базы данных (или LEFT JOIN, если внутри запроса). Это классическая проблема **N+1** — чтение одного объекта порождает чтение связанных.

**Особенно опасно:**
- В циклах: `Для Каждого Строка → Строка.Номенклатура.ВидНоменклатуры.Наименование` = 3 обращения к БД × N строк
- С составными типами: если тип ссылки составной, JOIN делается ко ВСЕМ возможным таблицам

### Как правильно
Получить все нужные данные одним запросом с явными JOIN.

### Пример

```bsl
// ❌ ПЛОХО: цепочка точек в цикле — N+1 проблема
Для Каждого СтрокаТоваров Из Документ.Товары Цикл
    // Каждое обращение через точку — чтение из БД
    ВидНоменклатуры = СтрокаТоваров.Номенклатура.ВидНоменклатуры;   // чтение 1
    ЕдиницаИзмерения = СтрокаТоваров.Номенклатура.ЕдиницаИзмерения; // чтение 2 (кэш может помочь, но не гарантировано)
    ИмяКонтрагента = Документ.Контрагент.Наименование;               // чтение 3
КонецЦикла;

// ✅ ПРАВИЛЬНО: один запрос со всеми данными
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
|   Товары.Номенклатура КАК Номенклатура,
|   Товары.Номенклатура.ВидНоменклатуры КАК ВидНоменклатуры,
|   Товары.Номенклатура.ЕдиницаИзмерения КАК ЕдиницаИзмерения
|ИЗ
|   Документ.РеализацияТоваровУслуг.Товары КАК Товары
|ГДЕ
|   Товары.Ссылка = &ДокументСсылка";
Запрос.УстановитьПараметр("ДокументСсылка", Документ.Ссылка);
```

## Антипаттерн 3: &НаСервере вместо &НаСервереБезКонтекста

### Что плохо
Использование директивы `&НаСервере` для серверных вызовов из формы, когда данные формы не нужны.

### Почему плохо
При вызове `&НаСервере` платформа:
1. **Сериализует весь контекст формы** — все реквизиты, все строки всех табличных частей, настройки условного оформления, состояние динамических списков
2. **Передаёт на сервер** — при форме с 1000 строк в табличной части это может быть 1-5 МБ данных
3. **Выполняет код**
4. **Сериализует контекст обратно**
5. **Передаёт на клиент**

Итого: 2-10 МБ трафика на каждый вызов. При медленном канале (WAN, мобильный интернет) — секунды задержки.

`&НаСервереБезКонтекста` передаёт **только параметры вызова** — обычно десятки байт.

### Как правильно
Использовать `&НаСервереБезКонтекста`, передавая только необходимые данные параметрами. `&НаСервере` — только когда действительно нужно читать/изменять реквизиты формы.

### Пример

```bsl
// ❌ ПЛОХО: &НаСервере — передаёт весь контекст ради одного значения
&НаСервере
Функция ПолучитьЦенуНоменклатурыНаСервере()
    Возврат ОбщегоНазначения.ЗначениеРеквизитаОбъекта(
        Объект.Товары[0].Номенклатура, "Цена");
КонецФункции

// ✅ ПРАВИЛЬНО: &НаСервереБезКонтекста — только параметры
&НаСервереБезКонтекста
Функция ПолучитьЦенуНоменклатуры(НоменклатураСсылка)
    Возврат ОбщегоНазначения.ЗначениеРеквизитаОбъекта(
        НоменклатураСсылка, "Цена");
КонецФункции

&НаКлиенте
Процедура НоменклатураПриИзменении(Элемент)
    ТекущаяСтрока = Элементы.Товары.ТекущиеДанные;
    ТекущаяСтрока.Цена = ПолучитьЦенуНоменклатуры(ТекущаяСтрока.Номенклатура);
КонецПроцедуры
```

**Подробнее:** [coding-standards.md](coding-standards.md), правило 3; [form-patterns.md](form-patterns.md), правило 1.

## Антипаттерн 4: ТекущаяДата() вместо ТекущаяДатаСеанса()

### Что плохо
Использование `ТекущаяДата()` для получения текущей даты в бизнес-логике.

### Почему плохо
`ТекущаяДата()` возвращает дату сервера приложений в **его** локальном часовом поясе. Проблемы:
- Сервер в Москве (UTC+3), пользователь в Новосибирске (UTC+7) — разница 4 часа
- В 01:00 по Новосибирску `ТекущаяДата()` вернёт вчерашнюю дату (21:00 по Москве)
- Документы создаются с «неправильной» датой, отчёты показывают неверные данные
- В кластере серверов время на разных узлах может отличаться на секунды — порядок документов нарушается

### Как правильно
Всегда использовать `ТекущаяДатаСеанса()` — она возвращает дату в часовом поясе сеанса пользователя.

### Пример

```bsl
// ❌ ПЛОХО
ДатаДокумента = ТекущаяДата();
Если ДатаОплаты < ТекущаяДата() Тогда
    // Просрочка может определиться неверно!
КонецЕсли;

// ✅ ПРАВИЛЬНО
ДатаДокумента = ТекущаяДатаСеанса();
Если ДатаОплаты < ТекущаяДатаСеанса() Тогда
    // Корректное определение просрочки в часовом поясе пользователя
КонецЕсли;
```

**Стандарт ИТС:** «Использование текущей даты».

## Антипаттерн 5: Сообщить() вместо ОбщегоНазначения.СообщитьПользователю()

### Что плохо
Использование `Сообщить()` для вывода ошибок валидации.

### Почему плохо
`Сообщить()` выводит текст в окно сообщений формы **без привязки к полю**. Пользователь видит «Не заполнено поле», но:
- Не понимает, **какое** поле (если полей много)
- Не может кликнуть на сообщение, чтобы перейти к полю
- В форме с табличными частями не понимает, **какая строка** содержит ошибку

`ОбщегоНазначения.СообщитьПользователю()` привязывает сообщение к конкретному полю — поле подсвечивается красным, клик переводит фокус.

### Как правильно
Использовать `ОбщегоНазначения.СообщитьПользователю()` с указанием объекта, реквизита и пути к данным формы.

### Пример

```bsl
// ❌ ПЛОХО: сообщение без привязки
Сообщить("Не заполнен контрагент!");

// ✅ ПРАВИЛЬНО: сообщение привязано к полю
ОбщегоНазначения.СообщитьПользователю(
    НСтр("ru = 'Не заполнен контрагент.'"),
    ЭтотОбъект,           // Объект — источник данных
    "Контрагент",          // Имя реквизита объекта
    "Объект.Контрагент");  // Путь к данным формы (для привязки к элементу формы)
```

**Подробнее:** [coding-standards.md](coding-standards.md), правило 5.

## Антипаттерн 6: Глотание исключений в Попытка/Исключение

### Что плохо
Пустой блок `Исключение` или блок, который перехватывает ошибку, но ничего не делает с ней.

### Почему плохо
Проглоченное исключение:
1. **Скрывает ошибку** — система выглядит работающей, но данные не записаны, операция не выполнена
2. **Делает отладку невозможной** — ошибка произошла, но ни в журнале регистрации, ни в логах следов нет
3. **Нарушает инварианты** — вызывающий код считает, что операция прошла успешно

**Особенно опасно** в транзакциях: если внутри `Попытка` была `НачатьТранзакцию()`, а в `Исключение` не вызвана `ОтменитьТранзакцию()` — транзакция «зависает», блокируя данные.

### Как правильно
1. Всегда логировать ошибку в журнал регистрации
2. Либо повторно генерировать исключение, либо корректно обработать
3. Никогда не оставлять пустой блок `Исключение`

### Пример

```bsl
// ❌ ПЛОХО: пустой блок Исключение — ошибка проглочена
Попытка
    ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
    // Ничего. Тишина. Документ не проведён, но никто не узнает.
КонецПопытки;

// ❌ ПЛОХО: перехватили, но не залогировали
Попытка
    ОтправитьДанныеВоВнешнююСистему(Данные);
Исключение
    Возврат Ложь; // Ошибка потеряна — какая именно? когда? почему?
КонецПопытки;

// ✅ ПРАВИЛЬНО: логирование + корректная обработка
Попытка
    ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
    ИнформацияОбОшибке = ИнформацияОбОшибке();
    
    ЗаписьЖурналаРегистрации(
        НСтр("ru = 'Проведение документа'"),
        УровеньЖурналаРегистрации.Ошибка,
        Метаданные.Документы.РеализацияТоваровУслуг,
        ДокументОбъект.Ссылка,
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке));
    
    ВызватьИсключение; // Пробрасываем дальше — пусть вызывающий код решает
КонецПопытки;
```

**Подробнее:** [error-handling.md](error-handling.md), правила 1-3.

## Антипаттерн 7: Затенение глобального контекста

### Что плохо
Использование имён `Документы`, `Справочники`, `Регистры` и подобных как имён локальных переменных.

### Почему плохо
Платформа 1С предоставляет глобальные менеджеры метаданных: `Документы`, `Справочники`, `Перечисления`, `РегистрыСведений` и т.д. Локальная переменная с таким именем **скрывает** глобальный контекст:

```bsl
Документы = Новый Массив; // Теперь «Документы» — массив
Документы.РеализацияТоваровУслуг; // Ошибка! Метод не существует у массива
```

Ошибка может быть не сразу заметна, если переменная объявлена далеко от использования глобального имени. Отладка превращается в головоломку.

### Как правильно
Использовать конкретные, описательные имена: `МассивДокументов`, `СписокСправочников`, `ОбрабатываемыеДокументы`.

### Пример

```bsl
// ❌ ПЛОХО
Документы = ПолучитьСписокДокументов();
Справочники = Новый Массив;

// ✅ ПРАВИЛЬНО
ДокументыКОбработке = ПолучитьСписокДокументов();
СписокСправочниковОтбора = Новый Массив;
```

## Антипаттерн 8: ПолучитьФорму() вместо ОткрытьФорму()

### Что плохо
Использование устаревшего метода `ПолучитьФорму()` для открытия форм.

### Почему плохо
`ПолучитьФорму()` — метод из обычного приложения (толстый клиент), он:
1. **Не работает** в управляемом приложении (тонкий клиент, веб-клиент)
2. **Создаёт форму на сервере**, но не отображает — требуется дополнительный вызов `Форма.Открыть()`
3. **Не поддерживает** модальность, механизм оповещений и другие возможности управляемого интерфейса

### Как правильно
Использовать `ОткрытьФорму()` с параметрами и обработкой оповещения о закрытии.

### Пример

```bsl
// ❌ ПЛОХО: устаревший метод
Форма = ПолучитьФорму("Обработка.ЗагрузкаДанных.Форма");
Форма.Открыть();

// ✅ ПРАВИЛЬНО: ОткрытьФорму с параметрами
ПараметрыФормы = Новый Структура;
ПараметрыФормы.Вставить("Ключ", ДокументСсылка);

ОткрытьФорму("Документ.РеализацияТоваровУслуг.ФормаОбъекта",
    ПараметрыФормы,
    ЭтотОбъект,                     // Владелец формы
    ,                                 // Уникальность
    ,                                 // Окно
    ,                                 // НавигационнаяСсылка
    Новый ОписаниеОповещения(         // Обработка закрытия
        "ПослеЗакрытияФормыДокумента", ЭтотОбъект));
```

## Антипаттерн 9: Прямая запись в базу из модуля формы

### Что плохо
Размещение бизнес-логики записи/модификации объектов непосредственно в модуле формы.

### Почему плохо
1. **Дублирование** — если объект создаётся/изменяется из нескольких мест (другая форма, обработка, обмен данными), логику придётся копировать
2. **Невозможность тестирования** — логика привязана к форме, нельзя вызвать без неё
3. **Нарушение архитектуры** — модуль формы отвечает за UI, модуль объекта — за бизнес-логику

### Как правильно
Бизнес-логика валидации и заполнения — в модуле объекта (обработчики `ОбработкаЗаполнения`, `ОбработкаПроверкиЗаполнения`, `ПередЗаписью`). Модуль формы — только UI и вызов серверных методов.

### Пример

```bsl
// ❌ ПЛОХО: бизнес-логика в модуле формы
// Модуль формы документа
&НаСервере
Процедура ЗаписатьИПровестиНаСервере()
    ДокументОбъект = РеквизитФормыВЗначение("Объект");
    
    // Бизнес-логика заполнения — должна быть в модуле объекта!
    Для Каждого Строка Из ДокументОбъект.Товары Цикл
        Строка.Сумма = Строка.Количество * Строка.Цена;
    КонецЦикла;
    
    ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
    ЗначениеВРеквизитФормы(ДокументОбъект, "Объект");
КонецПроцедуры

// ✅ ПРАВИЛЬНО: бизнес-логика в модуле объекта
// Модуль объекта документа
Процедура ПередЗаписью(Отказ)
    Для Каждого Строка Из Товары Цикл
        Строка.Сумма = Строка.Количество * Строка.Цена;
    КонецЦикла;
КонецПроцедуры

// Модуль формы — только UI
&НаКлиенте
Процедура ЗаписатьИПровести(Команда)
    ЗаписатьВФоне(); // Или стандартная команда формы
КонецПроцедуры
```

## Антипаттерн 10: Хардкод значений вместо параметров конфигурации

### Что плохо
Использование литеральных значений (чисел, строк, дат) в коде вместо перечислений, предопределённых элементов и констант.

### Почему плохо
1. **Непонятно** — `Если Статус = 3` — что такое 3?
2. **Хрупко** — при изменении значения нужно найти все вхождения в коде (а `grep` по числу 3 найдёт тысячи ложных срабатываний)
3. **Не настраиваемо** — изменение требует обновления конфигурации, а не настройки в интерфейсе

### Как правильно
- Статусы, типы, виды → **Перечисления** (предопределённые значения)
- Настраиваемые значения → **Константы** или **Регистры сведений**
- Предопределённые элементы → через `ПредопределённоеЗначение()`

### Пример

```bsl
// ❌ ПЛОХО: магические числа и строки
Если Документ.Статус = 3 Тогда // Что такое 3???
    МаксПопыток = 5;            // Откуда 5? Кто решил?
    ПутьКФайлу = "C:\Temp\";   // Хардкод пути
КонецЕсли;

Если Документ.ВидОперации = "Реализация" Тогда // Строковое сравнение — хрупко
КонецЕсли;

// ✅ ПРАВИЛЬНО: перечисления, константы, предопределённые элементы
Если Документ.Статус = Перечисления.СтатусыДокументов.Согласован Тогда
    МаксПопыток = Константы.МаксимальноеКоличествоПопытокОтправки.Получить();
    ПутьКФайлу = Константы.КаталогВременныхФайлов.Получить();
КонецЕсли;

Если Документ.ВидОперации = Перечисления.ВидыОпераций.Реализация Тогда
КонецЕсли;
```

## Антипаттерн 11: Конкатенация строк в цикле через «+»

### Что плохо
Формирование длинных строк через оператор `+` внутри цикла.

### Почему плохо
Строки в BSL иммутабельны. `Результат = Результат + НоваяЧасть` создаёт **новую строку** длиной `Длина(Результат) + Длина(НоваяЧасть)` и копирует обе части. На N итерациях:
- Итерация 1: копируется 1 часть
- Итерация 2: копируется 2 части (предыдущий результат + новая)
- Итерация N: копируется N частей

Итого: O(N²) по времени и памяти. Для 10 000 строк — ощутимые задержки.

### Как правильно
Использовать `Массив` + `СтрСоединить()` — O(N) по времени.

### Пример

```bsl
// ❌ ПЛОХО: O(N²) конкатенация
ТекстОтчёта = "";
Для Каждого Строка Из ТаблицаДанных Цикл
    ТекстОтчёта = ТекстОтчёта + Строка.Описание + Символы.ПС; // Квадратичная сложность!
КонецЦикла;

// ✅ ПРАВИЛЬНО: O(N) через массив
Части = Новый Массив;
Для Каждого Строка Из ТаблицаДанных Цикл
    Части.Добавить(Строка.Описание);
КонецЦикла;
ТекстОтчёта = СтрСоединить(Части, Символы.ПС);
```

## Антипаттерн 12: Пустой блок Исключение без ВызватьИсключение

### Что плохо
Блок `Исключение` который только логирует ошибку, но не пробрасывает её дальше и не возвращает статус ошибки.

### Почему плохо
Вызывающий код не знает, что произошла ошибка, и продолжает работу с некорректными данными. Данные могут быть частично обработаны, транзакция может остаться незакрытой.

### Как правильно
1. Если метод может обработать ошибку полностью — обработать и вернуть статус (Истина/Ложь)
2. Если не может — залогировать и `ВызватьИсключение` для пробрасывания
3. В транзакциях — **обязательно** `ОтменитьТранзакцию()` в блоке `Исключение`

### Пример

```bsl
// ❌ ПЛОХО: ошибка залогирована, но проглочена
Попытка
    НачатьТранзакцию();
    // ... запись данных ...
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ЗаписьЖурналаРегистрации("Ошибка", УровеньЖурналаРегистрации.Ошибка,,, 
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    // Молчим. Вызывающий код думает, что всё ок.
КонецПопытки;

// ✅ ПРАВИЛЬНО: вариант А — пробрасываем исключение
Попытка
    НачатьТранзакцию();
    // ... запись данных ...
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ЗаписьЖурналаРегистрации("Ошибка", УровеньЖурналаРегистрации.Ошибка,,,
        ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
    ВызватьИсключение; // Вызывающий код узнает об ошибке!
КонецПопытки;

// ✅ ПРАВИЛЬНО: вариант Б — возвращаем статус
Функция ЗаписатьДанные(Данные)
    Попытка
        // ... запись ...
        Возврат Истина;
    Исключение
        ЗаписьЖурналаРегистрации(...);
        Возврат Ложь; // Вызывающий код проверяет результат
    КонецПопытки;
КонецФункции
```

## Антипаттерн 13: Неправильный порядок Попытка/Транзакция

### Что плохо
Размещение `НачатьТранзакцию()` вне блока `Попытка` или `ЗафиксироватьТранзакцию()` внутри блока `Исключение`.

### Почему плохо
Если `НачатьТранзакцию()` вызвана до `Попытка`, а ошибка произойдёт **между** ними, транзакция останется незакрытой. Зависшая транзакция блокирует данные в СУБД, что может привести к каскадным таймаутам у других пользователей.

### Как правильно
Строго соблюдать порядок: `НачатьТранзакцию` → `Попытка` → логика → `ЗафиксироватьТранзакцию` → `Исключение` → `ОтменитьТранзакцию` → обработка.

### Пример

```bsl
// ❌ ПЛОХО: транзакция начата до Попытка
НачатьТранзакцию();
ПодготовитьДанные(); // Если здесь ошибка — транзакция зависнет!
Попытка
    ЗаписатьДанные();
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
КонецПопытки;

// ✅ ПРАВИЛЬНО: канонический паттерн
НачатьТранзакцию();
Попытка
    ПодготовитьДанные();
    ЗаписатьДанные();
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ЗаписьЖурналаРегистрации(...);
    ВызватьИсключение;
КонецПопытки;
```

**Подробнее:** [error-handling.md](error-handling.md), правило 2.

## Антипаттерн 14: Избыточные серверные вызовы из формы

### Что плохо
Множественные последовательные вызовы `&НаСервере` / `&НаСервереБезКонтекста` методов при одном действии пользователя.

### Почему плохо
Каждый серверный вызов — это сетевой round-trip (сериализация → передача → выполнение → передача обратно). 3 последовательных вызова × 100 мс = 300 мс задержка, ощутимая пользователем. При медленном канале — секунды.

### Как правильно
Объединить несколько серверных операций в один вызов, возвращающий все нужные данные.

### Пример

```bsl
// ❌ ПЛОХО: 3 серверных вызова при изменении одного поля
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
    ДоговорПоУмолчанию = ПолучитьДоговорПоУмолчанию(Объект.Контрагент);     // вызов 1
    ВалютаДоговора = ПолучитьВалютуДоговора(ДоговорПоУмолчанию);              // вызов 2
    КурсВалюты = ПолучитьКурсВалюты(ВалютаДоговора, Объект.Дата);             // вызов 3
КонецПроцедуры

// ✅ ПРАВИЛЬНО: один серверный вызов
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
    ДанныеЗаполнения = ПолучитьДанныеКонтрагента(Объект.Контрагент, Объект.Дата);
    Объект.Договор = ДанныеЗаполнения.Договор;
    Объект.Валюта = ДанныеЗаполнения.Валюта;
    КурсВалюты = ДанныеЗаполнения.Курс;
КонецПроцедуры

&НаСервереБезКонтекста
Функция ПолучитьДанныеКонтрагента(Контрагент, Дата)
    Результат = Новый Структура("Договор, Валюта, Курс");
    // Всё за один серверный вызов
    Результат.Договор = ПолучитьДоговорПоУмолчанию(Контрагент);
    Результат.Валюта = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Результат.Договор, "ВалютаВзаиморасчетов");
    Результат.Курс = РаботаСКурсамиВалют.ПолучитьКурсВалюты(Результат.Валюта, Дата);
    Возврат Результат;
КонецФункции
```

## Сводка антипаттернов

| # | Антипаттерн | Последствие | Правильный подход |
|---|-------------|-------------|-------------------|
| 1 | Запросы в циклах | O(N) round-trips к СУБД | Один запрос с `В(&Массив)` |
| 2 | Точечная нотация через ссылки | N+1, неявные JOIN | Явный запрос с JOIN |
| 3 | &НаСервере вместо БезКонтекста | Передача всего контекста формы | &НаСервереБезКонтекста |
| 4 | ТекущаяДата() | Неверный часовой пояс | ТекущаяДатаСеанса() |
| 5 | Сообщить() | Нет привязки к полю | СообщитьПользователю() с привязкой |
| 6 | Пустой Исключение | Скрытые ошибки | Логирование + ВызватьИсключение |
| 7 | Затенение контекста | Скрытие глобальных менеджеров | Конкретные имена переменных |
| 8 | ПолучитьФорму() | Не работает в управляемом режиме | ОткрытьФорму() |
| 9 | Логика в модуле формы | Дублирование, нетестируемость | Модуль объекта для бизнес-логики |
| 10 | Хардкод значений | Нечитаемость, хрупкость | Перечисления, константы |
| 11 | Конкатенация «+» в циклах | O(N²) по памяти и времени | Массив + СтрСоединить() |
| 12 | Логирование без проброса | Вызывающий код не знает об ошибке | ВызватьИсключение или статус |
| 13 | Транзакция вне Попытка | Зависшая транзакция | Канонический паттерн |
| 14 | Множественные серверные вызовы | Суммарная латентность | Один вызов — все данные |
