# Что переживает платформенный импорт `Excel -> ТабличныйДокумент`

Сводка восстановлена по проверенному runtime-эксперименту на платформе
`8.3.27` (Linux x86-64): один лист `.xlsx` прочитан `ТабличныйДокумент.Прочитать`,
результат записан обратно в `MXL` и `XLSX` и сравнён с исходником.
Исходный fidelity-отчёт задачи утрачен; цифры ниже — фактические замеры того
прогона, перенесённые сюда как ориентир, а не как гарантия для любого файла.

## Замеренный контур

- Вход: `.xlsx`, один лист, сетка `A1:H13`, 5 merge-областей, 53 неформульных
  значения, заливки, шрифты (bold/italic), границы, числовые форматы,
  freeze panes, auto filter, print area.
- Маршрут: `ТабличныйДокумент.Прочитать(xlsx)` -> `Записать(mxl)` /
  `Записать(xlsx)` -> структурное сравнение входа и выхода.

## Сохраняется (подтверждено замером)

| Свойство | Факт |
|---|---|
| Сетка строк/колонок | `A1:H13` сохранена (`dimension=H13`) |
| Merge-области | все 5 областей на месте |
| Неформульные значения | все 53 значения присутствуют по своим координатам |
| Заливки, шрифты, выравнивание | отображаемые fills/fonts/alignment перенесены |
| Границы | визуальная рамка таблицы перенесена |

## Теряется или искажается

| Свойство | Что происходит |
|---|---|
| Ширины колонок | не совпадают: Excel и MXL используют разные шкалы ширины; перезадаются кодом с коэффициентом ~`0.864` (калибруется на конкретном шаблоне) |
| Высоты строк | дробные высоты искажаются; перезадаются через `АвтоВысотаСтроки = Ложь` + `ВысотаСтроки` |
| Цвета границ | часть border colors не переживает импорт |
| Числовые форматы | часть number formats упрощается; перезадаётся `Область(...).Формат` |
| Формулы | превращаются в последние вычисленные значения — итоги надо считать кодом |
| `freeze panes` | теряется |
| `auto filter` | теряется |
| `print area` | теряется |
| Имя листа | может измениться |

## Ограничение клиента

`ТабличныйДокумент.Прочитать` в этом маршруте работал только на **толстом
клиенте**: тонкий клиент вернул `Метод недоступен на тонком клиенте` при
открытии обработки с клиентским импортом. При выборе runtime-маршрута тип
клиента фиксируй в proof явно — ложноположительный `run_scenario=Success`
не доказывает импорт, если форма показала `ErrorWindow`.

## Практический вывод

Imported MXL — это визуально-структурный каркас, а не точная копия workbook.
Поверх него кодом достраиваются:

- привязка данных к координатам (`Область(R,C).Значение/Текст`);
- пересчёт итогов (формул нет — только значения);
- геометрия: `ВосстановитьГеометриюExcel` из `platform-import-roundtrip.bsl`;
- служебные подписи и режим печати (`ОтображатьСетку = Ложь`).

Сравнение входа и round-trip результата выполняется скриптом
`compare_xlsx_fidelity.py` из этого же каталога.
