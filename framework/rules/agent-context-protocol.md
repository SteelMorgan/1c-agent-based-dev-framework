# Протокол контекста агента (Agent Context Protocol)

> RULES — обязательная политика. Каждый сабагент MUST сохранять контекст перед завершением
> и MUST читать его при старте. Это единственный надёжный механизм преемственности между запусками.

---

## Назначение

Сабагент работает в изолированной сессии — после завершения его контекст уничтожается.
При повторном запуске агент стартует с чистого листа и вынужден повторять уже проделанную работу.

`{role}-context.md` решает эту проблему: агент сохраняет всё важное перед выходом
и читает это при старте следующего запуска.

---

## Правило: первый шаг при старте

Каждый сабагент MUST выполнить как **первый шаг**:

```
1. Проверить наличие {role}-context.md в task_dir
2. Если файл существует → прочитать полностью
3. Продолжить работу с учётом сохранённого контекста,
   не повторяя уже выполненные шаги
```

Имя файла по роли:

| Агент     | Файл контекста              |
|-----------|-----------------------------|
| analyst   | `analyst-context.md`        |
| architect | `architect-context.md`      |
| developer | `developer-context.md`      |
| tester    | `tester-context.md`         |
| reviewer  | `reviewer-context.md`       |

---

## Правило: последний шаг перед завершением

Каждый сабагент MUST записать `{role}-context.md` в `task_dir` **перед любым завершением**:
- при успешном завершении (`completed`)
- при блокирующих вопросах (`clarification_needed`)
- при обнаружении ошибки реализации (`implementation_error`)

---

## Структура файла контекста

```markdown
# {Role} Context

## Status
<!-- Одно из: completed | clarification_needed | implementation_error -->
{status}

## Completed Steps
<!-- Что уже сделано: какие файлы изучены, какие инструменты вызваны,
     какие артефакты созданы. Достаточно чтобы не повторять работу. -->
- ...

## Findings
<!-- Конкретные находки: модули, паттерны, структуры данных, зависимости.
     Всё что потребует усилий для повторного обнаружения. -->
- ...

## Assumptions
<!-- Допущения, принятые при неопределённости. -->
- ...

## Pending Questions
<!-- Заполняется только при Status: clarification_needed.
     Все вопросы одним блоком — не добавлять вопросы по одному. -->
- ...

## User Answers
<!-- Заполняет оркестратор перед повторным запуском агента.
     Агент читает этот раздел чтобы продолжить работу. -->
- ...
```

---

## Что MUST попасть в контекст

| Секция | Что включать |
|--------|--------------|
| `Completed Steps` | Список изученных файлов/модулей, вызванные инструменты, созданные артефакты |
| `Findings` | Найденные модули и их пути, паттерны реализации, структуры данных, точки расширения, существующие зависимости |
| `Assumptions` | Любое допущение принятое вместо вопроса пользователю |
| `Pending Questions` | Все блокирующие вопросы одним списком (только при `clarification_needed`) |
| `User Answers` | Не заполняется агентом — только оркестратором |

---

## Что НЕ нужно включать в контекст

- Полное содержимое прочитанных файлов — только выводы и пути
- Промежуточные рассуждения — только финальные находки
- Информацию доступную из других артефактов в `task_dir` (спецификация, тех. дизайн)

---

## Механизм resume (оптимизация внутри сессии)

Если оркестратор и сабагент работают в одной сессии, оркестратор MAY использовать
`resume agentId` для продолжения в том же transcript вместо нового запуска.

```
Когда resume работает:           Когда НЕ работает:
  Аналитик → вопрос                Пользователь закрыл IDE
  → ответ в той же сессии          → открыл завтра
  → resume agentId ✅              → agentId устарел ❌
```

**Правило:** `{role}-context.md` — основной механизм, всегда надёжен.
`resume` — дополнительная оптимизация, применять когда agentId актуален.
При использовании `resume` контекст-файл всё равно MUST быть записан.
