# Маршрутизация моделей (Model Routing)

> RULES — обязательные политики выбора модели по tier задачи. Экономия токенов: не использовать Premium для задач, не требующих глубокого рассуждения.

---

## Назначение

Это правило обеспечивает баланс качества и стоимости: выбор модели по сложности задачи. Дорогие модели (Premium) используются только для критичных задач; простые задачи выполняются Economy-моделями.

---

## Условия срабатывания

Правило применяется, когда:

- Оркестратор или агент выбирает модель для выполнения задачи
- Работает full-cycle workflow с поддержкой tier-инг
- Доступны модели разных tier (Economy, Mid, High, Premium)

---

## Требования

### Принцип

MUST использовать наиболее дешёвую подходящую модель. Не использовать Premium для exploration.

### Правила маршрутизации по типу задачи

| Тип задачи | Tier | Обоснование |
|------------|------|-------------|
| Explorer, форматирование | Economy | Не требуют глубокого рассуждения |
| Генерация кода | Mid или High | В зависимости от сложности |
| Ревью кода | High или Premium | Ревьюер ≥ tier автора |
| Написание спеки | Mid или High | Сложность задачи |
| Ревью спеки | Premium | Критичность для всего цикла |
| Архитектурные решения | High или Premium | Требуют глубокого reasoning |
| Финальная проверка перед пользователем | Premium | Максимальное качество |

### Классификация по сложности

| Критерий | Простая (Economy/Mid) | Средняя (Mid/High) | Сложная (High/Premium) |
|----------|------------------------|-------------------|------------------------|
| Объём | < 20 строк, один файл | Несколько файлов | Мультимодуль, интеграция |
| Решения | Нет архитектурных | Есть некоторые решения | Архитектурные, критические |
| Контекст | Локальный | Бизнес-логика, рефакторинг | Архитектура, кросс-модуль |

---

## Классификация задач по tier

Детали tier и моделей — в [docs/model-capabilities.md](../../docs/model-capabilities.md).

| Tier | Назначение | Примеры моделей |
|------|------------|----------------|
| Economy | Навигация, форматирование, массовый анализ | Grok Code Fast 1, Claude Haiku 4.5 |
| Mid | Реализация фич, рефакторинг, агентная работа | Gemini 3 Pro, GPT 5.3 Codex |
| High | Сложная бизнес-логика, multi-file рефакторинг | Claude Sonnet 4.5 |
| Premium | Архитектура, ревью, критические решения | Claude Opus 4.6, GPT 5.2 |

---

## Правило ревьюера

Tier ревьюера MUST быть ≥ tier автора артефакта.

---

## Исключения

| Ситуация | Действие |
|----------|----------|
| Пользователь явно указал модель | Следовать указанию пользователя |
| Дешёвая модель даёт неадекватное качество | Эскалация на следующий tier |
| Свободный режим (без full-cycle) | Маршрутизация advisory, не mandatory |
