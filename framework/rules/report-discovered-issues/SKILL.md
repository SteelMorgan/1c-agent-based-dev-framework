# Доклад о найденных проблемах

> Агент часто видит больше, чем нужно для текущей задачи. Молчаливо проигнорированная находка остаётся неисправленным риском, поэтому её нужно явно донести до пользователя.

## Принцип

Решая задачу, агент может найти регрессии, ошибки в смежных модулях, техдолг, антипаттерны, расхождения кода со спецификацией, проблемы производительности или безопасности. Чинить их внутри текущей задачи без разрешения пользователя нельзя, но и скрывать нельзя.

## MUST

| Требование | Описание |
|-----------|----------|
| Фиксировать находки | По мере обнаружения записывать проблему в рабочий контекст, заметки задачи или раздел финального отчёта |
| Не расширять scope молча | Не исправлять найденные проблемы внутри текущей задачи без явного разрешения пользователя |
| Доложить после завершения | В финальном ответе или отчёте перечислить найденные проблемы, не относящиеся к выполненному scope |
| Давать конкретику | Для каждой находки указать место, суть, риск, серьёзность и примерный размер исправления |
| Предложить путь | Предложить дальнейшее действие: отдельная задача, quick-fix, отложить, задокументировать или проверить дополнительно |

## Что докладывать: вердикт

| Находка / поведение | Вердикт |
|---------------------|---------|
| Баги, ведущие к потере данных, денег, безопасности или доступности | докладывать |
| Регрессии и расхождения с источником истины | докладывать |
| Проблемы целостности данных | докладывать |
| Краши или исключения, возможные в рабочем сценарии | докладывать |
| Ошибки в тестах или инфраструктуре, маскирующие реальный результат | докладывать |
| Чисто стилистические мелочи без влияния на сопровождение | не докладывать |
| Опечатки в комментариях | не докладывать |
| Абстрактные пожелания по рефакторингу без конкретного риска | не докладывать |
| Превращать текущую задачу в уборку всего найденного | запрещено |
| Откладывать доклад «на потом» | запрещено |
| Объединять разные проблемы в одну расплывчатую фразу | запрещено |
| Драматизировать или преуменьшать (описание должно быть проверяемым) | запрещено |

## Формат доклада

```markdown
## Найдено по пути

### 1. [Краткое название]
- **Где:** `path/to/file:line`
- **Что:** конкретное описание проблемы
- **Почему проблема:** последствия или риск
- **Серьезность:** критично / средне / низко
- **Усилие:** простой фикс / отдельная задача / большая работа
- **Предложение:** что сделать дальше
```

## Связанные правила

- `agent-context-protocol` — где фиксировать рабочий контекст и найденные проблемы.
- `quick-fix` / `full-cycle` — как превращать находки в дальнейшую работу.
- `source-of-truth` — как проверять расхождения между артефактами.
