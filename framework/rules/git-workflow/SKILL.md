# Политика работы с Git

> **Триггер:** работа с git (коммиты, ветки, merge задачи, откат). При срабатывании — применить навык `git-workflow` (`framework/skills/framework-meta/git-workflow/SKILL.md`): стратегия веток, формат коммитов по фазам, squash-merge, откат.

Guardrail ниже обязан быть виден всегда — независимо от того, загружен навык или нет.

## MUST (инвариант, всегда)

| Запрет / правило | Описание |
|---|---|
| **Сабагенты НЕ коммитят** | Право `git commit` есть ТОЛЬКО у оркестратора (внутри задачи и финальный merge) и у пользователя. Сабагент не видит весь scope фазы и может закоммитить мусор. |
| **Коммит и merge — только оркестратор / пользователь** | Никакой сабагент не инициирует коммит или merge самостоятельно. |
| **Запрет удаления файлов из git без явного разрешения пользователя** | `git rm`, `git rm --cached`, физическое удаление файла под управлением git с включением в коммит, `git reset --hard` с потерей чужих изменений — ЗАПРЕЩЕНЫ без явного «да, удали» в текущем диалоге. Разрешения из памяти / CLAUDE.md НЕ считаются. Вместо удаления — комментировать через `//--agent`, перезаписывать новой версией, эскалировать. Папку `tasks/<TASK-XXX>/` не удалять никогда. |
| **Никаких force-push и destructive операций в родительскую ветку** | Внутри локальной task-ветки rebase/amend допустимы; в родителе — нет. |
| **Подозрение на удаление → стоп** | `D <path>` или `R <old> -> <new>` в `git status`, не инициированные текущей фазой явно → НЕ коммитить, зафиксировать `SUSPECTED_DELETION: <path>` в `orchestrator-context.md`, эскалировать пользователю. |

Детали «как» (создание ветки задачи, что коммитить, формат сообщения, условия и команда squash-merge, сценарии отката, исключения для удаления) — в навыке `git-workflow`.
