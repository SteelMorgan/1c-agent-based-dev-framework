# Формат эскалации пользователю

> **Триггер:** оркестратор или сабагент запрашивает решение пользователя — `clarification_needed`, превышение лимита итераций (3+ BLOCK), архитектурный выбор без однозначного источника, конфликт между уровнями source-of-truth и др. При срабатывании — применить навык `escalation-format` (`framework/skills/framework-meta/escalation-format/SKILL.md`): он задаёт структуру сообщения, правила группировки и примеры.

> **ВАЖНО — фильтр «когда эскалировать» находится в `framework/workflows/orchestrator.md` § 4 «Принцип „делегируй, не спрашивай“».** Этот триггер задаёт только повод применить формат. Перед эскалацией оркестратор/сабагент ОБЯЗАН пройти фильтр в orchestrator.md и убедиться, что эскалация легитимна (admin-операция / изменение контракта L1-L2 / бизнес-выбор / 3+ BLOCK / scope-расширение). Технические выборы и диагностика эскалации НЕ требуют — они решаются делегированием сабагенту.

## Инвариант (всегда)

- **Запрещено** эскалировать «один вопрос без контекста» — пользователь не сможет выбрать, не понимая стоящих за вопросом проблем.
- **Запрещено** прятать варианты в одну фразу («принимаем или меняем спеку») — каждый вариант разворачивается: что меняется, где, какой ценой.
- Применять формат эскалации к техническому вопросу (который решается делегированием сабагенту) = ошибка.
