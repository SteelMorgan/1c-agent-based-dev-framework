# Лимиты самовосстановления (канонический реестр)

Единый источник числовых лимитов для сабагентов. Профили ссылаются на этот реестр; числа в профилях
дублируют таблицу и не должны расходиться с ней. При исчерпании лимита агент НЕ продолжает
«вслепую» — он переходит к указанному действию (bug-report или эскалация оркестратору/пользователю).

| Контекст | Кто | Лимит | Что после исчерпания |
|----------|-----|-------|----------------------|
| Self-fix в собственном коде реализации | developer-code | 2 попытки | завести `bug-report.json` → СТОП (orchestrator → Debugger) |
| Red-гейт: причина «зелёного» до прод-кода не найдена | scenario-coder | 2 попытки | завести `bug-report.json` → СТОП |
| Исправление технической ошибки теста | tester | 3 попытки | завести `bug-report.json` (при неочевидном runtime-дефекте) → СТОП |
| Цикл гипотез расследования | debugger | 5 гипотез (+3 по согласованию с оркестратором → max 8) | эскалация пользователю (`escalated_to_user`) |
| BLOCK-итерации ревью артефакта | reviewer / orchestrator | 3 итерации | эскалация оркестратору/пользователю |
| Ревью локального фикса дебаггера (scope=debug) | reviewer / orchestrator | 1 итерация | эскалация оркестратору/пользователю |
| Цикл bug → fix → снова bug на том же артефакте | orchestrator | 2 цикла | эскалация оркестратору/пользователю |
