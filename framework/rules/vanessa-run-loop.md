# Политика прогона Vanessa Automation

> Когда прогон обязателен: создание/изменение `.feature`, параметров запуска или `bddRunner.epf`.

## MUST

| Требование | Описание |
|------------|----------|
| Pre-run config sanity | Перед запуском `vrunner` агент MUST прочитать выбранный `vrunner-va-run-*.json` и связанный `va-params-run-*.json` и убедиться, что параметр `КаталогФич` указывает на feature-папку **текущей задачи**. При несоответствии — пересоздать task-dedicated config (`vrunner-va-run-<taskID>.json` + `va-params-run-<taskID>.json`) и запускать с ним; CLI-флаг `--vanessasettings` — только страховка, не основа |
| Обязательный прогон | После изменения сценария агент MUST выполнить сценарный прогон |
| Мониторинг ЖР во время прогона | Агент MUST опрашивать журнал регистрации каждые **20 секунд** пока тест выполняется |
| Прерывание при ошибке | Если в ЖР появились записи уровня `Error` — агент MUST прервать тест и перейти к диагностике |
| Детект зависания | Если в ЖР нет ни ошибок, ни записей о действиях пользователя >60 сек — агент MUST снять скриншоты и оценить, жив ли тест |
| Обязательный анализ артефактов | После прогона агент MUST проверить `va-status.json` и `vanessa-execution.log` |
| Обязательный анализ ЖР | После прогона агент MUST проверить `event-log`, если сценарий не прошёл или запуск выглядит подозрительно |
| Пост-валидация успеха | После `va-status == 0` агент MUST проверить логи на полноту: все шаги выполнены, нет пропущенных/ненайденных |
| Явная классификация | При падении агент MUST вернуть класс ошибки, а не просто текст сбоя |

## Признак успеха

Минимальный признак успеха:

1. файл `va-status.json` существует;
2. значение в `va-status.json` равно `0`;
3. файл `vanessa-execution.log` создан;
4. в логах нет пропущенных или ненайденных шагов;
5. количество выполненных шагов > 0.

Vanessa считает прогон успешным даже если ни один шаг не был найден или часть шагов пропущена — это **ложный успех**. Агент MUST выявлять такие случаи.

## Pre-run config check

Перед стартом `vrunner` runner-агент выполняет процедуру:

1. Read выбранного `vrunner-va-run-*.json` → найти ключ `--vanessasettings` (путь к `va-params-run-*.json`).
2. Read указанного `va-params-run-*.json` → grep значения `КаталогФич`.
3. Сравнить со ожидаемым `vanessa-tests/features/tasks/<taskID>/`.
4. При несоответствии — создать task-dedicated пару config-файлов (по шаблону из `tools/runtime/vanessa/`), переподставить пути, запускать с ними.
5. Зафиксировать в `{role}-context.md` использованный config и каталог фич.

**Почему:** общие `vrunner-va-run.json` / `va-params-run.json` в проекте обычно содержат «залипший» `КаталогФич` от последней задачи. Запуск без pre-check подхватывает чужой каталог и крутит сценарии другой задачи десятки минут. Pre-check в самом runner-агенте — основная защита; CLI-флаг `--vanessasettings` — лишь страховка.

Подробная процедура мониторинга, пост-валидации и диагностики описывается навыками, а не этим правилом.
