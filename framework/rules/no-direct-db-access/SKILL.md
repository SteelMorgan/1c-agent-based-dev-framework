# Запрет прямого доступа к СУБД

Глобальное правило для всех агентов и сабагентов.

## Контекст

Платформа 1С:Предприятие — единственный легитимный слой доступа к данным.
Прямое обращение к СУБД (PostgreSQL, MS SQL, и др.) обходит бизнес-логику,
нарушает целостность данных и создаёт риски безопасности.

## Правила

### ЗАПРЕЩЕНО (без исключений)

- Модификация данных в СУБД напрямую: `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, DDL-операции
- Генерация или предложение SQL-скриптов для изменения данных
- Обход платформенных механизмов (RLS, блокировки, подписки) через прямой доступ

### ЗАПРЕЩЕНО (без согласования пользователем)

- Чтение данных из СУБД напрямую (`SELECT`) — только через платформенные запросы 1С
- Подключение к СУБД любым способом (psql, sqlcmd, ODBC, и др.)

### ДОПУСТИМО (только задачи производительности)

При **явном** согласовании с пользователем **или** если задача классифицирована
как задача производительности:

- `SELECT`-запросы к СУБД для анализа планов выполнения (`EXPLAIN ANALYZE`)
- Чтение системных представлений СУБД (`pg_stat_*`, `sys.dm_exec_*`)
- Анализ блокировок, статистик, индексов через системные view

Даже в этих случаях — **только чтение**, **никаких изменений**.

## Поведение при нарушении

1. НЕ выполнять запрос к СУБД
2. Зафиксировать попытку в `{role}-context.md`
3. Предложить платформенную альтернативу (запрос 1С, механизм БСП, и др.)
4. Если платформенная альтернатива невозможна — `clarification_needed` → пользователь
