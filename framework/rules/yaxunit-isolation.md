# Изоляция YaxUnit-тестов (транзакционный откат)

> **Триггер:** серверный тест (`ДобавитьСерверныйТест`) обращается к БД на запись — создаёт, проводит, изменяет, удаляет объекты. При срабатывании — применить навык `test-writing` (`framework/skills/bsl-practices/test-writing/SKILL.md`), раздел «Изоляция тестовых данных».

## Принцип

Тест, пишущий в БД, **обязан откатывать свои изменения** — иначе каждый прогон оставляет мусор в базе, тесты становятся неидемпотентными, а база постепенно деградирует. YaxUnit решает это через встроенный механизм `.ВТранзакции()`: перед каждым тестом открывается транзакция, после теста — откатывается.

## MUST

| Требование | Описание |
|---|---|
| `.ВТранзакции()` по умолчанию | Любой набор серверных тестов, пишущих в БД, регистрируется с `.ВТранзакции()` сразу после `ДобавитьТестовыйНабор()` |
| Справочники — через `ЮТест.Данные()` | Создание элементов справочников только через `ЮТест.Данные().СоздатьЭлемент(...)` или `КонструкторОбъекта(...).Записать()` — тогда они трекаются и удаляются автоматически |
| Исключение → явное обоснование | Набор без `.ВТранзакции()` ОБЯЗАН содержать комментарий перед `ДобавитьТестовыйНабор()` с указанием причины исключения (одна из трёх ниже) + teardown через `.После("ИмяПроцедурыОчистки")` |
| Документы без `.ВТранзакции()` → teardown | Документы, создаваемые через `Документы.X.СоздатьДокумент()` (не через `ЮТест.Данные()`), НЕ трекаются автоочисткой — требуют явного teardown в `.После()` |
| Клиентские тесты — без `.ВТранзакции()` | `ДобавитьКлиентскийТест` выполняется в клиентском контексте, где транзакционный откат недоступен |

## Допустимые исключения из `.ВТранзакции()`

### (а) Негативные тесты проведения (ожидаемый Отказ)

Тест проверяет, что проведение документа **запрещается** (устанавливается `Отказ = Истина` в обработчике). Вложенная транзакция записи с ошибкой **отравляет** внешнюю: последующие чтения дают «В данной транзакции уже происходили ошибки!». Решение — не оборачивать такие наборы в `.ВТранзакции()`, создавать объекты через `ЮТест.Данные()` (они будут удалены по `.УдалениеТестовыхДанных()`) и дополнительно зачищать документ в teardown.

```bsl
// Исключение (а): негативный тест проведения — ожидаемый Отказ отравляет внешнюю транзакцию.
// Изоляция через ЮТест.Данные() + .УдалениеТестовыхДанных() + teardown в .После().
ЮТТесты
    .ДобавитьТестовыйНабор("Запрет проведения без договора")
        .УдалениеТестовыхДанных()
        .После("ОчиститьДокументыЗапретПроведения")
        .ДобавитьСерверныйТест("ТестЗапретБезДоговора");
```

### (б) Тест вызывает прод-код с гвардом `ТранзакцияАктивна()`

Некоторые прод-процедуры явно проверяют отсутствие активной транзакции (двухфазные фиксации, реальные вызовы внешнего API, записи в регистры сведений с уникальным ключом). Запуск такого кода внутри `.ВТранзакции()` вызывает ошибку или неожиданное поведение в самом прод-коде.

```bsl
// Исключение (б): прод-код содержит гвард ТранзакцияАктивна() — нельзя запускать в транзакции.
// Teardown выполняет ручную очистку через ЮТест.Данные().УстановитьЗначениеРеквизита().
ЮТТесты
    .ДобавитьТестовыйНабор("Двухфазная фиксация позиции")
        .После("ОчиститьДанныеДвухфазнойФиксации")
        .ДобавитьСерверныйТест("ТестФиксацияПозиции");
```

### (в) Клиентский контекст

`ДобавитьКлиентскийТест` — транзакционный откат на клиенте недоступен по архитектуре платформы. Тестовые данные под клиентскими тестами создаются и чистятся через `Перед`/`После`-обработчики в серверном контексте.

## Паттерн перечитывания объекта при перепроведении

Тест, который меняет режим записи документа (проведение → отмена проведения → повторное проведение), **обязан перечитывать объект** между сменами через `ДокОбъект = Ссылка.ПолучитьОбъект()` — это моделирует поведение формы:

```bsl
// Провести
ДокОбъект = ДокСсылка.ПолучитьОбъект();
ДокОбъект.Записать(РежимЗаписиДокумента.Проведение);

// Отменить проведение — перечитываем, как это делает форма
ДокОбъект = ДокСсылка.ПолучитьОбъект();
ДокОбъект.Записать(РежимЗаписиДокумента.ОтменаПроведения);

// Снова провести — перечитываем ещё раз
ДокОбъект = ДокСсылка.ПолучитьОбъект();
ДокОбъект.Записать(РежимЗаписиДокумента.Проведение);
```

**Важно (платформа 8.3.27):** программное перепроведение в серверной сессии может вызвать платформенную ошибку `[ОшибкаХранимыхДанных]` (стек без прикладных кадров). Ни перечитывание, ни `.ВТранзакции()` её не устраняют — это ограничение платформы. В таком случае идемпотентность перепроведения проверяется **сценарным слоем** (Vanessa, путь через форму), а юнит-тест пишется с `ЮТест.Пропустить()` и явным обоснованием.

## Пример правильной регистрации с `.ВТранзакции()`

```bsl
Процедура ИсполняемыеСценарии() Экспорт

        .ДобавитьТестовыйНабор("Проведение документа")
            .ВТранзакции()

        // Исключение (а): негативный тест — ожидаемый Отказ
```
