# Тесты не оставляют следов (zero-residue)

> **Триггер:** проектирование, написание или ревью ЛЮБОГО теста (YaxUnit unit, серверный YaxUnit-хелпер «Vanessa-перехват», Vanessa `.feature`, интеграционный, сквозной), который создаёт/изменяет/записывает объекты в БД. Применяется ко ВСЕМ видам тестов. При срабатывании — применить навык `test-writing` (`framework/skills/bsl-practices/test-writing/SKILL.md`) и соответствующий механизм изоляции: `yaxunit-isolation` для YaxUnit, `vanessa-test-isolation-policy` для Vanessa.

**GUARD:** тест, оставивший после прогона данные в боевой базе, НЕ принимается (Reviewer BLOCK) — даже если «зелёный».

## Принцип

Тест, накапливающий хвосты, засоряет реальные данные, ломает другие тесты (регламенты выбирают тестовые объекты → таймауты; идемпотентность видит чужие прогоны как дубли) и маскирует деградацию базы. Чистка постфактум — симптом; корень — отсутствие teardown в АРХИТЕКТУРЕ теста. Это закладывается в архитектуру каждого теста, а не делается разовой уборкой.

## MUST (инвариант, всегда)

| Требование | Описание |
|-----------|----------|
| Нулевой след | Дельта количества по КАЖДОМУ затронутому справочнику / регистру / документу / набору записей до и после прогона = **0** |
| Механизм изоляции обязателен | YaxUnit — `.ВТранзакции()` (откат) ИЛИ явный teardown `.После()` при допустимом исключении (см. `yaxunit-isolation`). Vanessa и серверные хелперы вне транзакции — физическая зачистка созданного, устойчивая к падению Act/Assert |
| Объекты — трекаемо | Справочники создавать через `ЮТест.Данные()` (автотрекинг + автоудаление по `.УдалениеТестовыхДанных()`), а не `Справочники.X.СоздатьЭлемент()` мимо трекинга |
| Физическое удаление нетрекаемого | То, что не чистится транзакцией/автотрекингом (документы через `Документы.X.СоздатьДокумент()`, объекты из хелперов) — удалять физически: `ОбменДанными.Загрузка = Истина` + `Удалить()`, в порядке зависимые → владелец; не пометка на удаление |
| Устойчивость к падению | Созданные ссылки регистрируются в момент создания (накопитель), teardown выполняется в `.После()` / финальном шаге сценария ДАЖЕ если Act/Assert упали |
| Сквозной тест — шаг-зачистка | Если данные обязаны жить во время прогона (end-to-end) — единственное исключение, и тест ОБЯЗАН завершаться явным шагом, удаляющим всё созданное |
| Приёмка = дельта-0 | Проверка дельты ключевых объектов до/после — часть приёмочного критерия фазы; ненулевая дельта = тест не принят |
| Запрет band-aid | Скрытие созданного от выборок/регламентов (флаг-исключение объекта, спец-префикс-фильтр) НЕ засчитывается как зачистка — объект должен быть удалён физически |

## Связь с механизмами

- `yaxunit-isolation` — КАК изолировать серверный YaxUnit-тест (`.ВТранзакции()`, допустимые исключения, teardown `.После()`). Это правило задаёт ИНВАРИАНТ (дельта-0), то правило — механизм.
- `vanessa-test-isolation-policy` — изоляция Vanessa-сценариев (создание своих объектов). Усиливается требованием физической зачистки до нуля.
