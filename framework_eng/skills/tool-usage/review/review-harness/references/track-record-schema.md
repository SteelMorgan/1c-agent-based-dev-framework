# Track record schema and strengths projections — shared (RVSW-01, FR-01е, FR-12)

> The canonical location for the shared schema is this file. It was moved from
> `agent-consilium/references/track-record-schema.md` (T-14) with
> parameterization for two tools: the harness storage layer
> (`scripts/track_record.py`) accepts `storage_dir`; the tools have different
> durable directories and different session counters.

Track record is repository-level durable storage for statistics: it survives
`close` of any session and is excluded from cleanup-checkpoint. Its contents are
runtime data and are not committed to git.

## Tool directories (storage_dir parameterization, FR-01е)

| Tool | `storage_dir` | Session counter (`config.json`) | `seq` field |
| --- | --- | --- | --- |
| Consilium | `.consilium-track-record/` | `consiliums_completed` | `consilium_seq` |
| Swarm | `.swarm-track-record/` | `reviews_completed`, `light_reviews_completed`, `calibration_every` | `review_seq` |

The directory structure is shared:

```
<storage_dir>/
├── observations.jsonl   # source of truth, append-only
├── strengths.json       # GENERATED read-only projection (manual editing prohibited)
└── config.json          # tool counters
```

The source of truth is only `observations.jsonl`: when assigning roles, the core
does NOT read `strengths.json`, but recalculates the projection from observations
each time; file substitution does not affect assignment (inherited from the
Consilium F-04).

## Observation

One record per (participant × role × session); written by the tool core when a
session is closed/reported. Common envelope fields:

- `<seq_field>` — the tool session sequence number (basis for recency decay);
- `date` — the record date;
- `participant_id`, `family`, `role` — the projection cell `(participant_id, role)`;
- outcome counters — specific to the tool protocol (built from session state by
the tool core, not the harness).

Observation field sets for the tools:

- Consilium — `agent-consilium/references/track-record-schema.md`
  (inherited fields: `findings_accepted/withdrawn`, `critiques_upheld/
  overruled`, `moderator_is_participant`, `outcome`, domain, checklist_stats);
- Swarm — `review-swarm/references/track-record-swarm.md` (FR-12 fields:
  unique/non-unique findings, attacks, fixed/partially/not_fixed,
  nit/in-lens/out-of-lens, `forced`/`gate_pass`/`calibration_run` markers).

## Strengths projection formulas (inherited CONS-01, decision TBD-02)

For a cell (participant `p`, role `r`):

1. **Observation weight** (recency decay): `w_i = 0.5^(k_i / 8)`, where `k_i` is
   how many sessions ago the observation was made (half-life 8 sessions,
   `STRENGTHS_HALF_LIFE`).
2. **Segregation of tainted observations** (measurement safeguard): observations
   where the choice/role was not a free decision by the model (for the consilium -
   `moderator_is_participant = true`) are excluded from the projection AS LONG AS
   there are ≥ 3 “clean” observations; otherwise they are included with a ×0.5
   discount (`TAINTED_DISCOUNT`). Effective volume: `n_eff = n_clean + 0.5 × n_tainted`.
   For the swarm, segregation is stricter: observations with `forced`/`gate_pass`
   markers are excluded ENTIRELY (see `review-swarm/references/track-record-swarm.md`).
3. **Metrics**: `accept_rate = Σ w·accepted / Σ w·(accepted+withdrawn)`;
   `upheld_rate = Σ w·upheld / Σ w·(upheld+overruled)`. Empty denominator →
   component is excluded (None), not division by zero.
4. **Score**: `score(p, r) = 0.6 · accept_rate + 0.4 · upheld_rate`
   (`SCORE_W_ACCEPT`/`SCORE_W_UPHELD`).
5. **Floor**: the projection is applied to role assignment only when `n_eff ≥ 3`
   (`STRENGTHS_FLOOR`); otherwise - fallback round-robin with a ban on repeating the role.
6. **Exploration budget**: `EXPLORATION_EVERY = 4` - every 4th session
   of the tool assigns roles round-robin against the statistics (for the consilium -
   by the `consiliums_completed` counter; for the swarm, exploration is the default balanced
   rotation of lenses until n_eff is reached, FR-11).

`strengths.json` is regenerated by the core after each observation write
(`track_record.regenerate_strengths(storage_dir, seq_field=...)`; the key format
is `«pid|role»`); manual editing is forbidden (self-declaration of strengths
is prohibited - the `strengths` field in the `adapters.yaml` registry is rejected
fail-closed, FR-02).
