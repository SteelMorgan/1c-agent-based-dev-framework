# SPEC-005: Visual Validation Skills

## Цель

Обеспечить агента инструментами для визуальной проверки форм 1С через веб-клиент.
Это позволяет ловить проблемы, которые не видны в XML (вёрстка, обрезание, порядок).

## Архитектура

Два новых скилла:
1. `tool-usage/visual-check` — механика (browser-use, навигация, скриншоты)
2. `bsl-practices/form-visual-requirements` — критерии (чеклист, стандарты)

## Skill 1: `visual-check`

**Назначение**: Открыть форму в браузере, сделать скриншот, проверить базовую работоспособность.

**Пререквизиты**:
- Опубликованная база (URL)
- Логин/пароль
- `browser-use` MCP server (доступен в sandbox)

**Алгоритм**:
1. `browser_navigate(url)`
2. Вход в систему (поиск полей `#userName`, `#userPassword` или по placeholder)
3. Навигация к объекту:
   - Через "Функции для технического специалиста" (если доступно)
   - Через панель разделов (нужно знать путь: "Справочники" → "Номенклатура")
   - Через прямую ссылку (e.g. `e1cib/data/Catalog.Номенклатура?ref=...`) — предпочтительно!
4. Открытие формы:
   - Форма списка
   - Форма элемента (Создать / Открыть)
5. `browser_take_screenshot` (fullPage=false, viewport)
6. Анализ скриншота

**Прямые ссылки (Deep Linking)**:
Агент должен уметь формировать навигационные ссылки 1С:
- `e1cib/list/Catalog.Товары` — форма списка
- `e1cib/data/Catalog.Товары?ref=...` — форма элемента
- `e1cib/app/DataProcessor.МояОбработка` — форма обработки

Это избавляет от сложной навигации через UI меню.

## Skill 2: `form-visual-requirements`

**Назначение**: Оценить качество формы по скриншоту.

**Чеклист (Checklist)**:

### 1. Компоновка (Layout)
- [ ] Поля выровнены, нет "лесенок"
- [ ] Логические группы визуально отделены (рамки, заголовки)
- [ ] Табличные части занимают адекватное место (не 3 строки по высоте)
- [ ] Нет пустых "дыр" (пустого пространства > 150px)

### 2. Элементы (Controls)
- [ ] Заголовки полей видны полностью (не обрезаны "...")
- [ ] Ширина полей соответствует типу (Дата — узкая, Комментарий — широкий)
- [ ] Чекбоксы имеют понятные подписи
- [ ] Кнопки командной панели не переполнены ("Ещё..." не содержит важных кнопок)

### 3. Юзабилити (Usability)
- [ ] Порядок обхода (Tab order) логичный: слева-направо, сверху-вниз
- [ ] Главные поля (Наименование, Код) — сверху/слева
- [ ] Второстепенные — на вкладках или снизу

### 4. Дефекты (Defects)
- [ ] Горизонтальный скролл (недопустимо для обычных форм)
- [ ] Наложение элементов
- [ ] Нечитаемый текст

## Интеграция

Агент использует `visual-check` для получения артефакта (скриншот), затем применяет знания из `form-visual-requirements` для вердикта.

Если есть дефекты → агент правит XML (через `xml-gen form ...`) → повторяет проверку.
